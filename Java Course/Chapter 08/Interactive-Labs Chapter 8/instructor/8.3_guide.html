The grade book that forgets the sixth student

Objectives

  • Process array elements in a loop whose subscript is a variable
  • Use the length field, not a typed number, as an array's capacity
  • Keep a count to process only the part of an array that holds real data
  • Explain why an enhanced for loop cannot change the elements it visits

Requirements

  1. R1 add() compares count with the array's length field (or the constant MAX_QUIZZES) instead of a typed 10.
  2. R2 curve() adds the points to every entered score: its loop stops at count.
  3. R3 average() totals only the entered scores and divides by count; it returns 0.0 when no score has been entered.
  4. R4 highest() returns the highest entered score using a loop with a variable subscript, or 0 when no score has been entered.
  5. R5 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. scores has 10 elements and the test enters 6 scores. What is scores.length, what is count, and what do the elements after the sixth hold?

    scores.length is 10 and count is 6. Elements 6 through 9 still hold 0, the default value of an int array.

  2. Which scores does the starter's curve() loop change when 6 scores have been entered?

    Only scores[0] through scores[4], the first five. The sixth score, scores[5], is never curved.

Solution

QuizBook.java
public class QuizBook
{
    public static final int MAX_QUIZZES = 10;
    private int[] scores = new int[MAX_QUIZZES];
    private int count = 0;   // how many scores have been entered so far

    // Stores a score if there is room; returns false when the book is full.
    public boolean add(int score)
    {
        if(count < scores.length)
        {
            scores[count] = score;
            ++count;
            return true;
        }
        return false;
    }

    // Adds points to every score entered so far.
    public void curve(int points)
    {
        for(int i = 0; i < count; ++i)
            scores[i] += points;
    }

    // The average of the entered scores, or 0.0 when none were entered.
    public double average()
    {
        if(count == 0)
            return 0.0;
        int total = 0;
        for(int i = 0; i < count; ++i)
            total += scores[i];
        return total * 1.0 / count;
    }

    // The highest entered score, or 0 when none were entered.
    public int highest()
    {
        int best = 0;
        for(int i = 0; i < count; ++i)
            if(scores[i] > best)
                best = scores[i];
        return best;
    }

    public String list()
    {
        String text = "";
        for(int i = 0; i < count; ++i)
            text += scores[i] + " ";
        return text.trim();
    }
}

Walkthrough

A loop whose subscript is a variable lets one statement process every element (p. 273). The length field holds the number of elements, so count < scores.length keeps working if MAX_QUIZZES changes (pp. 274–275); scores.length() would not compile, because for arrays length is a field, not a method. Like the book's AverageOfQuizzes (Figure 8-4), this class uses only part of an array: count says how many elements hold real data, so curve(), average() and highest() all stop at count. The starter's enhanced for loop in average() visits all 10 elements; the empty ones add nothing to the total, but dividing by length counts them, which is why the average was 49.5 instead of 83.0. An enhanced for loop also can't curve the scores: its variable is a copy of each element, so changing it leaves the array as it was. average() must test for count == 0 first, or it computes 0 / 0.0, which is NaN.

Messages students see when a check fails

C1 · add() takes its limit from the array

Compare count with scores.length (or MAX_QUIZZES), not with a typed 10. If the book grows to 12 quizzes, a typed number silently stays wrong; the length field always matches the array.

Hint:

Arrays have a length field with no parentheses; Strings have a length() method.

C2 · curve() changes every entered score

Loop while the subscript is below count, the number of entered scores. A typed 5 skips the sixth student, scores.length would also curve the empty slots, and an enhanced for loop can't change the elements.

C3 · average() divides by the number of entered scores

Divide the total by count, the number of scores entered. Dividing by scores.length counts the empty slots as zeros, which is how the average dropped to 49.5. Return 0.0 first when count is 0.

C4 · highest() loops over the entered scores

Loop a subscript from 0 while it is below count, compare each scores[i] with the highest value so far, and keep the larger one. Stopping at count keeps the empty zeros out of the result.

Progressive hints

  1. The array knows its own size: every array has a length field. Two different limits are in play here: scores.length is how many scores fit, count is how many were entered.

  2. Loops that work on real scores need the second limit. Find every loop that uses a typed number or the whole array, and ask which limit it should use.

  3. In average(), test for count == 0 before you divide. For highest(), keep the best value seen so far in a variable and compare it with each entered score.

Reflection: questions and model answers

  1. The starter's average was 49.5 instead of 83.0. Explain exactly where the difference comes from.

    The starter adds the six entered scores and divides by scores.length, 10, so the four empty elements count as scores of 0. It also left the sixth score uncurved. Dividing the curved total by count, 6, gives the real average.

  2. Why must curve() use a for loop with a subscript, and not for(int s : scores) s += points;?

    In an enhanced for loop, s is a copy of each element's value. Adding to s changes the copy, not the array, so no score would be curved. It would also visit the empty elements.

  3. The department raises MAX_QUIZZES to 12. What changes in your class, and what would have broken with the starter's typed 10?

    Only the constant changes: the array gets 12 elements and add() accepts 12 scores because it compares with scores.length. With the typed 10, quizzes 11 and 12 would be rejected even though the array had room.
