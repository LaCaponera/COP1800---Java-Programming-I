COP1800 · Java Programming I · Lab 8.6

The greenhouse log that loses its Celsius readings

Objectives

  • Explain why changing a parameter that received one array element doesn't change the array
  • Write a method that changes the caller's array through the reference it receives
  • Write a method that returns a new array and leaves its argument unchanged

Requirements

  1. R1 calibrate() adds the offset to every element of the array it receives, so the caller's array changes; it no longer calls adjust().
  2. R2 toFahrenheit() creates a new array the same length as celsius, fills it and returns it; it never assigns to an element of celsius.
  3. R3 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. When calibrate() calls adjust(readings[i], offset), what does the parameter reading receive: the element itself, or something else? What happens to the array?

    It receives a copy of the element's value, because a double is a primitive and is passed by value. adjust() changes its copy, and the array element stays the same.

  2. The starter's toFahrenheit() returns celsius. After double[] fahrenheit = SensorLog.toFahrenheit(log);, how many arrays exist, and what do fahrenheit and log refer to?

    Only one array exists. fahrenheit and log hold the same address, so both refer to that one array, which now holds Fahrenheit values.

Solution

SensorLog.java
public class SensorLog
{
    // Corrects every reading in the caller's array by the offset.
    public static void calibrate(double[] readings, double offset)
    {
        for(int i = 0; i < readings.length; ++i)
            readings[i] += offset;
    }

    // Returns the readings converted to Fahrenheit.
    // The caller's Celsius log must stay exactly as it was.
    public static double[] toFahrenheit(double[] celsius)
    {
        double[] fahrenheit = new double[celsius.length];
        for(int i = 0; i < celsius.length; ++i)
            fahrenheit[i] = celsius[i] * 9 / 5 + 32;
        return fahrenheit;
    }

    public static String format(double[] values)
    {
        String text = "";
        for(int i = 0; i < values.length; ++i)
        {
            if(i > 0)
                text += ", ";
            text += values[i];
        }
        return text;
    }
}

Walkthrough

Primitive values, including a single array element, are passed by value: adjust() receives a copy of one double, so changing it has no effect on the array (pp. 289–290, Figure 8-16). An array is a reference type: passing its name passes a copy of its memory address, so the receiving method can change the caller's elements (p. 290). readings[i] += offset therefore corrects the readings in main() even though calibrate() is void. In the book's words, Java doesn't pass an array by reference; it passes a reference to the array by value (p. 290). toFahrenheit() must not use that power: it creates new double[celsius.length], fills it, and returns it. A method that returns an array has square brackets in its return type, and its return statement names the array without brackets (p. 291). fahrenheit == log is false because == on arrays compares addresses (p. 289), and these are now two different arrays.

Messages students see when a check fails

C1 · calibrate() changes the caller's elements

Change the elements themselves: readings[i] += offset;. readings holds the address of the caller's array, so this changes the caller's readings; adjust(readings[i], offset) only changes a copy of one value.

C2 · toFahrenheit() returns a new array

Create a new array, double[] fahrenheit = new double[celsius.length];, write the converted values into it, and return it. Assigning to celsius[i] overwrites the caller's Celsius log, because celsius refers to that same array.

Progressive hints

  1. An array parameter holds a copy of the caller's array address. Through that address, assigning to an element of readings changes the caller's array directly.

  2. To leave the caller's array alone, write the results somewhere else: declare a local double[] with the same length as celsius and fill that one instead.

  3. A method that returns an array has square brackets in its return type, and its return statement names the array without brackets.

Reflection: questions and model answers

  1. Both adjust() and your calibrate() are void and change a parameter. Why does only one of them change what main() sees?

    adjust() receives a copy of a primitive value, so changing it affects only the copy. calibrate() receives a copy of the array's address; both copies point to the same array, so changing readings[i] changes main's array.

  2. Java passes a reference to an array by value. What would readings = new double[4]; inside calibrate() do to the caller's array?

    Nothing. It makes the method's copy of the reference point to a new array; main's variable still refers to the original. Only changes made through the reference, to the elements, reach the caller.

  3. Why is returning a new array the safer design for toFahrenheit(), even though converting in place would use less memory?

    The caller still needs the Celsius values. A method named for a conversion shouldn't silently destroy its input; returning a new array leaves that decision to the caller.
