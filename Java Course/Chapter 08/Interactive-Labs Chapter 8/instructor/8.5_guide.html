COP1800 · Java Programming I · Lab 8.5

The print shop that charges every order the small-job price

Objectives

  • Search an array for a value and use the same subscript in a parallel array
  • Stop a search as soon as the item is found
  • Find the range a number falls into by comparing it with the ranges' lower limits (a range match)

Requirements

  1. R1 priceOf() stops comparing as soon as it finds the code, and still returns -1.0 for a code that doesn't exist.
  2. R2 perCopyPrice() finds the order's price break with a range match on LIMITS and returns the price at the same subscript of PER_COPY.
  3. R3 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. priceOf(204) finds 204 in CODES[0]. How many comparisons does the starter still make, and why?

    Six. The for loop only stops when x reaches CODES.length, so it keeps comparing 204 with the five other codes after the match.

  2. For an order of 750 copies, which lower limits in LIMITS does 750 reach? Which of them is the right price break?

    It reaches 1, 100 and 500, but not 1000. The right break is the highest limit it reaches, 500, so the price is PER_COPY[2], $0.08.

Solution

PrintShop.java
public class PrintShop
{
    // Paper stock codes and their prices per ream, in matching positions.
    public static final int[] CODES = {204, 311, 318, 402, 517, 620};
    public static final double[] PRICES = {6.25, 8.75, 9.5, 12.0, 15.25, 21.75};

    // Price breaks: the lowest copy count of each range, and the price per copy.
    public static final int[] LIMITS = {1, 100, 500, 1000};
    public static final double[] PER_COPY = {0.12, 0.1, 0.08, 0.06};

    // How many codes the last priceOf() call compared.
    public static int steps = 0;

    // Price per ream for a stock code, or -1.0 when the code does not exist.
    public static double priceOf(int code)
    {
        double price = -1.0;
        boolean found = false;
        steps = 0;
        for(int x = 0; x < CODES.length && !found; ++x)
        {
            ++steps;
            if(code == CODES[x])
            {
                found = true;
                price = PRICES[x];
            }
        }
        return price;
    }

    // Price per copy for an order of the given number of copies (at least 1).
    public static double perCopyPrice(int copies)
    {
        int sub = LIMITS.length - 1;
        while(sub >= 0 && copies < LIMITS[sub])
            --sub;
        return PER_COPY[sub];
    }
}

Walkthrough

A parallel array has the same number of elements as another, with related values in corresponding positions (p. 284): when the search finds CODES[x], the price is PRICES[x]. Once the code is found, every further comparison is wasted (p. 286). The solution uses the book's compound condition, x < CODES.length && !found (Figure 8-12), so the loop counter changes only in the for clause; return PRICES[x]; inside the if, or setting x = CODES.length (Figure 8-11), also stops early and passes. perCopyPrice() is a range match (pp. 286–287): store only each range's low limit and compare the order with the limits. The starter's forward loop returns at the first limit the order reaches, which is always 1. The book's FindDiscount (Figure 8-13) starts at the top range and moves down while the order is below the limit; sub >= 0 is tested first, so the subscript is never used once it drops below 0. A forward loop that keeps updating the price while copies >= LIMITS[x] is also correct.

TestPrintShop.java
public class TestPrintShop
{
    public static void main(String[] args)
    {
        lookUp(204);
        lookUp(517);
        lookUp(999);

        quote(1);
        quote(99);
        quote(100);
        quote(750);
        quote(1000);
        quote(5000);
    }

    private static void lookUp(int code)
    {
        double price = PrintShop.priceOf(code);
        System.out.println("Stock " + code + ": " + price
            + " after " + PrintShop.steps + " comparison(s)");
    }

    private static void quote(int copies)
    {
        System.out.println("Order of " + copies + ": $" + PrintShop.perCopyPrice(copies)
            + " per copy");
    }
}

Messages students see when a check fails

C1 · The search stops at the first match

Stop the loop once the code is found, for example by adding && !found to the for condition and setting found = true when the code matches. Every comparison after a match is wasted, and the first codes are the most popular ones.

C2 · perCopyPrice() is a range match

Use a range match: start at the last price break (LIMITS.length - 1) and move down while the order is below that limit, then return PER_COPY at the same subscript. The starter returns at the first limit the order reaches, and every order reaches 1.

Progressive hints

  1. To stop a for loop early without changing its counter inside the body, add a second condition to the middle part of the for: keep going only while the code has not been found. A boolean flag can record that.

  2. Parallel arrays share subscripts: when CODES[x] matches, the price is PRICES[x]. In the range match, when LIMITS[x] is the right break, the price is PER_COPY[x].

  3. For the range match, start at the highest limit and move down while the order is smaller than the current limit. Test that the subscript is still 0 or more before you use it.

Reflection: questions and model answers

  1. The book suggests putting the most often ordered items first in a search array. Why does that only pay off after your change to priceOf()?

    Without an early stop, every search compares all six codes wherever the match is, so the order doesn't matter. Once the loop stops at the match, codes near the front are found in fewer comparisons.

  2. Why does a range match store only the low limit of each range, instead of one price for every possible copy count?

    One element per copy count would need thousands of elements, most repeating the same price. Four low limits describe every range, and changing a price break means editing one number.

  3. The book notes that many programmers would replace parallel arrays with an array of objects. What could go wrong with CODES and PRICES that an array of PaperStock objects (a code and a price each) would prevent?

    Someone could add a code without its price, or insert a price at the wrong position, and every later code would get its neighbour's price. An object keeps each code and its price together, so they can't drift apart.

Extension

Add quote(int copies), which returns the total for an order (copies times the price per copy). Which costs less: 99 copies or 100 copies? What does that tell you about price breaks? Then move the stock data into a PaperStock class and search a PaperStock[] instead of two parallel arrays.
