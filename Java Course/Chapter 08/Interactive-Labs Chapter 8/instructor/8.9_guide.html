The guest list that turns away Amir

Objectives

  • Use the static methods of java.util.Arrays with the class name
  • Explain why binarySearch() needs a sorted array, and read the position it returns
  • Compare the contents of two arrays with Arrays.equals() instead of ==
  • Reset every element of an array with Arrays.fill()

Requirements

  1. R1 The constructor sorts the guest names with Arrays.sort() before any search.
  2. R2 isInvited() treats every position from 0 upward that binarySearch() returns as found, and a negative result as not found.
  3. R3 sameList() compares the contents of the two arrays with Arrays.equals().
  4. R4 clearCheckIns() resets every element of checkedIn with Arrays.fill() instead of a loop.
  5. R5 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. In a sorted list where Amir comes first, what does Arrays.binarySearch(guests, "Amir") return, and what does the starter's > 0 then decide?

    It returns 0, the first position. 0 > 0 is false, so the starter says Amir is not invited.

  2. guests == other is false even when both arrays hold the same five names in the same order. What does == compare for arrays?

    == compares the two references, the memory addresses. Two separate arrays have different addresses, so == is false even when their contents match.

Solution

GuestList.java
import java.util.Arrays;

public class GuestList
{
    private String[] guests;
    private boolean[] checkedIn;   // checkedIn[i] belongs to guests[i]

    public GuestList(String[] names)
    {
        guests = names;
        Arrays.sort(guests);
        checkedIn = new boolean[guests.length];
    }

    public boolean isInvited(String name)
    {
        return Arrays.binarySearch(guests, name) >= 0;
    }

    public boolean checkIn(String name)
    {
        int position = Arrays.binarySearch(guests, name);
        if(position < 0)
            return false;
        checkedIn[position] = true;
        return true;
    }

    public int arrivals()
    {
        int count = 0;
        for(boolean arrived : checkedIn)
            if(arrived)
                ++count;
        return count;
    }

    // True when other holds the same names in the same order as this list.
    public boolean sameList(String[] other)
    {
        return Arrays.equals(guests, other);
    }

    // Starts a new evening: nobody has checked in yet.
    public void clearCheckIns()
    {
        Arrays.fill(checkedIn, false);
    }
}

Walkthrough

The Arrays class in java.util has static methods for common array tasks (p. 307, Table 8-3), so you call them with the class name. A binary search compares the key with the middle of the part still to search and discards the half that can't contain it (pp. 307–308). That only works if the array is in order (p. 309): on the unsorted RSVPs it threw away the half that held Amir, and then the half that held Zoe. binarySearch() returns the element's position, 0 or more, when the key is found, and a negative number when it isn't (p. 309), so > 0 wrongly rejects position 0. == on arrays compares references (p. 289), while Arrays.equals() compares element by element. Arrays.fill(checkedIn, false) replaces the loop. Note that Arrays.sort(guests) also reorders the caller's rsvps array, because guests holds the same reference (section 8.6).

Test program

Students run it in an IDE and paste the output into the page.

TestGuestList.java
public class TestGuestList
{
    public static void main(String[] args)
    {
        String[] rsvps = {"Zoe", "Amir", "Lena", "Kofi", "Bea"};
        GuestList list = new GuestList(rsvps);

        System.out.println("Amir invited? " + list.isInvited("Amir"));
        System.out.println("Zoe invited? " + list.isInvited("Zoe"));
        System.out.println("Max invited? " + list.isInvited("Max"));

        list.checkIn("Zoe");
        list.checkIn("Kofi");
        list.checkIn("Max");
        System.out.println("Arrivals: " + list.arrivals());

        String[] printed = {"Amir", "Bea", "Kofi", "Lena", "Zoe"};
        System.out.println("Matches the printed list? " + list.sameList(printed));

        list.clearCheckIns();
        System.out.println("Arrivals after reset: " + list.arrivals());
    }
}

Zoe invited? true
Max invited? false
Arrivals: 2
Matches the printed list? true

Messages students see when a check fails

C1 · The names are sorted before any search

Sort the names once in the constructor with Arrays.sort(guests);. binarySearch() decides which half to keep by comparing with the middle element; on an unsorted array it can throw away the half the name is in.

C2 · Position 0 counts as found

Test the result with >= 0: position 0 is the first guest in alphabetical order, and binarySearch() returns a negative number only when the name is missing.

C3 · sameList() compares contents

Return Arrays.equals(guests, other). == compares the two arrays' addresses, so two separate arrays holding the same names are never ==.

C4 · clearCheckIns() uses Arrays.fill()

Replace the loop with Arrays.fill(checkedIn, false);: it assigns the same value to every element in one call.

Progressive hints

  1. The Arrays methods are static: you call them with the class name, as in Arrays.methodName(theArray). Sorting happens in place, so there is nothing to assign.

  2. binarySearch() returns a position (0 or more) when the key is found, and a negative number when it isn't. The test you need separates negative from non-negative.

  3. Table 8-3 lists a method that returns true when two arrays of the same type hold equal elements, and one that assigns one value to every element.

Reflection: questions and model answers

  1. Why did searching the unsorted RSVP list fail for Zoe, although she is in the array? Describe what binarySearch() did.

    It compared Zoe with the middle element, Lena. Zoe comes after Lena, so it searched only the elements after the middle, Kofi and Bea, and found nothing. Zoe was in position 0 of the unsorted array, in the half it had thrown away.

  2. Arrays.sort(guests) in the constructor also reorders the test program's rsvps array. Why, and when could that surprise the caller?

    guests holds the same reference as rsvps, so sorting guests sorts the one shared array. A caller who later prints rsvps expecting the order the RSVPs arrived in would find it changed.

  3. When is writing your own search or sort loop, as in sections 8.5 and 8.7, still worth it now that Arrays does both?

    When the rule is something the library methods don't do directly, such as a range match, and while learning, because knowing how the algorithms work tells you when the library methods give reliable results, such as binarySearch() needing a sorted array.

Extension

In the constructor, copy the names into a new array before sorting it, so the caller's array keeps its order (use a loop, or look up Arrays.copyOf() in the Java API documentation). Test it by printing rsvps after creating the list.
