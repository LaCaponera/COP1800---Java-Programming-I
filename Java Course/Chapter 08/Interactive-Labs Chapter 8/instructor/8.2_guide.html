COP1800 · Java Programming I · Lab 8.2

The coffee board that sells a null for $0.0

Objectives

  • Create and fill an array in one statement with an initialization list
  • Predict the default value of the elements of a new int, double and String array
  • Decide when an array should be filled with a list and when its default values are exactly right

Requirements

  1. R1 sizes is created and filled in one statement with an initialization list of the four size names; no statement assigns a single sizes element.
  2. R2 prices is created and filled in one statement with an initialization list of the four prices, in the same order as the sizes.
  3. R3 cupsSold is still created with new int[4], and no statement assigns 0 to its elements: a new int array already holds zeros.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. In the starter, nothing is ever assigned to sizes[3] or prices[3]. So what does describe(3) put on the board, and where do those values come from?

    It shows null and 0.0. They are the default values Java gives every element of a new String array (null) and a new double array (0.0).

  2. cupsSold[3] is never set to 0 either. What does it hold, and why?

    It holds 0, because every element of a new int array is set to 0 automatically.

Solution

CoffeeMenu.java
public class CoffeeMenu
{
    private String[] sizes = {"Small", "Medium", "Large", "Extra Large"};
    private double[] prices = {2.25, 2.75, 3.25, 3.75};

    // Cups sold of each size since the cart opened this morning.
    // Every element of a new int array already starts at 0.
    private int[] cupsSold = new int[4];

    public void sell(int sizeIndex)
    {
        cupsSold[sizeIndex] += 1;
    }

    public String describe(int sizeIndex)
    {
        return sizes[sizeIndex] + " $" + prices[sizeIndex]
            + " (" + cupsSold[sizeIndex] + " sold)";
    }
}

Walkthrough

An initialization list both sizes and fills an array (p. 272), so an element can't be forgotten the way the starter forgot Extra Large: four values give exactly four elements, and new is not needed. The starter's null $0.0 line shows the default values at work: elements of an array of objects, including String, start as null; double elements start as 0.0; int elements as 0; boolean elements as false (p. 272). Those defaults are exactly what cupsSold needs, so new int[4] with no assignments is the right choice; the three = 0 statements only repeated what Java had already done. Once the constructor is empty you can delete it: Java then supplies a default constructor, and new CoffeeMenu() still compiles.

Messages students see when a check fails

C1 · sizes is created with an initialization list

Declare sizes with an initialization list, String[] sizes = {...};, holding the four names. The list sets the array's size to the number of values, so no element can be left out (and left null).

C2 · prices is created with an initialization list

Declare prices with an initialization list of the four prices, in the same order as the sizes. An element you never assign in a double array stays 0.0, which is how Extra Large ended up free.

C3 · cupsSold relies on the default value 0

Keep int[] cupsSold = new int[4]; and delete the cupsSold[...] = 0; statements: every element of a new int array already starts at 0. (cupsSold[3] was never set, and it showed 0 anyway.)

Progressive hints

  1. An initialization list is a pair of curly braces holding the values, separated by commas, after the = in the declaration. The list decides the array's size, so no number goes in the brackets.

  2. Once both arrays are filled where they are declared, the constructor has nothing left to assign. You may delete the whole constructor: Java then supplies a default one.

  3. For cupsSold, the right starting value is 0 for every size, and that is what creating the array with new already gives you.

Reflection: questions and model answers

  1. Why can an initialization list never produce the null $0.0 line that the starter produced?

    The list sets the array's size to the number of values in it, so every element gets a value from the list. With new String[4] and separate assignments, any element you forget keeps its default.

  2. Java gave cupsSold its zeros for free. Describe a situation where relying on a default value would hide a bug instead of helping.

    When 0 is not a real value, such as a price: an unassigned price shows 0.0 and the item looks free, instead of the program failing where the mistake is.

  3. Next season the cart adds a fifth size. With your version, which lines must change, and what keeps each price next to the right size?

    One value in the sizes list, one in the prices list at the same position, and the 4 in new int[4]. Only keeping the two lists in the same order lines them up; nothing checks it for you.

Extension

Make cupsSold follow the menu automatically with new int[sizes.length] (the length field is in section 8.3). Then add a fifth size, Kids $1.50, by editing only the two initialization lists. Do the existing lines of the test program still print the same?
