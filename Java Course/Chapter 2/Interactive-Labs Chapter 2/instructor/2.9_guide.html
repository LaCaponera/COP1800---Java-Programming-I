The muffin batch scaler

Objectives

  • Predict the unifying type of an expression with mixed operand types
  • Cast an operand to double before a division, not after
  • Use a cast to store a double result in a float
  • Use a cast to int and explain that it drops the fractional part

Requirements

  1. R1 scale is computed with floating-point division by casting an operand to double before dividing.
  2. R2 butterCups (a float) receives the scaled butter through an explicit cast of the whole product.
  3. R3 wholeEggs (an int) receives the scaled eggs through an explicit cast, which drops the fraction.
  4. R4 The batch card matches the screen above exactly. (verified by the program output)

Before you code: warm-up and model answers

  1. Evaluate the starter's (double) (orderedMuffins / BASE_BATCH) step by step for 30 and 12. Why is the result 2.0 and not 2.5?

    The parentheses make 30 / 12 run first. Both operands are int, so integer division gives 2 and the .5 is lost. Then (double) converts 2 into 2.0: the cast comes too late to save the fraction.

  2. flourGrams = BASE_FLOUR_GRAMS * scale; multiplies an int by a double and needs no cast. What is the unifying type, and why is no cast needed?

    double, the higher type in the order of unifying types. Java promotes the int to double automatically, and the double result is stored in a double variable, so nothing is lost and no cast is required.

Solution

BatchScaler.java
public class BatchScaler
{
    public static void main(String[] args)
    {
        final int BASE_BATCH = 12;
        final int BASE_FLOUR_GRAMS = 450;
        final double BASE_BUTTER_CUPS = 0.75;
        final int BASE_EGGS = 3;

        int orderedMuffins = 30;
        double scale;
        double flourGrams;
        float butterCups;
        int wholeEggs;

        scale = (double) orderedMuffins / BASE_BATCH;
        flourGrams = BASE_FLOUR_GRAMS * scale;
        butterCups = (float) (BASE_BUTTER_CUPS * scale);
        wholeEggs = (int) (BASE_EGGS * scale);

        System.out.println("Order: " + orderedMuffins +
            " muffins (recipe makes " + BASE_BATCH + ")");
        System.out.println("Scale factor: " + scale);
        System.out.println("Flour: " + flourGrams + " g");
        System.out.println("Butter: " + butterCups + " cups");
        System.out.println("Whole eggs: " + wholeEggs);
    }
}

Walkthrough

In the starter, orderedMuffins / BASE_BATCH divides two ints, so the result is already 2 before the cast runs: casting afterwards is too late. Casting orderedMuffins first makes one operand a double, so double becomes the unifying type and the division keeps the .5. BASE_FLOUR_GRAMS * scale needs no cast: the int is promoted to double and the result fits the double variable. BASE_BUTTER_CUPS * scale is a double, so storing it in a float needs an explicit cast around the whole product. (int) on 7.5 drops the fraction and gives 7: it truncates, it does not round.

Messages students see when a check fails

C1 · The cast happens before the division

Remove the parentheses around the division so the cast applies to orderedMuffins alone: with one double operand, Java divides in floating point and keeps the .5. Casting the finished int result is too late; the fraction is already gone.

Hint:

The cast applies to whatever immediately follows it. What follows it in the starter?

C2 · The butter product is cast to float

Multiply BASE_BUTTER_CUPS by scale (a double result) and cast the whole product to float: put the product in parentheses and (float) in front. Without the cast Java refuses, because a double doesn't fit a float without losing precision.

C3 · The eggs are cast to int

Compute BASE_EGGS * scale (a double, 7.5) in parentheses and cast it to int with (int). The cast drops the fractional part, which is exactly the "whole eggs" rule.

Progressive hints

  1. Run the starter and look at the scale factor. Then evaluate orderedMuffins / BASE_BATCH by hand: what type are the two operands?

  2. A cast applies only to the value directly after it. To change how a division is done, the cast must reach an operand, not the result.

  3. When you cast an expression with several operators, put the expression in parentheses so the cast applies to the result of all of it.

Reflection: questions and model answers

  1. Compare (double) orderedMuffins / BASE_BATCH with (double) (orderedMuffins / BASE_BATCH). Explain in your own words why the parentheses change the answer.

    In the first, the cast converts orderedMuffins to 30.0 before dividing, so the division is floating-point and gives 2.5. In the second, the parentheses make the integer division happen first, giving 2, and only that result is cast. Extra parentheses change which value the cast applies to.

  2. Flour needed no cast, but butter and eggs did. State the rule: when does Java convert for you, and when must you cast?

    Java converts automatically when the value goes to a higher type in the unifying order (an int into a double), because nothing is lost. Going to a lower type, such as double to float or double to int, can lose data, so Java requires an explicit cast to show you meant it.

Extension

The kitchen would rather round eggs to the nearest whole egg (7.5 to 8) than drop the fraction. Using only a cast and arithmetic, how could you round instead of truncate?
