The ride gate

Objectives

  • Store the result of a comparison in a boolean variable
  • Choose between > and >=, < and <= from the wording of a rule
  • Use == to compare for equality, not =
  • Reassign variables to evaluate a second case with the same statements

Requirements

  1. R1 isTallEnough is true when the height is at least MIN_HEIGHT_CM, including exactly 122.
  2. R2 isWithinWeightLimit is true when the weight is up to MAX_WEIGHT_KG, including exactly 136.
  3. R3 Rider 2's values are assigned to the same variables, and all three results are computed and printed again.
  4. R4 Every comparison uses the named constants, never the numbers 122, 136 or 14.
  5. R5 The output matches the screen above exactly. (verified by the program output)

Before you code: warm-up and model answers

  1. Rider 1 is exactly 122 cm. What does the starter's (heightCm > MIN_HEIGHT_CM) store in isTallEnough, and does that follow the rule "at least 122 cm"?

    It stores false, because 122 is not greater than 122. That breaks the rule: "at least 122" includes 122, so she should be allowed on.

  2. A teammate writes isWristbandValid = (wristbandDay = TODAY);. Why doesn't it compile?

    A single = is assignment, not comparison: it stores TODAY in wristbandDay, and the result is an int, which can't be stored in a boolean. The equality operator is ==.

Solution

RideGate.java
public class RideGate
{
    public static void main(String[] args)
    {
        final int MIN_HEIGHT_CM = 122;
        final int MAX_WEIGHT_KG = 136;
        final int TODAY = 14;

        int heightCm;
        int weightKg;
        int wristbandDay;
        boolean isTallEnough;
        boolean isWithinWeightLimit;
        boolean isWristbandValid;

        heightCm = 122;
        weightKg = 136;
        wristbandDay = 14;
        isTallEnough = (heightCm >= MIN_HEIGHT_CM);
        isWithinWeightLimit = (weightKg <= MAX_WEIGHT_KG);
        isWristbandValid = (wristbandDay == TODAY);
        System.out.println("Rider 1: " + heightCm + " cm, " + weightKg +
            " kg, wristband day " + wristbandDay);
        System.out.println("Tall enough: " + isTallEnough);
        System.out.println("Within weight limit: " + isWithinWeightLimit);
        System.out.println("Wristband valid: " + isWristbandValid);

        heightCm = 121;
        weightKg = 137;
        wristbandDay = 13;
        isTallEnough = (heightCm >= MIN_HEIGHT_CM);
        isWithinWeightLimit = (weightKg <= MAX_WEIGHT_KG);
        isWristbandValid = (wristbandDay == TODAY);
        System.out.println("Rider 2: " + heightCm + " cm, " + weightKg +
            " kg, wristband day " + wristbandDay);
        System.out.println("Tall enough: " + isTallEnough);
        System.out.println("Within weight limit: " + isWithinWeightLimit);
        System.out.println("Wristband valid: " + isWristbandValid);
    }
}

Walkthrough

"At least 122" includes 122, so the comparison is >=; "up to 136" includes 136, so it is <=. With > and < the two riders who sit exactly on a limit are wrongly refused. Each comparison produces true or false, which is stored in a boolean. For rider 2 the same variables receive new values (each holds one value at a time) and the results must be computed again: a boolean stores the result of the comparison when it ran, it doesn't watch the variables afterwards.

Messages students see when a check fails

C1 · Height uses >= with MIN_HEIGHT_CM, for both riders

"At least 122 cm" includes 122 itself, so use "greater than or equal to", >=, in both height comparisons. > leaves out the rider who is exactly at the limit.

Hint:

Read the rule aloud with each operator: is 122 "greater than 122"? Is it "greater than or equal to 122"?

C2 · Weight uses <= with MAX_WEIGHT_KG, for both riders

"Up to 136 kg" includes 136, so use <= in both weight comparisons. The two symbols go in that order, with no space between them.

C3 · Rider 2 reuses the variables and recomputes every result

For rider 2, assign 121, 137 and 13 to the existing variables (no new declarations), then repeat all three comparisons, including isWristbandValid with ==. A boolean keeps the result from when it was computed; it doesn't update when the variables change.

C4 · Comparisons use the named constants

Compare against MIN_HEIGHT_CM, MAX_WEIGHT_KG and TODAY, not the numbers. If the park changes a rule, only the constant's declaration changes.

Progressive hints

  1. Rider 1 sits exactly on both limits. For each comparison in the starter, substitute 122 or 136 and decide whether the result is true or false.

  2. Of the six relational operators, two include the equal case. Which one matches "at least", and which matches "up to"?

  3. Rider 2's block looks like rider 1's: three assignments without int in front, three comparisons, four output lines.

Reflection: questions and model answers

  1. Why did this lab test riders who are exactly at the limits? What kind of mistake do those values catch that 150 cm or 100 kg wouldn't?

    Values at the boundary are the only ones where > and >= (or < and <=) give different answers. A rider well above or below the limit gets the same result with either operator, so only boundary values reveal an operator that excludes the limit itself.

  2. After rider 2's values are assigned, what would isTallEnough hold if you forgot to recompute it? Explain.

    It would still hold true, rider 1's result. The comparison ran once, when rider 1's height was 122, and the boolean stored that answer; changing heightCm later doesn't change it. The comparison has to run again.

Extension
