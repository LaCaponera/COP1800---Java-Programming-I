The taco pickup kiosk

Objectives

  • Read an int, a line and a token with nextInt(), nextLine() and next()
  • Explain how the keyboard buffer keeps the Enter key after nextInt()
  • Consume the leftover Enter with an extra nextLine() call
  • Write one clear prompt for each value the user enters

Requirements

  1. R1 After nextInt() reads the quantity, a nextLine() call whose result isn't stored consumes the leftover Enter, before the name is read with nextLine().
  2. R2 The kiosk prompts Pickup time >> with print() and reads the time into pickupTime.
  3. R3 The ticket starts with a blank line from println(), then the header, the quantity and name, and Pickup at with the time.
  4. R4 With the input 3, Dana Cruz and 18:45, the output matches the test program's expected output. (verified by the program output)

Before you code: warm-up and model answers

  1. The customer types 3 and presses Enter. What does nextInt() take from the keyboard buffer, and what does it leave there?

    nextInt() takes the token 3 and stops at the whitespace after it, so the Enter key press is left in the buffer.

  2. Why does the starter's name prompt appear but never wait for an answer?

    nextLine() reads everything up to the next Enter. The Enter left by nextInt() is already waiting, so nextLine() returns immediately with an empty string, and the program moves on without letting the customer type.

Solution

TacoKiosk.java
import java.util.Scanner;

public class TacoKiosk
{
    public static void main(String[] args)
    {
        int quantity;
        String customerName;
        String pickupTime;
        Scanner input = new Scanner(System.in);

        System.out.print("Number of tacos >> ");
        quantity = input.nextInt();
        input.nextLine();
        System.out.print("Name for the order >> ");
        customerName = input.nextLine();

        System.out.print("Pickup time >> ");
        pickupTime = input.next();

        System.out.println();
        System.out.println("--- Order ticket ---");
        System.out.println(quantity + " tacos for " + customerName);
        System.out.println("Pickup at " + pickupTime);
    }
}

Walkthrough

nextInt() reads the token 3 and leaves the Enter key that followed it in the keyboard buffer. The next nextLine() reads everything up to the next Enter, which is already waiting, so it returns an empty string without pausing. A nextLine() call that isn't stored consumes that Enter. nextLine() is needed for the name because it contains a space (next() would return only "Dana"); the pickup time is a single token, so next() works (and nextLine() would too).

Messages students see when a check fails

C1 · The leftover Enter is consumed before the name is read

Between quantity = input.nextInt(); and the line that reads the name, add a call to nextLine() on the Scanner without storing the result. It removes the Enter that nextInt() left behind, so the name's nextLine() waits for the customer.

Hint:

The extra call doesn't need a variable or an =: its only job is to throw away what's in the buffer.

C2 · The full name is read with nextLine()

Keep nextLine() for the name: next() stops at the first space, so "Dana Cruz" would become "Dana" and "Cruz" would be read as the pickup time.

C3 · The pickup time has its own prompt and input

Print the prompt Pickup time >> with print() (so the answer goes on the same line), then read the answer into pickupTime on the next line.

C4 · The ticket starts with a blank line and ends with the pickup time

Call println() with no argument right before the header line, and add a last line that prints Pickup at followed by pickupTime.

Progressive hints

  1. Run the starter and watch the prompts: which one doesn't wait? Ask yourself what nextInt() takes from the buffer, and what it leaves.

  2. The reading's fix in Figure 2-22 adds one statement. It calls a Scanner method but doesn't assign its result to anything.

  3. The name contains a space, so it needs the method that reads a whole line. The pickup time is a single token.

Reflection: questions and model answers

  1. Your fix calls nextLine() without storing what it returns. Explain what that call does in this program and why nothing needs to be stored.

    It consumes the Enter key that nextInt() left in the keyboard buffer. The Enter carries no information we need, so it's read and thrown away; that clears the buffer, and the following nextLine() waits for the name.

  2. Why does the name need nextLine() while the pickup time could use next()? What would happen with next() for the name?

    next() returns one token, stopping at whitespace; nextLine() returns the whole line. "Dana Cruz" has a space, so next() would return only "Dana" and leave "Cruz" to be read as the pickup time. "18:45" has no spaces, so one token is enough.

Extension
