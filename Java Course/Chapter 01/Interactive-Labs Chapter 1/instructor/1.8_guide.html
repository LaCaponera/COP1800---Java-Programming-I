COP1800 · Java Programming I · Lab 1.8

Lot B is full

Objectives

  • Use an import statement to reach a class in a package
  • Display a message in a dialog box with JOptionPane.showMessageDialog()
  • Pass two arguments to a method, separated by a comma
  • Explain the difference between console output and GUI output

Requirements

  1. R1 The file imports JOptionPane from the javax.swing package, above the class.
  2. R2 First, the program logs Alert sent: Lot B is full to the console.
  3. R3 Then it shows the alert text in a dialog box centred on the screen.
  4. R4 Running the test program shows the log line between the test's own two lines. (verified by the program output)

Before you code: warm-up and model answers

  1. System.out.println() works without any import statement, but JOptionPane needs one. Why the difference?

    System is in the java.lang package, which is imported automatically into every Java program. JOptionPane is in javax.swing, which isn't, so the program must import it to use it.

  2. println() takes one argument; showMessageDialog() takes two. What is each of the two arguments for?

    The first argument says where the dialog is placed: null puts it in the centre of the screen. The second argument is the message (a literal string here) shown in the dialog.

Solution

LotAlert.java
import javax.swing.JOptionPane;

public class LotAlert
{
    public static void main(String[] args)
    {
        System.out.println("Alert sent: Lot B is full");
        JOptionPane.showMessageDialog(null,
            "Lot B is full. Please park in Lot C on Elm Street.");
    }
}

Walkthrough

JOptionPane lives in the javax.swing package, which isn't imported automatically (only java.lang, home of System, is), so the import statement goes at the top of the file, outside the class. showMessageDialog() takes two arguments separated by a comma: null places the dialog in the centre of the screen, and the second is the message. The console line comes first so the log is written even if nobody clicks OK for a while.

Messages students see when a check fails

C1 · JOptionPane is imported above the class

Add import javax.swing.JOptionPane; as the first statement in the file, before public class LotAlert. Import statements must be outside any class you write.

Hint:

Figure 1-23 shows where the import line goes.

C2 · The alert is logged to the console

Write the log line with System.out.println(), exactly Alert sent: Lot B is full. That is console output, separate from the dialog.

C3 · The dialog is centred and shows the alert

Call JOptionPane.showMessageDialog with two arguments separated by a comma: null (which centres the dialog) and the alert text in quotation marks.

Hint:

Unlike println(), this method needs two pieces of information. The first one isn't a string.

C4 · The log line comes before the dialog

Put the println() statement above the dialog. Statements run in order, and the program waits at the dialog until someone clicks OK; the log should already be written by then.

Progressive hints

  1. You need two kinds of output: one that goes to the console (you know this statement from section 1.4) and one that opens a window.

  2. The class for dialog boxes isn't in java.lang, so the compiler can't find it unless you import it. The import names the package, a dot, then the class.

  3. When a method needs more than one argument, the arguments go inside the same parentheses, separated by commas. Here the first argument controls where the dialog appears.

Reflection: questions and model answers

  1. Why must the import statement be placed above the class rather than inside main()?

    Import statements tell the compiler where to find classes used anywhere in the file, and Java requires them to be outside any class you write, at the top of the file. Inside main() it's a syntax error.

  2. For this alert, why is a dialog box a better choice than console output alone? When would console output be the better choice?

    A dialog appears in the middle of the screen and stays until someone clicks OK, so the attendant can't miss it; console text can scroll away unnoticed. Console output is better for logs and records that people don't need to act on immediately, or for programs without a GUI.
