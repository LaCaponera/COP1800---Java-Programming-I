The library kiosk

Objectives

  • Find logic errors by comparing a program's output with its specification
  • Modify a compiled class so its output changes
  • Explain why a change doesn't appear until the class is recompiled
  • Distinguish compile-time errors from runtime (logic) errors

Requirements

  1. R1 The welcome appears on two lines, Welcome to and Westside Library, spelled correctly.
  2. R2 Closed Sundays appears directly after the hours.
  3. R3 Every message is on its own line: none run together.
  4. R4 The full output matches the kiosk screen exactly. (verified by the program output)

Before you code: warm-up and model answers

  1. Predict exactly what the starter prints. How many lines appear, and what does the last one say?

    Three lines: Welcome to Westside Libary, the hours line, and Returns go in the blue bin by the doorAsk a librarian for help. The last two messages are joined because the first was printed with print(), which doesn't move to a new line.

  2. The starter compiles with no errors. Is "Libary" a syntax error or a logic error? Explain.

    A logic error. The misspelling is inside a literal string, and any combination of letters is legal there, so the compiler accepts it. The program runs but produces incorrect output, which can only be found by examining the output.

Solution

KioskMessage.java
public class KioskMessage
{
    public static void main(String[] args)
    {
        System.out.println("Welcome to");
        System.out.println("Westside Library");
        System.out.println("Hours: 9 AM to 8 PM, Monday to Saturday");
        System.out.println("Closed Sundays");
        System.out.println("Returns go in the blue bin by the door");
        System.out.println("Ask a librarian for help");
    }
}

Walkthrough

Two logic errors were in the starter: Libary is misspelled inside a literal string (the compiler never checks spelling there), and print() leaves the insertion point on the same line, so the next message ran into it: ...by the doorAsk a librarian.... Splitting the welcome is a modification: one statement becomes two, because a literal string can't be broken across lines. After saving, the class must be recompiled, or java KioskMessage runs the old .class file.

Messages students see when a check fails

C1 · The welcome is split and spelled correctly

Use two consecutive println() statements: one for Welcome to, one for Westside Library. A literal string can't continue onto the next line, so the split takes two statements. Check the spelling of Library against the screen.

Hint:

Read the starter's first message one letter at a time.

C2 · Closed Sundays follows the hours

Add a println() statement with Closed Sundays immediately after the hours statement, so the two pieces of schedule information sit together.

C3 · No message runs into the next one

One statement uses print(), which leaves the insertion point on the same line, so the next message is glued to it (...doorAsk a librarian...). Each kiosk message needs to end its line.

C4 · Lines are built from separate statements

Make each line its own println() statement rather than putting \n inside a string, the way Figure 1-19 splits the First application's output.

Reflection: questions and model answers

  1. You edit KioskMessage.java, save it, and type java KioskMessage, but the kiosk still shows the old text. What happened, and what are the steps that fix it?

    java runs the compiled KioskMessage.class, and that file still contains the old bytecode because the class wasn't recompiled. The fix: save the source file, recompile it with javac KioskMessage.java (which replaces the old .class file), then run java KioskMessage.

  2. The reading calls a logic error a kind of runtime error. Why is it usually harder to find than a syntax error?

    A syntax error is found by the compiler, which reports its line and nature. A logic error passes compilation; it shows up only when the program runs and someone notices the output is wrong, so the programmer must test and examine output carefully and then trace which statement caused it.
