The help desk that always serves the newest ticket

Objectives

  • Describe how a doubly-linked list stores each element with the addresses of the elements before and after it
  • Decide between ArrayList and LinkedList from how a program moves its data
  • Use add(0, ...), remove(0) and isEmpty() to build a fair, first-come queue

Requirements

  1. R1 Store the tickets in a LinkedList<String>; no ArrayList remains in the class.
  2. R2 addUrgent() inserts the ticket at the front of the queue (position 0).
  3. R3 serveNext() returns "(none)" when the queue is empty; otherwise it removes and returns the ticket at the front.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. Trace the starter with T1, T2 and T3 added: which ticket does the first serveNext() return, and what happens when serveNext() is called on an empty queue?

    T3, the newest ticket, because it removes the last element. On an empty queue it calls remove(-1), which throws IndexOutOfBoundsException and crashes.

  2. Look at Figure 13-18. When item 102 is removed from the linked list, which references change, and does item 103 move in memory?

    Only 101's next (now 103's address) and 103's previous (now 101's address) change. 103 stays where it is in memory.

Solution

HelpDesk.java
import java.util.*;

public class HelpDesk
{
    private LinkedList<String> tickets = new LinkedList<String>();

    // A normal ticket waits behind everyone already in the queue.
    public void addNormal(String ticket)
    {
        tickets.add(ticket);
    }

    // An urgent ticket goes ahead of everyone already waiting.
    public void addUrgent(String ticket)
    {
        tickets.add(0, ticket);
    }

    // Removes and returns the ticket at the front of the queue,
    // or "(none)" when nobody is waiting.
    public String serveNext()
    {
        if (tickets.isEmpty())
            return "(none)";
        return tickets.remove(0);
    }

    public int waiting()
    {
        return tickets.size();
    }

    public String toString()
    {
        return tickets.toString();
    }
}

Walkthrough

Java's LinkedList is doubly-linked: each element holds the address of the one before it and the one after it (p. 524). Removing or inserting therefore changes only a couple of references (Figure 13-18), while an ArrayList must move every element after the gap (p. 526). A help-desk queue inserts and removes at the front constantly, so LinkedList is the better fit. The methods are the same as ArrayList's (p. 526): add(0, ticket) puts an urgent ticket first, and remove(0) takes the oldest normal ticket because normal tickets are added at the end. The starter's remove(size() - 1) served the newest ticket (last in, first out) and threw IndexOutOfBoundsException on an empty list (remove(-1)), so check isEmpty() first. LinkedList also has addFirst() and removeFirst(), which the checks accept.

Messages students see when a check fails

C1 · Tickets live in a LinkedList

Declare private LinkedList<String> tickets = new LinkedList<String>();. Inserting and removing at the front only relinks neighbors in a linked list.

C2 · Urgent tickets go first

Use tickets.add(0, ticket): the ticket goes into position 0, ahead of everyone already waiting.

C3 · The oldest ticket is served

Return tickets.remove(0). Normal tickets join at the end, so the oldest one is at the front.

C4 · An empty queue doesn't crash

Before removing, test tickets.isEmpty() and return "(none)". Calling remove() on an empty list throws an exception.

C5 · The empty-queue message

Return exactly "(none)" when nobody is waiting, so the front-desk screen shows it.

Progressive hints

  1. Only the declaration line needs LinkedList; the methods you already call (add, remove, size) work unchanged.

  2. Decide where the front of the queue is. Normal tickets are added at the end, so the front is position 0 for both adding urgent tickets and serving.

  3. Put the empty check first in serveNext(), so remove() is never called on an empty list.

Reflection: questions and model answers

  1. The help desk also prints a daily report that walks through 5,000 closed tickets one by one with get(x). Which class would you store that list in, and why?

    An ArrayList. Reading every element in order is faster when the elements are stored next to each other; a LinkedList must follow each element's link to find the next one.

  2. With 1,000 tickets waiting, what happens inside an ArrayList when the first ticket is removed, and what happens inside a LinkedList?

    In the ArrayList the other 999 tickets each move one position up. In the LinkedList only the new first ticket's previous link changes; nothing moves.
