COP1800 · Java Programming I · Lab 13.7

Three copies of one loop, and a counter that finds nothing

Objectives

  • Write a generic method by placing a type parameter section before the return type
  • Replace near-identical overloads with one generic method
  • Use the type parameter as a return type so callers get the right type without a cast
  • Compare objects with equals() rather than ==

Requirements

  1. R1 One generic method, public static <T> void printNumbered(T[] items), replaces the three type-specific copies.
  2. R2 countMatches() compares each element with target using equals().
  3. R3 lastOf() is generic, public static <T> T lastOf(T[] items), and returns null for an empty array.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. Read the starter's countMatches() header. Where does the type parameter section <T> sit, and what does T become when the test calls countMatches(scores, 1000)?

    Between static and the return type int. T becomes Integer, because scores is an Integer[] and 1000 is boxed to an Integer.

  2. Why does String lastRoom = ListTools.lastOf(rooms); fail to compile with the starter even though the array holds Strings?

    lastOf() is declared to return Object, and the compiler won't assign an Object to a String variable without a cast, whatever is actually in the array.

Solution

ListTools.java
public class ListTools
{
    // One method prints a numbered list of any reference type.
    public static <T> void printNumbered(T[] items)
    {
        int count = 1;
        for (T element : items)
        {
            System.out.println(count + ". " + element);
            ++count;
        }
        System.out.println("----------");
    }

    // Counts the elements equal to target.
    public static <T> int countMatches(T[] items, T target)
    {
        int matches = 0;
        for (T element : items)
        {
            if (element.equals(target))
                ++matches;
        }
        return matches;
    }

    // Returns the last element, or null if the array is empty.
    public static <T> T lastOf(T[] items)
    {
        if (items.length == 0)
            return null;
        return items[items.length - 1];
    }
}

Walkthrough

A generic method puts its type parameter section in angle brackets before the return type (p. 532), exactly like the book's displayNumberedList(). The single printNumbered() then accepts an array of any reference type, so Character[] works without a fourth copy. Used as the return type, T lets the compiler know that lastOf(rooms) returns a String and lastOf(scores) an Integer, so the caller needs no cast and can call toUpperCase() or add 1 directly. Type parameters must be reference types (p. 532), which is why the arrays are Integer[] and Character[], not int[] or char[]. == on objects compares references: the two 1000s were boxed into separate Integer objects, and part + "air" builds a new String at run time, so == finds no match even though the values are equal. equals() compares values. The empty-array check comes first because items[items.length - 1] is items[-1] when the length is 0.

Messages students see when a check fails

C1 · One generic printNumbered()

Write public static <T> void printNumbered(T[] items) and use T for the loop variable. The <T> goes before the return type void.

C2 · The type-specific copies are gone

Delete the String[], Integer[] and Double[] versions. The generic method handles them all, and the test's Character[] too.

C3 · countMatches() compares values

Use element.equals(target). == is true only when both references point to the same object, so equal values in different objects don't match.

C4 · lastOf() returns the caller's type

Write public static <T> T lastOf(T[] items). The second T is the return type: a String[] gives back a String, an Integer[] an Integer.

C5 · An empty array returns null

Return null when items.length == 0, before reading items[items.length - 1], which would be items[-1].

Progressive hints

  1. Keep one copy of printNumbered(), add <T> before void, and change String to T in the parameter and the loop.

  2. Inside countMatches(), ask the element whether it equals the target: element.equals(target).

  3. lastOf() needs T in three places: the type parameter section, the return type and the array parameter.

Reflection: questions and model answers

  1. The office wants Integer lists printed differently, with each score right-aligned. The book (p. 533) says generic methods can be overloaded. Which method would Java call for printNumbered(scores) if you added printNumbered(Integer[] items) beside the generic one?

    The Integer[] version, because it matches the argument more exactly. Every other type still goes to the generic <T> method.

  2. Why did countMatches(scores, 1000) return 0 with ==, even though 1000 appears twice?

    Each 1000 was boxed into its own Integer object, so == compared three different references and never found the same object. equals() compares the values inside, which are equal.
