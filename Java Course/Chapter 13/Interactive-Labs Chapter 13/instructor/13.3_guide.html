The race results that reshuffle the entry list

Objectives

  • Store objects of your own class in an ArrayList and remove one by its position
  • Make a class sortable by implementing Comparable and overriding compareTo()
  • Sort with Collections.sort() without destroying an order the program still needs

Requirements

  1. R1 Runner implements Comparable<Runner> and overrides compareTo(). It returns a negative number, 0 or a positive number by comparing seconds, so the fastest runner sorts first.
  2. R2 ranked() sorts with Collections.sort().
  3. R3 ranked() sorts a new ArrayList that holds the same runners (for example, filled with addAll()) and returns it, leaving entries in registration order.
  4. R4 withdraw() loops through entries with size() and get(), removes the runner whose bib matches with remove(), and returns true. If no bib matches, it returns false.
  5. R5 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. Without a compareTo() method, what goes wrong if ranked() calls Collections.sort(entries) on the starter's Runner class?

    It doesn't compile: Collections.sort() needs elements that implement Comparable, and Runner doesn't, so Java can't tell how to order two runners.

  2. Priya ran 1520 s and Marco ran 1495 s. With the natural ordering "fewer seconds first", what should priya.compareTo(marco) return: 1, 0 or -1? Why?

    1, because Priya took more seconds, so she is "greater" and must sort after Marco.

Solution

Runner.java
public class Runner implements Comparable<Runner>
{
    private int bib;
    private String name;
    private int seconds;

    public Runner(int bib, String name, int seconds)
    {
        this.bib = bib;
        this.name = name;
        this.seconds = seconds;
    }

    public int getBib()
    {
        return bib;
    }

    public int getSeconds()
    {
        return seconds;
    }

    public String toString()
    {
        return "#" + bib + " " + name + " " + seconds + "s";
    }

    // Faster runners come first: fewer seconds means "less than".
    @Override
    public int compareTo(Runner other)
    {
        int result;
        if (seconds == other.seconds)
            result = 0;
        else
            if (seconds > other.seconds)
                result = 1;
            else
                result = -1;
        return result;
    }
}
Leaderboard.java
import java.util.*;

public class Leaderboard
{
    private ArrayList<Runner> entries = new ArrayList<Runner>();

    // Adds a runner in the order the official entry list received them.
    public void add(Runner r)
    {
        entries.add(r);
    }

    public ArrayList<Runner> entryOrder()
    {
        return entries;
    }

    // Returns the runners fastest first.
    // The official entry order must stay exactly as it was.
    public ArrayList<Runner> ranked()
    {
        ArrayList<Runner> copy = new ArrayList<Runner>();
        copy.addAll(entries);
        Collections.sort(copy);
        return copy;
    }

    // Removes the runner wearing this bib. Returns true if one was removed.
    public boolean withdraw(int bib)
    {
        for (int x = 0; x < entries.size(); ++x)
        {
            if (entries.get(x).getBib() == bib)
            {
                entries.remove(x);
                return true;
            }
        }
        return false;
    }

    public int size()
    {
        return entries.size();
    }
}

Walkthrough

Collections.sort() orders objects with their compareTo() method (p. 520). For your own class you choose the natural ordering, write implements Comparable<Runner> in the class header and override compareTo() (pp. 520–521). The method returns 0 for equal times, 1 if this runner is slower and -1 if faster, the same pattern as the book's Student class; Integer.compare(seconds, other.seconds) returns the same signs. Collections.sort() changes the list it receives, so ranked() fills a new ArrayList with addAll() (Table 13-1) and sorts that; both lists hold references to the same Runner objects, so nothing is duplicated except the references. Marco and Sam tie at 1495 s, and they stay in entry order because Collections.sort() is stable. In withdraw(), remove(x) removes by position and closes the gap (p. 515); returning right away avoids skipping the element that moves into position x.

Messages students see when a check fails

C1 · Runner implements Comparable<Runner>

Change the header to public class Runner implements Comparable<Runner>. The type in angle brackets says what a Runner is compared to.

C2 · compareTo() is overridden

Add @Override public int compareTo(Runner other) to Runner. It must be public, take a Runner and return an int.

C3 · Runners are compared by time

Compare seconds with other.seconds: return 0 when equal, 1 when this runner is slower, -1 when faster. The leaderboard ranks by time, not by bib.

C4 · ranked() uses Collections.sort()

Call Collections.sort(copy) in ranked(). It uses the compareTo() you wrote in Runner.

C5 · The entry list is never sorted

Make a new ArrayList<Runner>, copy the runners into it with copy.addAll(entries), then sort and return the copy. Sorting entries itself would reorder the official entry list.

C6 · withdraw() removes by position

Loop with for (int x = 0; x < entries.size(); ++x). When entries.get(x).getBib() == bib, call entries.remove(x) and return true;.

Progressive hints

  1. Copy the shape of the book's Student.compareTo() on p. 521, but compare seconds instead of id.

  2. ranked() takes three statements: create an empty ArrayList<Runner>, addAll() the entries into it, then sort it. Return the copy.

  3. In withdraw(), get(x) gives you a Runner, and a Runner has getBib(). Return as soon as you have removed one.

Reflection: questions and model answers

  1. The race director now wants the leaderboard sorted by bib number. Which single method would you change, and why does Leaderboard not need to change at all?

    Only Runner.compareTo(), to compare bib instead of seconds. Collections.sort() asks each Runner how it compares, so the sorting code in Leaderboard stays the same.

  2. copy and entries are two different ArrayList objects. Are there now two Priya Runner objects in memory? Explain what addAll() copied.

    No. A collection holds references, so addAll() copied the references. Both lists point to the same four Runner objects; only the order of the references differs.
