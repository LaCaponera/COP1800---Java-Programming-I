The waitlist that turns people away at three

Objectives

  • Explain why a collection is dynamically resizable and an array is not
  • Store a group of objects in a Collection<String> instead of an array and a counter
  • Use the Collection methods add(), contains(), remove(), removeAll() and size() from Table 13-1

Requirements

  1. R1 Store the names in a Collection<String> field (the type in angle brackets is String). Remove the String[] array and the count field.
  2. R2 join() returns false for a name that is already waiting (contains()); otherwise it adds the name and returns what add() returns.
  3. R3 leave(), isWaiting(), size() and toString() each use one Collection method instead of a loop.
  4. R4 dropNoShows() removes every name in noShows with a single removeAll() call and returns its result.
  5. R5 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. Trace the starter: which of the six join() calls return true, and why does Dara get false?

    Ana, Ben and Chen get true. Dara, Eli and the second Ana get false because count reaches names.length (3) and the array can't grow.

  2. The second Join Ana must print false. Which Collection method in Table 13-1 tells you whether Ana is already on the list?

    contains(Object obj): it returns true if the object is an element of the collection.

Solution

Waitlist.java
import java.util.*;

public class Waitlist
{
    private Collection<String> names = new ArrayList<String>();

    // Adds a name to the end of the waitlist. Returns true if it was added.
    public boolean join(String name)
    {
        if (names.contains(name))
            return false;
        return names.add(name);
    }

    // Removes a name. Returns true if the name was on the list.
    public boolean leave(String name)
    {
        return names.remove(name);
    }

    // Returns true if the name is on the list.
    public boolean isWaiting(String name)
    {
        return names.contains(name);
    }

    // Removes everyone in noShows. Returns true if anyone was removed.
    public boolean dropNoShows(Collection<String> noShows)
    {
        return names.removeAll(noShows);
    }

    public int size()
    {
        return names.size();
    }

    public String toString()
    {
        return names.toString();
    }
}

Walkthrough

An array must be given its size when it is created and that size can't change; a collection can grow and shrink as objects are added or removed (p. 511), so the limit of three disappears with the array. Every operation the starter wrote by hand is a method in Table 13-1 (p. 512): contains() answers "is this name here?", add() and remove() return true when the collection changed, size() counts the elements and removeAll() removes every element of another collection in one call, returning true only if something was removed (which is why the second call prints false). ArrayList's toString() already prints [Ana, Dara]. Declaring the field as Collection<String> means the class uses only the operations every collection has; ArrayList<String> or List<String> also pass.

Test program

Students run it in an IDE and paste the output into the page.

TestWaitlist.java
import java.util.*;

public class TestWaitlist
{
    public static void main(String[] args)
    {
        Waitlist list = new Waitlist();
        String[] arrivals = {"Ana", "Ben", "Chen", "Dara", "Eli", "Ana"};
        for (String name : arrivals)
            System.out.println("Join " + name + ": " + list.join(name));
        System.out.println("Waiting: " + list.size() + " " + list);
        System.out.println("Is Chen waiting? " + list.isWaiting("Chen"));
        System.out.println("Leave Ben: " + list.leave("Ben"));
        System.out.println("Leave Zoe: " + list.leave("Zoe"));

        ArrayList<String> noShows = new ArrayList<String>();
        noShows.add("Chen");
        noShows.add("Eli");
        System.out.println("Dropped no-shows: " + list.dropNoShows(noShows));
        System.out.println("Dropped again: " + list.dropNoShows(noShows));
        System.out.println("Waiting: " + list.size() + " " + list);
    }
}

Messages students see when a check fails

C1 · Names live in a Collection of Strings

Declare the field as private Collection<String> names = new ArrayList<String>();. A collection grows as students join, so the limit of three disappears.

C2 · The array and the counter are gone

Delete String[] names and int count. The collection stores the names and knows how many there are (size()).

C3 · join() refuses a name already waiting

In join(), return false when names.contains(name) is true; otherwise return names.add(name).

C4 · leave() uses remove()

Replace the loop in leave() with return names.remove(name);. remove() already returns true only when the name was there.

C5 · isWaiting() uses contains()

Replace the loop in isWaiting() with return names.contains(name);.

C6 · size() and toString() ask the collection

Return names.size() from size() and names.toString() from toString(). The collection already formats itself as [Ana, Dara].

C7 · dropNoShows() uses removeAll()

Write return names.removeAll(noShows);. One call removes every no-show and tells you whether anything changed.

Progressive hints

  1. Start with the field. Once the names are in a collection, every method that used names[x] or count turns red; fix them one at a time.

  2. Read the returns column of Table 13-1: add(), remove() and removeAll() all return a boolean that says whether the collection changed. Those are exactly the values your methods must return.

  3. join() needs one if before adding: a name that contains() finds gets false.

Reflection: questions and model answers

  1. The book says collections cannot hold primitive types. What would happen if the club stored student ID numbers as Collection<int>, and what would you write instead?

    It doesn't compile, because the type in angle brackets must be a class. Use Collection<Integer>; Java wraps each int in an Integer object when you add it.

  2. Why did the second dropNoShows(noShows) call print false? What does that return value let a program do?

    Chen and Eli had already been removed, so removeAll() changed nothing and returned false. The program can tell whether the call did anything, for example to report "no one to drop".

Extension

Add boolean keepOnly(Collection<String> confirmed) that uses retainAll() to keep only students who confirmed by email, and boolean allWaiting(Collection<String> group) that uses containsAll() to check whether a whole group of friends is on the list.
