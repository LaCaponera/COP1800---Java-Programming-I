COP1800 · Java Programming I · Lab 13.2

The concert program that can't say who's in slot 3

Objectives

  • Explain what a List adds to a Collection: positions (indexes) and duplicates
  • Use the List methods indexOf(), lastIndexOf(), add(int, Object) and set() from Table 13-2
  • Take part of a list with subList() without asking for an end past the list's size

Requirements

  1. R1 Declare acts as a List<String> so the class can use the index methods.
  2. R2 insertAfter() finds the existing act with indexOf(), returns false when it gets -1, and otherwise inserts with add(index, act). firstSlot() and lastSlot() return indexOf() and lastIndexOf().
  3. R3 replace() uses set() and returns the act that was in the slot (set() returns it).
  4. R4 nextUp() returns subList(0, end), where end is never larger than the number of acts.
  5. R5 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. The starter's insertAfter("Jazz", "Piano") returns true. Where in the running order does the Piano act actually end up, and why?

    At the end, after the second Choir, because the starter calls add(act), which always adds to the end. A Collection has no way to add at a position.

  2. The running order is [Choir, Jazz, Drums, Choir]. What do indexOf("Choir"), lastIndexOf("Choir") and indexOf("Mime") return?

    0, 3 and -1. The first Choir is at index 0, the last at index 3, and Mime isn't in the list.

Solution

RunningOrder.java
import java.util.*;

public class RunningOrder
{
    private List<String> acts = new ArrayList<String>();

    // Books an act at the end of the show.
    public void book(String act)
    {
        acts.add(act);
    }

    // Puts act in the slot right after existing.
    // Returns false, and changes nothing, if existing isn't booked.
    public boolean insertAfter(String existing, String act)
    {
        int slot = acts.indexOf(existing);
        if (slot == -1)
            return false;
        acts.add(slot + 1, act);
        return true;
    }

    // Slot of the first and of the last appearance of an act (0 = opener).
    public int firstSlot(String act)
    {
        return acts.indexOf(act);
    }

    public int lastSlot(String act)
    {
        return acts.lastIndexOf(act);
    }

    // Puts act in the given slot and returns the act it replaced.
    public String replace(int slot, String act)
    {
        return acts.set(slot, act);
    }

    // The next count acts for the stage manager's cue card.
    // Asking for more acts than are booked gives the whole show.
    public List<String> nextUp(int count)
    {
        int end = Math.min(count, acts.size());
        return acts.subList(0, end);
    }

    public String toString()
    {
        return acts.toString();
    }
}

Walkthrough

List extends Collection, so it keeps every collection method and adds methods that work with an index (Table 13-2, p. 513). A list keeps its elements in order and may contain duplicates, which is why the Choir can open and close the show. indexOf() returns the first index of an element and lastIndexOf() the last, both -1 when the element isn't there; checking for -1 before inserting is what makes Mime after Magic change nothing. add(index, obj) inserts and keeps the existing elements (they shift one slot later), while set(index, obj) replaces the element and returns the old one. subList(start, end) returns the elements from start to one less than end, so subList(0, 3) is slots 0, 1 and 2; Math.min(count, acts.size()) (or an if) keeps end legal. The field could also be ArrayList<String>; List<String> asks only for what the class needs.

public class TestRunningOrder

        show.book("Choir");
        show.book("Jazz");

Messages students see when a check fails

C1 · acts is a List

Change the field to private List<String> acts = new ArrayList<String>();. Only a List has indexOf(), add(index, ...), set() and subList().

C2 · insertAfter() finds the act and inserts after it

Store acts.indexOf(existing) in a variable, then insert with acts.add(slot + 1, act). The new act goes one slot after the one you found.

C3 · A missing act changes nothing

indexOf() returns -1 when the act isn't booked. Test for it and return false; before adding anything.

C4 · First and last slots

firstSlot() returns acts.indexOf(act) and lastSlot() returns acts.lastIndexOf(act). The Choir appears twice, and only lastIndexOf() finds the second one.

C5 · replace() uses set()

Return acts.set(slot, act). set() replaces the element and gives back the one that was there, which the stage manager wants to hear.

C6 · nextUp() uses subList()

Return acts.subList(0, end). It holds the elements from index 0 up to one less than end.

C7 · The end never passes the list's size

subList(0, 10) on a five-act show throws IndexOutOfBoundsException. Use Math.min(count, acts.size()) (or an if) as the end.

Progressive hints

  1. Change the field first. Every method you need in this lab is in Table 13-2, which lists what List adds to Collection.

  2. insertAfter() takes three steps: find the position of existing, give up if it is -1, then insert one position later.

  3. For nextUp(), ask yourself what the largest legal end for subList() is in a five-act show.

Reflection: questions and model answers

  1. add(2, "Piano") and set(2, "Piano") both take an index and an act. How do the running orders they produce differ?

    add() inserts the act and moves every later act one slot down, so the show gets longer. set() overwrites the act in slot 2, so the show keeps its length and the old act is gone.

  2. Why must insertAfter() check for -1 before calling add(slot + 1, act)? What would happen without the check when the act isn't booked?

    indexOf() returns -1 for a missing act, so slot + 1 would be 0 and the new act would quietly become the opener. The check makes the method report false and leave the show unchanged.

Extension

Add boolean move(String act, int newSlot) that removes the first appearance of act with remove(int) and puts it back at newSlot with add(int, Object). Return false if the act isn't booked or newSlot is outside the show.
