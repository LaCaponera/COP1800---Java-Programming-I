Lab 14.1: The audit that thinks a Jukebox is a control

Tell Swing controls, containers and windows apart by their type, not their name

Estimated time: about 20 minutes. Reading: Ch. 14, section 14.1 (pp. 545–546).

You will be able to:

  • Describe how JComponent, Container, Component, Window, Frame and JFrame are related
  • Explain why every Swing control is also a container, and why a JFrame is not a JComponent
  • Use instanceof to classify GUI objects by type instead of guessing from a class name

How to complete it

  1. Open the lab page (14.1.html) from this module. Your work saves automatically in your browser.
  2. Answer the short warm-up about the code you are given, then write your code until every structure check passes.
  3. Run the test program (instructions are on the lab page), paste its output back into the page and compare.
  4. Answer the reflection questions in your own words.
  5. Download (or copy) your lab report.

Submit here: the lab report (.txt) and your code file (ComponentAudit.java).

How it will be assessed

  • Requirements met (5 pts): All structure checks pass and the test program's output matches (see the lab report).
  • Reasoning (3 pts): Warm-up and reflection answers are specific to this code, in the student's own words.
  • Style (2 pts): Allman braces and indentation kept; ancestry() left unchanged; one instanceof test per question.

The checks on the lab page give you feedback; they are not your grade.
