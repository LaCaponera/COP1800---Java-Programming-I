The renewal form with a field too small for a barcode

Objectives

  • Add JLabel, JTextField and JButton components to a JFrame in the order users read them
  • Size a JTextField for the data it will hold
  • Use getText(), setText() and setEditable() on text fields and buttons

Requirements

  1. R1 The constructor adds prompt, barcodeField, renewButton and status to the frame, in that order.
  2. R2 barcodeField is created with room for at least 16 characters: a 14-digit barcode plus a little extra.
  3. R3 getBarcode() returns the field's text with spaces removed at both ends. clearForm() empties the field and sets the status back to READY.
  4. R4 recordFailedAttempt() shows Barcode not found. Tries left: n until attempts reaches LIMIT; from then on the field is not editable, the button reads See the desk and the status reads Too many tries. Please see the desk.
  5. R5 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. In what order do the starter's components appear in the window? Why does that order come from the constructor, not from the order of the field declarations?

    Barcode:, the Renew button, then the text field; the status label is missing. FlowLayout places components in the order add() is called, and the constructor adds the button before the field and never adds status.

  2. A JTextField(5) still accepts 14 digits. What goes wrong for the patron, according to section 14.6?

    Only about five characters show; the rest scroll out of view, so the patron can't check the barcode they typed.

Solution

RenewalFrame.java
import javax.swing.*;
import java.awt.*;

public class RenewalFrame extends JFrame
{
    final int FRAME_WIDTH = 460;
    final int FRAME_HEIGHT = 140;
    final int LIMIT = 3;
    final String READY = "Scan or type the barcode.";
    JLabel prompt = new JLabel("Barcode:");
    JTextField barcodeField = new JTextField(16);
    JButton renewButton = new JButton("Renew");
    JLabel status = new JLabel(READY);
    int attempts = 0;

    public RenewalFrame()
    {
        super("Renew a book");
        setSize(FRAME_WIDTH, FRAME_HEIGHT);
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        setLayout(new FlowLayout());
        add(prompt);
        add(barcodeField);
        add(renewButton);
        add(status);
    }

    // Returns what the patron typed, without spaces at either end.
    public String getBarcode()
    {
        return barcodeField.getText().trim();
    }

    // Gets the form ready for the next patron.
    public void clearForm()
    {
        barcodeField.setText("");
        status.setText(READY);
    }

    // Called each time a barcode is not found.
    public void recordFailedAttempt()
    {
        ++attempts;
        if (attempts >= LIMIT)
        {
            barcodeField.setEditable(false);
            renewButton.setText("See the desk");
            status.setText("Too many tries. Please see the desk.");
        }
        else
        {
            status.setText("Barcode not found. Tries left: " + (LIMIT - attempts));
        }
    }
}

Walkthrough

With FlowLayout, components appear left to right in the order they are added (p. 561), so the order of the add() calls, not the order of the field declarations, decides what the patron sees; the starter also never added status. new JTextField(16) leaves room for a 14-digit barcode; the section advises overestimating, because extra characters scroll out of view in a field that is too small (p. 559). getText() returns a String (p. 560), so trim() can remove the spaces a scanner adds. setText("") clears the field. setEditable(false) stops the patron from changing the field once attempts reaches LIMIT, the same idea as the book's if(attempts > LIMIT) example (p. 560); here the lock comes on at the third failure, so the comparison is >=. A JButton's text changes with setText() (p. 560). Any column count of 16 or more passes the checks.

Test program

Students run it in an IDE and paste the output into the page.

TestRenewalFrame.java
import javax.swing.*;
import java.awt.*;

public class TestRenewalFrame
{
    public static void main(String[] args)
    {
        RenewalFrame form = new RenewalFrame();
        System.out.println("Title: " + form.getTitle());
        System.out.println("Left to right:");
        for (Component part : form.getContentPane().getComponents())
            System.out.println("  " + describe(part));
        boolean roomy = form.barcodeField.getColumns() >= 16;
        System.out.println("Field has room for a barcode: " + roomy);

        form.barcodeField.setText("  31234005678901 ");   // what the scanner sends
        System.out.println("Barcode read: \"" + form.getBarcode() + "\"");
        form.status.setText("Renewed until Dec 2.");
        form.clearForm();
        System.out.println("After clearForm:");
        System.out.println("  field: \"" + form.barcodeField.getText() + "\"");
        System.out.println("  status: " + form.status.getText());

        for (int attempt = 1; attempt <= 4; ++attempt)
        {
            form.recordFailedAttempt();
            String field = form.barcodeField.isEditable() ? "editable" : "locked";
            System.out.println("Failed attempt " + attempt + ": field " + field);
            System.out.println("  button: " + form.renewButton.getText());
            System.out.println("  status: " + form.status.getText());
        }
        System.exit(0);   // close the window
    }

    static String describe(Component part)
    {
        if (part instanceof JLabel)
            return "JLabel " + ((JLabel) part).getText();
        if (part instanceof JButton)
            return "JButton " + ((JButton) part).getText();
        if (part instanceof JTextField)
            return "JTextField";
        return part.getClass().getSimpleName();
    }
}

Messages students see when a check fails

C1 · Components are added in reading order

Add the components in reading order: add(prompt);, add(barcodeField);, add(renewButton);, add(status);. FlowLayout places them left to right in the order you add them.

C2 · The field has room for a whole barcode

Create the field with at least 16 columns, for example new JTextField(16). A barcode has 14 digits, and section 14.6 advises overestimating a field's size.

C3 · getBarcode() trims the field's text

Return barcodeField.getText().trim();. getText() reads the field, and trim() removes the spaces a scanner can add at either end.

C4 · clearForm() resets the field and the status

In clearForm(), call barcodeField.setText("") and status.setText(READY) so the next patron starts with an empty field and the instructions.

C5 · The field locks after LIMIT failed attempts

Compare attempts with LIMIT; once it is reached, call barcodeField.setEditable(false) and change the button with renewButton.setText("See the desk").

Progressive hints

  1. FlowLayout places components left to right in the order you call add().

  2. getText() returns a String, so you can call any String method on the result.

  3. In recordFailedAttempt(), decide with one if on attempts and LIMIT: lock the form, or report the tries left (LIMIT - attempts).

Reflection: questions and model answers

  1. Why lock the field with setEditable(false) instead of removing it from the window?

    The patron and the staff can still see the barcode that was typed, and the layout doesn't jump around; the field just stops accepting changes.

  2. The test types the barcode with spaces around it, the way some scanners send it. What would go wrong in the library's lookup if getBarcode() didn't trim?

    " 31234005678901 " is not equal to the stored "31234005678901", so a correct barcode would be reported as not found and count as a failed attempt.

Extension

Add a JPasswordField for the patron's four-digit PIN between the barcode and the button, and a method pinLooksValid() that returns true only when exactly four characters were typed. Look up getPassword() in the Java documentation first: why does it return a char[] instead of a String?
