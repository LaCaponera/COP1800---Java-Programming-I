COP1800 · Java Programming I · Lab 14.3

The pickup board that never shows the order

Objectives

  • Change the text of an existing JLabel with setText() instead of creating a new label
  • Build Font objects and derive one font from another with deriveFont()
  • Remove a component from a container and refresh it with invalidate(), validate() and repaint()

Requirements

  1. R1 makeHeadline(text) returns a JLabel showing the text in HEADLINE_FONT (Arial, bold, 36 points).
  2. R2 footerFont(headline) returns a font derived from headline with deriveFont(): same typeface, plain, 14 points.
  3. R3 announce(label, orderNumber) changes the text of the label it receives to Order 42 is ready (for order 42). It must not create a new JLabel.
  4. R4 retire(board, label) removes the label from the board, then calls invalidate(), validate() and repaint() on the board so a showing window updates.
  5. R5 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. The starter's announce() builds a brand-new JLabel with the order number. Why does the board still say Welcome!?

    The new label is assigned only to the parameter, a local copy of the reference. The label on the board is a different object that never changes, and the new label is never added to the board.

  2. Name the three arguments of the Font constructor and say what each controls in new Font("Arial", Font.BOLD, 36).

    Typeface ("Arial", the font's name), style (Font.BOLD) and point size (36, about 1/72 of an inch per point).

Solution

OrderBoard.java
import javax.swing.*;
import java.awt.*;

public class OrderBoard
{
    // The font for the big line on the TV above the counter.
    public static final Font HEADLINE_FONT = new Font("Arial", Font.BOLD, 36);

    // Returns a label that shows text in the headline font.
    public static JLabel makeHeadline(String text)
    {
        JLabel label = new JLabel(text);
        label.setFont(HEADLINE_FONT);
        return label;
    }

    // Returns the font for the small line under the headline:
    // the headline's typeface, plain, 14 points.
    public static Font footerFont(Font headline)
    {
        return headline.deriveFont(Font.PLAIN, 14);
    }

    // Shows "Order 42 is ready" on the label that is already on the board.
    public static void announce(JLabel label, int orderNumber)
    {
        label.setText("Order " + orderNumber + " is ready");
    }

    // Takes a label off a board that is already showing.
    public static void retire(JFrame board, JLabel label)
    {
        board.remove(label);
        board.invalidate();
        board.validate();
        board.repaint();
    }
}

Walkthrough

setFont() takes a Font object (p. 553), so makeHeadline() applies the shared HEADLINE_FONT constant. deriveFont(Font.PLAIN, 14) builds a new font from the headline (p. 554): it keeps the typeface, so a Serif headline gives a Serif footer, which is exactly what basing one font on another is for. In announce(), the parameter holds a reference to the label already on the board; setText() (p. 553) changes that object. Assigning new JLabel(...) to the parameter only makes the local variable point to a new label that is never added anywhere, so the board doesn't change. retire() uses remove(), the counterpart of add(), and then invalidate(), validate() and repaint(), which section 14.3 says are needed when a component is added or removed after the window is visible. revalidate() instead of invalidate() and validate() also passes.

Test program

Students run it in an IDE and paste the output into the page.

TestOrderBoard.java
import javax.swing.*;
import java.awt.*;

public class TestOrderBoard
{
    public static void main(String[] args)
    {
        JFrame board = new JFrame("Pickup");
        board.setSize(400, 150);
        JLabel headline = OrderBoard.makeHeadline("Welcome!");
        board.add(headline);
        System.out.println("Headline: " + headline.getText()
            + " in " + describe(headline.getFont()));

        OrderBoard.announce(headline, 42);
        System.out.println("After announce: " + headline.getText());
        OrderBoard.announce(headline, 43);
        System.out.println("After announce: " + headline.getText());

        Font footer = OrderBoard.footerFont(OrderBoard.HEADLINE_FONT);
        System.out.println("Footer (Arial headline): " + describe(footer));
        Font rebrand = new Font("Serif", Font.BOLD, 40);
        footer = OrderBoard.footerFont(rebrand);
        System.out.println("Footer (Serif headline): " + describe(footer));

        Container content = board.getContentPane();
        System.out.println("Labels on board: " + content.getComponentCount());
        OrderBoard.retire(board, headline);
        int left = content.getComponentCount();
        System.out.println("Labels on board after retire: " + left);
        System.exit(0);   // close the board window
    }

    static String describe(Font font)
    {
        String style = "plain";
        if (font.isBold() && font.isItalic())
            style = "bold italic";
        else if (font.isBold())
            style = "bold";
        else if (font.isItalic())
            style = "italic";
        return font.getName() + ", " + style + ", " + font.getSize() + " pt";
    }
}

Messages students see when a check fails

C1 · The headline label uses HEADLINE_FONT

Call label.setFont(HEADLINE_FONT); before returning the label. A new JLabel uses the look and feel's small default font.

C2 · The footer font is derived from the headline

Return headline.deriveFont(Font.PLAIN, 14);. A derived font keeps the headline's typeface, so a Serif headline gives a Serif footer; new Font("Arial", ...) would stay Arial forever.

C3 · announce() changes the existing label

Call label.setText("Order " + orderNumber + " is ready");. Creating a new JLabel changes only your local variable; the label on the board stays the same object.

C4 · retire() removes the label and refreshes the board

Call board.remove(label);, then invalidate(), validate() and repaint() on the board. Emptying the text leaves the label in the window, and without the three calls a showing window keeps its old layout.

Progressive hints

  1. A parameter holds a reference to the label on the board. Calling a method through that reference changes the board's label; assigning a new object to the parameter only changes where your local variable points.

  2. Section 14.3 uses setText() for a label's text, setFont() for its font and deriveFont(style, size) for a font based on another one.

  3. After the label is removed from the board, the window keeps its old layout until you call the three methods from the section's last paragraph before Changing a JLabel's Font.

Reflection: questions and model answers

  1. Why does the footer derive its font from the headline instead of creating new Font("Arial", Font.PLAIN, 14)? Use the Serif line of the output in your answer.

    A derived font keeps the headline's typeface. When marketing switches the headline to Serif, the footer becomes Serif too (the output shows Serif, plain, 14), while a hard-coded Arial footer would no longer match.

  2. Section 14.3 calls the typeface argument "only a request". What happens on a computer that has no Arial, and why is that acceptable for this board?

    Java substitutes a default font, so the board still works and shows the order number; it just looks a little different. Showing the right text matters more than the exact typeface.
