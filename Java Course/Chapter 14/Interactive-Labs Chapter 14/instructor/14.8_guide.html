The 5K sign-up form that ignores half of what runners do

Objectives

  • Implement more than one listener interface in a single class
  • Match each component to its listener-registering method (Table 14-3)
  • Write event handlers with the exact names Java calls (Table 14-4), including every method an interface declares

Requirements

  1. R1 RaceSignupFrame implements ActionListener, ItemListener and FocusListener.
  2. R2 The constructor registers the frame on each source with the matching method: addActionListener() on the name field, addItemListener() on the check box and addFocusListener() on the email field. The check box no longer reports to actionPerformed().
  3. R3 The handlers have the names Java calls: itemStateChanged(ItemEvent) updates the total; focusLost(FocusEvent) shows Check the email address. when the email has no @ (and clears the hint otherwise); focusGained(FocusEvent) clears the hint.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. In the starter, the runner ticks the T-shirt box. Which method runs, and what do the total and the message show afterwards?

    The box is registered with addActionListener(this), so actionPerformed() runs: the name is empty, so the message says "Please type your name." and the total stays $25. shirtChanged() never runs.

  2. Using Table 14-4, which method or methods must the class write to implement ItemListener, and which to implement FocusListener?

    ItemListener: itemStateChanged(ItemEvent). FocusListener: focusGained(FocusEvent) and focusLost(FocusEvent).

Solution

RaceSignupFrame.java
import javax.swing.*;
import java.awt.*;
import java.awt.event.*;

public class RaceSignupFrame extends JFrame
    implements ActionListener, ItemListener, FocusListener
{
    final int ENTRY_FEE = 25;
    final int SHIRT_FEE = 8;
    final int FRAME_WIDTH = 360;
    final int FRAME_HEIGHT = 220;
    JTextField nameField = new JTextField(14);
    JTextField emailField = new JTextField(18);
    JCheckBox shirtBox = new JCheckBox("Race T-shirt (+$8)", false);
    JLabel totalLabel = new JLabel("Total: $25");
    JLabel emailHint = new JLabel("");
    JLabel message = new JLabel("");

    public RaceSignupFrame()
    {
        super("Campus 5K sign-up");
        setSize(FRAME_WIDTH, FRAME_HEIGHT);
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        setLayout(new FlowLayout(FlowLayout.LEFT));
        add(new JLabel("Name:"));
        add(nameField);
        add(new JLabel("Email:"));
        add(emailField);
        add(emailHint);
        add(shirtBox);
        add(totalLabel);
        add(message);
        nameField.addActionListener(this);
        shirtBox.addItemListener(this);
        emailField.addFocusListener(this);
    }

    @Override
    public void actionPerformed(ActionEvent e)
    {
        String name = nameField.getText().trim();
        if (name.equals(""))
            message.setText("Please type your name.");
        else
            message.setText("Thanks, " + name + "! You're registered.");
    }

    @Override
    public void itemStateChanged(ItemEvent e)
    {
        int total = ENTRY_FEE;
        if (shirtBox.isSelected())
            total += SHIRT_FEE;
        totalLabel.setText("Total: $" + total);
    }

    @Override
    public void focusGained(FocusEvent e)
    {
        emailHint.setText("");
    }

    @Override
    public void focusLost(FocusEvent e)
    {
        if (emailField.getText().contains("@"))
            emailHint.setText("");
        else
            emailHint.setText("Check the email address.");
    }

    public static void main(String[] args)
    {
        RaceSignupFrame form = new RaceSignupFrame();
        form.setVisible(true);
    }
}

Walkthrough

A class can implement as many listener interfaces as it needs (p. 569); list them after implements, separated by commas. Table 14-3 (p. 570) pairs each component with its registering method: the name field fires ActionEvents (Enter), the check box ItemEvents (addItemListener()), and any Swing component focus events (addFocusListener()). A JCheckBox can also fire ActionEvents, which is why the starter's shirtBox.addActionListener(this) sent clicks to the name confirmation. Table 14-4 (p. 571) gives the handler names: you can't choose your own, because the source calls the method the interface declares. So shirtChanged becomes itemStateChanged(ItemEvent) and checkEmail becomes focusLost(FocusEvent). FocusListener declares two methods, so focusGained() must be written too; here it clears the warning while the runner fixes the address. @Override is optional but makes the compiler confirm each name.

TestRaceSignupFrame.java
import javax.swing.*;
import java.awt.event.*;
import java.util.*;

public class TestRaceSignupFrame
{
    public static void main(String[] args)
    {
        RaceSignupFrame form = new RaceSignupFrame();
        System.out.println("Form hears Enter in name field: "
            + Arrays.asList(form.nameField.getActionListeners()).contains(form));
        System.out.println("Form hears T-shirt box changes: "
            + Arrays.asList(form.shirtBox.getItemListeners()).contains(form));
        System.out.println("Form hears email field focus: "
            + Arrays.asList(form.emailField.getFocusListeners()).contains(form));

        form.shirtBox.doClick();                 // the runner ticks the box
        report("Tick T-shirt", form);
        form.shirtBox.doClick();                 // ...and changes their mind
        report("Untick T-shirt", form);

        form.emailField.setText("ana.example.com");
        focus(form.emailField, false);           // the runner tabs out of the field
        report("Leave email", form);
        focus(form.emailField, true);            // ...and clicks back in to fix it
        report("Back in email", form);
        form.emailField.setText("ana@example.com");
        focus(form.emailField, false);
        report("Leave email", form);

        form.nameField.setText("Ana");
        form.nameField.postActionEvent();        // the runner presses Enter
        report("Enter in name", form);
        System.exit(0);   // close the window
    }

    // Tells every focus listener on the field, as Swing does when focus moves.
    static void focus(JTextField field, boolean gained)
    {
        for (FocusListener listener : field.getFocusListeners())
        {
            if (gained)
                listener.focusGained(new FocusEvent(field, FocusEvent.FOCUS_GAINED));
            else
                listener.focusLost(new FocusEvent(field, FocusEvent.FOCUS_LOST));
        }
    }

    static void report(String action, RaceSignupFrame form)
    {
        System.out.println(action);
        System.out.println("  " + form.totalLabel.getText()
            + ", hint: \"" + form.emailHint.getText() + "\"");
        System.out.println("  message: \"" + form.message.getText() + "\"");
    }
}

Messages students see when a check fails

C1 · The class implements all three listener interfaces

List all three interfaces in the class header: implements ActionListener, ItemListener, FocusListener. A class can implement as many listeners as it needs.

C2 · Item and focus listeners are registered

Register the frame with shirtBox.addItemListener(this); and emailField.addFocusListener(this);. Table 14-3 pairs each component with the method that registers its kind of event.

C3 · The check box doesn't call actionPerformed()

Delete shirtBox.addActionListener(this);. A ticked box would still fire an ActionEvent and run the name confirmation.

C4 · itemStateChanged() handles the check box

Rename shirtChanged to itemStateChanged(ItemEvent e), the method ItemListener declares (Table 14-4). Java calls that name, never one you invent.

C5 · focusLost() and focusGained() are both written

Rename checkEmail to focusLost(FocusEvent e) and add focusGained(FocusEvent e) that clears emailHint. FocusListener declares both, so the class must write both.

Progressive hints

  1. List the interfaces after implements, separated by commas. The compiler then insists on every method each interface declares, which tells you what to write.

  2. Table 14-3 pairs each component with a registering method. The format is source.addXXXListener(this);.

  3. Rename shirtChanged and checkEmail instead of rewriting them: their bodies are already right. focusGained() needs only one line.

Reflection: questions and model answers

  1. Why can't you name an event handler whatever you like, the way you name your other methods?

    The source calls the method declared in the listener interface, such as itemStateChanged(); it knows nothing about shirtChanged(). Implementing the interface guarantees that method exists, so Swing can call it.

  2. The email check runs when the field loses focus, not on every key the runner types. Why is that kinder to the runner?

    While typing, the address is incomplete and would be flagged as wrong after every key. Checking when they leave the field judges the finished address.
