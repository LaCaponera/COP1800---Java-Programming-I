COP1800 · Java Programming I · Lab 14.5

Three desk windows, and a constructor that builds a stranger

Objectives

  • Create a child class of JFrame whose constructor sets the frame's title, size, position and close operation
  • Call the parent constructor with super() and use methods with an implied this
  • Use setBounds() and close operations so several frames of one class can share a screen

Requirements

  1. R1 The constructor passes the title Check-in: Desk n to the JFrame constructor with super(...) and configures this frame; it creates no other JFrame.
  2. R2 Each desk window is DESK_WIDTH × DESK_HEIGHT pixels and placed with setBounds() at x = (n − 1) × DESK_WIDTH, y = 0.
  3. R3 Closing Desk 1 ends the program; closing any other desk disposes of that window and keeps the program running.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. The starter's constructor runs, yet the test program prints an empty title for every desk. Which object receives the title, and which object does the test ask?

    The title goes to the new JFrame stored in the local variable frame. The test asks the DeskFrame object being constructed (this), which never got a title or size.

  2. Inside the constructor, what is the difference between setBounds(0, 0, DESK_WIDTH, DESK_HEIGHT); and this.setBounds(0, 0, DESK_WIDTH, DESK_HEIGHT);?

    None. Both call setBounds() on the current DeskFrame being constructed; this is just written out in the second.

Solution

DeskFrame.java
import javax.swing.*;

public class DeskFrame extends JFrame
{
    final int DESK_WIDTH = 300;
    final int DESK_HEIGHT = 200;
    private int deskNumber;

    // Builds the window for one check-in desk, for example "Check-in: Desk 2".
    public DeskFrame(int deskNumber)
    {
        super("Check-in: Desk " + deskNumber);
        this.deskNumber = deskNumber;
        setBounds((deskNumber - 1) * DESK_WIDTH, 0, DESK_WIDTH, DESK_HEIGHT);
        if (deskNumber == 1)
            setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        else
            setDefaultCloseOperation(WindowConstants.DISPOSE_ON_CLOSE);
    }

    public int getDeskNumber()
    {
        return deskNumber;
    }

    public static void main(String[] args)
    {
        for (int desk = 1; desk <= 3; ++desk)
        {
            DeskFrame window = new DeskFrame(desk);
            window.setVisible(true);
        }
    }
}

Walkthrough

The starter's constructor builds a second, separate JFrame and configures it, so the DeskFrame being constructed keeps an empty title and a 0 × 0 size; the stray frame is never shown. Because DeskFrame extends JFrame, the constructor can call super(title) as its first statement (p. 557) and then call the inherited methods with an implied this: setBounds(...) and this.setBounds(...) mean the same thing. setBounds() sets position and size in one call (Table 14-1), so the windows sit side by side instead of the second one covering the first (the note on p. 558). Section 14.5 also points out that every frame built by one constructor gets the same close operation; the if gives Desk 1 EXIT_ON_CLOSE and the other desks DISPOSE_ON_CLOSE (p. 558). setSize() plus setLocation() instead of setBounds() doesn't pass the check but behaves the same.

Test program

Students run it in an IDE and paste the output into the page.

TestDeskFrame.java
import javax.swing.*;

public class TestDeskFrame
{
    public static void main(String[] args)
    {
        for (int desk = 1; desk <= 3; ++desk)
        {
            DeskFrame window = new DeskFrame(desk);
            System.out.println(window.getTitle());
            System.out.println("  at (" + window.getX() + ", " + window.getY()
                + "), " + window.getWidth() + " x " + window.getHeight());
            int operation = window.getDefaultCloseOperation();
            System.out.println("  on close: " + closeName(operation));
        }
        System.exit(0);   // close any window the test opened
    }

    static String closeName(int operation)
    {
        if (operation == JFrame.EXIT_ON_CLOSE)
            return "EXIT_ON_CLOSE";
        if (operation == WindowConstants.DISPOSE_ON_CLOSE)
            return "DISPOSE_ON_CLOSE";
        if (operation == WindowConstants.DO_NOTHING_ON_CLOSE)
            return "DO_NOTHING_ON_CLOSE";
        return "HIDE_ON_CLOSE";
    }
}

Messages students see when a check fails

C1 · The constructor calls super() and builds no other frame

Start the constructor with super("Check-in: Desk " + deskNumber); and delete the local JFrame. A DeskFrame is already a frame; configure it, not a new one.

C2 · Each desk is placed and sized with setBounds()

Call setBounds((deskNumber - 1) * DESK_WIDTH, 0, DESK_WIDTH, DESK_HEIGHT);. The first two arguments position the window; the last two size it.

C3 · Desk 1 exits; the other desks dispose

Use an if on deskNumber: Desk 1 gets JFrame.EXIT_ON_CLOSE, every other desk gets WindowConstants.DISPOSE_ON_CLOSE, so closing one desk doesn't shut the others down.

Progressive hints

  1. A DeskFrame is a JFrame. Inside its constructor, call the frame methods with no object in front of them (or with this.).

  2. super(...) must be the very first statement in the constructor; it hands the title to the JFrame constructor.

  3. Desk 1 is at x = 0, Desk 2 at x = 300, Desk 3 at x = 600: the x position grows by one window width per desk.

Reflection: questions and model answers

  1. Why is a DeskFrame class better than repeating the title, size, position and close settings for each desk in main()?

    The setup is written once in the constructor, so every desk window automatically gets it; adding a fourth desk is one line, and a change (a new size) happens in one place instead of three.

  2. Your constructor doesn't call setVisible(true); main() does. What does that choice allow that a constructor that shows itself would not?

    Code can create and set up a DeskFrame without it popping up, for example to finish filling it first or, as the test program does, to check its settings without showing a window.
