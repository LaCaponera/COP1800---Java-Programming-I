COP1800 · Java Programming I · Lab 14.7

The loyalty card whose buttons do nothing

Objectives

  • Name the source and the listener of an event in an event-driven program
  • Register a frame as the listener for several components with addActionListener(this)
  • Use getSource() in actionPerformed() to respond differently to each source, and setEnabled() to switch buttons on and off

Requirements

  1. R1 The constructor registers the frame (this) as the action listener of stampButton, redeemButton and nameField.
  2. R2 actionPerformed() uses getSource(): Add stamp adds one stamp; Redeem sets the stamps back to 0 and shows Enjoy your free coffee! ; Enter in the name field shows Hello, + name + ! and changes no stamps. Every status ends with Stamps: n/5, and the fifth stamp shows Card full! first.
  3. R3 With setEnabled(): Redeem is off until the card has 5 stamps; at 5 stamps Add stamp is off and Redeem is on; after redeeming, Add stamp is on and Redeem is off.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. The starter already says implements ActionListener and has an actionPerformed() method. Why does clicking Add stamp do nothing?

    The frame was never registered as a listener, so the button has no one to notify. stampButton.addActionListener(this) is missing.

  2. In this program, which components are event sources, and which object is the listener?

    The sources are stampButton, redeemButton and nameField. The listener is the StampCardFrame itself (this), whose actionPerformed() handles their events.

Solution

StampCardFrame.java
import javax.swing.*;
import java.awt.*;
import java.awt.event.*;

public class StampCardFrame extends JFrame implements ActionListener
{
    final int STAMPS_FOR_FREE = 5;
    final int FRAME_WIDTH = 340;
    final int FRAME_HEIGHT = 150;
    JTextField nameField = new JTextField(12);
    JButton stampButton = new JButton("Add stamp");
    JButton redeemButton = new JButton("Redeem free coffee");
    JLabel status = new JLabel("Stamps: 0/5");
    int stamps = 0;

    public StampCardFrame()
    {
        super("Coffee card");
        setSize(FRAME_WIDTH, FRAME_HEIGHT);
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        setLayout(new FlowLayout());
        add(new JLabel("Customer:"));
        add(nameField);
        add(stampButton);
        add(redeemButton);
        add(status);
        stampButton.addActionListener(this);
        redeemButton.addActionListener(this);
        nameField.addActionListener(this);
        updateButtons();
    }

    @Override
    public void actionPerformed(ActionEvent e)
    {
        Object source = e.getSource();
        if (source == stampButton)
        {
            ++stamps;
            if (stamps == STAMPS_FOR_FREE)
                status.setText("Card full! " + count());
            else
                status.setText(count());
        }
        else if (source == redeemButton)
        {
            stamps = 0;
            status.setText("Enjoy your free coffee! " + count());
        }
        else
        {
            status.setText("Hello, " + nameField.getText() + "! " + count());
        }
        updateButtons();
    }

    // "Stamps: 3/5"
    private String count()
    {
        return "Stamps: " + stamps + "/" + STAMPS_FOR_FREE;
    }

    // Only one of the two buttons makes sense at a time.
    private void updateButtons()
    {
        stampButton.setEnabled(stamps < STAMPS_FOR_FREE);
        redeemButton.setEnabled(stamps == STAMPS_FOR_FREE);
    }

    public static void main(String[] args)
    {
        StampCardFrame card = new StampCardFrame();
        card.setVisible(true);
    }
}

Walkthrough

Implementing ActionListener only prepares the class (p. 564). Until a source registers it with addActionListener(this), the buttons have no listeners to notify, so nothing happens, just as in the section 14.6 frames. Registering both buttons and the text field makes the frame the listener for three sources (p. 566), and Enter in a JTextField fires an ActionEvent too. Because all three call the same actionPerformed(), the method compares e.getSource() with each component (Figure 14-28) to decide what to do. setEnabled(false) makes a button unusable (p. 567): a disabled button fires no event, so the sixth click is ignored without any extra test, and the barista sees which action is available. The helper updateButtons() passes boolean expressions to setEnabled(); writing setEnabled(true) and setEnabled(false) inside if statements works just as well.

Test program

TestStampCardFrame.java
public class TestStampCardFrame
{
    public static void main(String[] args)
    {
        StampCardFrame card = new StampCardFrame();
        show("Start", card);
        card.nameField.setText("Ana");
        card.nameField.postActionEvent();      // the barista presses Enter
        show("Enter in name", card);
        for (int click = 1; click <= 6; ++click)
        {
            card.stampButton.doClick();        // the barista clicks Add stamp
            show("Add stamp", card);
        }
        card.redeemButton.doClick();
        show("Redeem", card);
        card.stampButton.doClick();
        show("Add stamp", card);
        System.exit(0);   // close the window
    }

    static void show(String action, StampCardFrame card)
    {
        String stamp = card.stampButton.isEnabled() ? "on" : "off";
        String redeem = card.redeemButton.isEnabled() ? "on" : "off";
        System.out.println(action + ": " + card.status.getText());
        System.out.println("  Add stamp " + stamp + ", Redeem " + redeem);
    }
}

Messages students see when a check fails

C1 · The frame listens to both buttons and the name field

In the constructor, register the frame with each source: stampButton.addActionListener(this);, redeemButton.addActionListener(this); and nameField.addActionListener(this);.

C2 · actionPerformed() asks which component fired

Start actionPerformed() with Object source = e.getSource();. All three sources call this one method, so it has to find out which one fired.

C3 · The source is compared with the components

Compare the source with each component, for example if (source == stampButton), and handle the redeem button and the name field in their own branches.

C4 · The buttons are switched on and off

Use setEnabled() on both buttons: redeemButton off until the card is full, stampButton off at five stamps, and the reverse after redeeming.

Progressive hints

  1. Section 14.7 lists three jobs: prepare the class (done), register it as a listener on each source, and write the response in actionPerformed().

  2. e.getSource() returns the component that fired the event. Compare it with == to each button; whatever is left is the name field.

  3. A disabled button ignores clicks, so the sixth click needs no special code once Add stamp is turned off at five stamps. Set the buttons once in the constructor and again after every event.

Reflection: questions and model answers

  1. The test clicks Add stamp six times, but the card stops at 5/5. Which part of your code stopped the sixth stamp, and why is that better for the barista than only checking the count inside actionPerformed()?

    Disabling stampButton at five stamps: a disabled button fires no event, so actionPerformed() never runs. The barista also sees the greyed-out button and knows the next step is Redeem.

  2. Pressing Enter in the name field and clicking a button run the same actionPerformed(). What would happen without the getSource() test?

    Every event would be treated the same, so greeting a customer with Enter would add a stamp (and redeeming might add one too), giving free stamps.
