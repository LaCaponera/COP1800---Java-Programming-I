COP1800 · Java Programming I · Lab 14.2

The bus-times window nobody can read

Objectives

  • Construct a JFrame with a title and set its size with named constants
  • Use setResizable() and setVisible() deliberately
  • Choose between EXIT_ON_CLOSE and DISPOSE_ON_CLOSE for each window of a program

Requirements

  1. R1 createMainWindow(stopName) returns a JFrame titled Next buses: followed by the stop name, sized with the named constants MAIN_WIDTH (480) and MAIN_HEIGHT (300).
  2. R2 The main window can't be resized, and closing it ends the program.
  3. R3 createAlertsWindow() returns a resizable JFrame titled Service alerts, sized with named constants (360 × 200); closing it disposes of that window and keeps the program running.
  4. R4 Neither method makes its window visible; the caller decides when to show it.
  5. R5 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. The starter's main window calls setVisible(true) but never setSize(). According to section 14.2, what does a commuter see, and why?

    Only the title bar, because a JFrame's size is 0 x 0 by default.

  2. The alerts window keeps the default close operation. What does that default do when a commuter clicks Close, and which of the four values fits the alerts window better?

    HIDE_ON_CLOSE hides the window and keeps the program running, but the frame object stays around. DISPOSE_ON_CLOSE closes and disposes of it while the program keeps running.

Solution

KioskWindows.java
import javax.swing.*;

public class KioskWindows
{
    static final int MAIN_WIDTH = 480;
    static final int MAIN_HEIGHT = 300;
    static final int ALERTS_WIDTH = 360;
    static final int ALERTS_HEIGHT = 200;

    public static JFrame createMainWindow(String stopName)
    {
        JFrame frame = new JFrame("Next buses: " + stopName);
        frame.setSize(MAIN_WIDTH, MAIN_HEIGHT);
        frame.setResizable(false);
        frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        return frame;
    }

    public static JFrame createAlertsWindow()
    {
        JFrame frame = new JFrame("Service alerts");
        frame.setSize(ALERTS_WIDTH, ALERTS_HEIGHT);
        frame.setDefaultCloseOperation(WindowConstants.DISPOSE_ON_CLOSE);
        return frame;
    }

    // The kiosk program: build both windows, load the bus data, then show them.
    public static void main(String[] args)
    {
        JFrame times = createMainWindow("Library Stop");
        JFrame alerts = createAlertsWindow();
        // ... the bus data is loaded here ...
        alerts.setLocation(500, 0);
        times.setVisible(true);
        alerts.setVisible(true);
    }
}

Walkthrough

The JFrame(String title) constructor sets the title (p. 547); setTitle() also works. A frame is 0 × 0 by default, which is why the starter showed only a title bar (p. 548); setSize() with named constants fixes that and documents the numbers. setResizable(false) stops commuters from shrinking the times (Table 14-1). The default close operation, HIDE_ON_CLOSE, hides the frame and keeps the program running (p. 549): wrong for the main window, which needs JFrame.EXIT_ON_CLOSE, and not quite right for the alerts window, which needs WindowConstants.DISPOSE_ON_CLOSE so the frame is released while the program (and the bus times) keep running. Neither method calls setVisible(true): section 14.2 points out that a frame can be built in the background and shown when appropriate, and here main() shows both once the data is loaded. JFrame.DISPOSE_ON_CLOSE is the same constant and also passes.

Test program

Students run it in an IDE and paste the output into the page.

TestKioskWindows.java
import javax.swing.*;

public class TestKioskWindows
{
    public static void main(String[] args)
    {
        report("Main window", KioskWindows.createMainWindow("Library Stop"));
        report("Alerts window", KioskWindows.createAlertsWindow());
        System.exit(0);   // close any window the test opened
    }

    static void report(String name, JFrame frame)
    {
        System.out.println(name);
        System.out.println("  title: " + frame.getTitle());
        System.out.println("  size: " + frame.getWidth() + " x " + frame.getHeight());
        System.out.println("  resizable: " + frame.isResizable());
        System.out.println("  visible: " + frame.isVisible());
        int operation = frame.getDefaultCloseOperation();
        System.out.println("  on close: " + closeName(operation));
    }

    static String closeName(int operation)
    {
        if (operation == JFrame.EXIT_ON_CLOSE)
            return "EXIT_ON_CLOSE";
        if (operation == WindowConstants.DISPOSE_ON_CLOSE)
            return "DISPOSE_ON_CLOSE";
        if (operation == WindowConstants.DO_NOTHING_ON_CLOSE)
            return "DO_NOTHING_ON_CLOSE";
        return "HIDE_ON_CLOSE";
    }
}

Messages students see when a check fails

C1 · The main window's title includes the stop name

Pass the title to the constructor: new JFrame("Next buses: " + stopName) (or call setTitle() with that text). A frame built with new JFrame() has no title.

C2 · The main window is sized with named constants

Declare static final int MAIN_WIDTH = 480; and MAIN_HEIGHT = 300; in the class, then call frame.setSize(MAIN_WIDTH, MAIN_HEIGHT);. Without a size a frame is 0 × 0.

C3 · Main window: fixed size, Close ends the program

Call frame.setResizable(false); and frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);. The default only hides the frame, so the program would keep running.

C4 · Alerts window: Close disposes of it only

Use frame.setDefaultCloseOperation(WindowConstants.DISPOSE_ON_CLOSE);. Closing alerts must not end the program, or the bus times would disappear with it.

C5 · The alerts size uses named constants

Replace 360 and 200 with named constants such as ALERTS_WIDTH and ALERTS_HEIGHT, declared next to the main window's constants.

C6 · createMainWindow() doesn't show the window

Remove setVisible(true) from createMainWindow(). The method builds the window; main() shows it once the bus data is loaded.

C7 · createAlertsWindow() doesn't show the window

Remove setVisible(true) from createAlertsWindow(); main() already shows the window at the right moment.

Progressive hints

  1. Table 14-1 lists a method for each tester complaint: size, resizing and visibility. The close behaviour comes from the list of four constants on p. 549.

  2. The main window and the alerts window need different close operations: one ends the program, the other disposes of only itself.

  3. A frame you never call setVisible(true) on still exists: you can set its title, size and close operation, and the test program can read them back.

Reflection: questions and model answers

  1. Why might the kiosk program want its windows built invisible and shown later, instead of appearing the moment they are created?

    The program can load the bus data and fill in the window first, so commuters never see an empty or half-built window; it shows the frame only when it is ready.

  2. A classmate sets both windows to EXIT_ON_CLOSE. Describe exactly what a commuter sees after closing the alerts window.

    The whole program ends, so the bus-times window disappears too and the kiosk screen is left empty until someone restarts the program.

Extension

At the start of main(), call the static method setDefaultLookAndFeelDecorated(true) on JFrame, then run it: the title bars switch to Java's Metal look (Figure 14-5). Then replace alerts.setLocation(500, 0) with a setBounds() call that places the alerts window to the right of the main window at the same height.
