COP1800 · Java Programming I · Lab 14.9

The burrito builder that lets you pick three proteins

Objectives

  • Build a JComboBox<String> from an array and look up a price with getSelectedIndex() and a parallel array
  • Group JCheckBoxes in a ButtonGroup so only one can be selected, and leave independent options ungrouped
  • Respond to ItemEvents by recalculating from the components' current state with isSelected()

Requirements

  1. R1 sizeBox is a JComboBox<String> filled from SIZES, starts on Regular, and has the frame registered as its item listener. The size price comes from SIZE_PRICES[sizeBox.getSelectedIndex()].
  2. R2 chicken, beans and steak belong to one ButtonGroup; guac and cheese are not in it.
  3. R3 itemStateChanged() recalculates the total from scratch: the size price, plus STEAK_EXTRA if steak is selected, plus each extra whose box isSelected(). No -= on a running total.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. In the starter, a customer clicks Beans and then Steak (Chicken starts ticked). How many proteins does the burrito have, and which sentence of section 14.9 explains why?

    Three: chicken, beans and steak are all ticked. Check boxes are independent unless they are added to a ButtonGroup, which lets the user select only one at a time.

  2. The starter adds or subtracts a price on every ItemEvent. When Steak replaces Chicken inside a ButtonGroup, how many ItemEvents do you expect, and for which boxes?

    Two: one for Chicken (deselected) and one for Steak (selected), because each box whose state changes generates its own ItemEvent.

Solution

BurritoFrame.java
import javax.swing.*;
import java.awt.*;
import java.awt.event.*;

public class BurritoFrame extends JFrame implements ItemListener
{
    final int FRAME_WIDTH = 380;
    final int FRAME_HEIGHT = 200;
    final String[] SIZES = {"Small", "Regular", "Large"};
    final int[] SIZE_PRICES = {7, 9, 11};
    final int STEAK_EXTRA = 2;
    final int GUAC_PRICE = 2;
    final int CHEESE_PRICE = 1;

    JComboBox<String> sizeBox = new JComboBox<String>(SIZES);
    JCheckBox chicken = new JCheckBox("Chicken", true);
    JCheckBox beans = new JCheckBox("Beans", false);
    JCheckBox steak = new JCheckBox("Steak +$2", false);
    JCheckBox guac = new JCheckBox("Guacamole +$2", false);
    JCheckBox cheese = new JCheckBox("Extra cheese +$1", false);
    ButtonGroup proteins = new ButtonGroup();
    JLabel totalLabel = new JLabel("");

    public BurritoFrame()
    {
        super("Burrito builder");
        setSize(FRAME_WIDTH, FRAME_HEIGHT);
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        setLayout(new FlowLayout());
        sizeBox.setSelectedIndex(1);
        proteins.add(chicken);
        proteins.add(beans);
        proteins.add(steak);
        add(new JLabel("Size:"));
        add(sizeBox);
        add(chicken);
        add(beans);
        add(steak);
        add(guac);
        add(cheese);
        add(totalLabel);
        sizeBox.addItemListener(this);
        chicken.addItemListener(this);
        beans.addItemListener(this);
        steak.addItemListener(this);
        guac.addItemListener(this);
        cheese.addItemListener(this);
        updateTotal();
    }

    @Override
    public void itemStateChanged(ItemEvent e)
    {
        updateTotal();
    }

    // Prices the order from what is selected right now.
    private void updateTotal()
    {
        int total = SIZE_PRICES[sizeBox.getSelectedIndex()];
        if (steak.isSelected())
            total += STEAK_EXTRA;
        if (guac.isSelected())
            total += GUAC_PRICE;
        if (cheese.isSelected())
            total += CHEESE_PRICE;
        totalLabel.setText("Total: $" + total);
    }

    public static void main(String[] args)
    {
        BurritoFrame order = new BurritoFrame();
        order.setVisible(true);
    }
}

Walkthrough

new JComboBox<String>(SIZES) fills the list from the array (p. 576), and setSelectedIndex(1) starts it on Regular (Table 14-6); calling addItem() for each size also passes. Because SIZE_PRICES is a parallel array, SIZE_PRICES[sizeBox.getSelectedIndex()] is the size price (p. 576). Creating a ButtonGroup groups nothing until each box is added to it (Don't Do It, p. 580); once chicken, beans and steak are in the group, selecting one deselects the others, and the selected one can't be unticked, which is why the second click on Beans changes nothing (p. 575). Guacamole and cheese stay outside the group so both can be chosen. When steak replaces chicken, two ItemEvents fire (chicken deselected, steak selected), and a size change fires two as well; adding and subtracting on each event, like the book's resort calculator, gets fragile as these multiply. Recomputing from getSelectedIndex() and isSelected() gives the right total after any sequence of events. updateTotal() is also called once in the constructor so the label starts correct.

Test program

TestBurritoFrame.java
import javax.swing.*;

public class TestBurritoFrame
{
    public static void main(String[] args)
    {
        BurritoFrame order = new BurritoFrame();
        show("Start", order);
        order.steak.doClick();                 // the customer taps Steak
        show("Click Steak", order);
        order.beans.doClick();
        show("Click Beans", order);
        order.beans.doClick();
        show("Click Beans again", order);
        order.guac.doClick();
        show("Click Guacamole", order);
        order.cheese.doClick();
        show("Click Extra cheese", order);
        order.sizeBox.setSelectedItem("Large"); // picks Large from the list
        show("Choose Large", order);
        order.guac.doClick();
        show("Click Guacamole again", order);
        order.sizeBox.setSelectedItem("Small");
        show("Choose Small", order);
        System.exit(0);   // close the window
    }

    static void show(String action, BurritoFrame order)
    {
        JCheckBox[] proteins = {order.chicken, order.beans, order.steak};
        JCheckBox[] extras = {order.guac, order.cheese};
        System.out.println(action + " -> " + order.totalLabel.getText());
        System.out.println("  size: " + order.sizeBox.getSelectedItem()
            + "   protein: " + selected(proteins));
        System.out.println("  extras: " + selected(extras));
    }

    static String selected(JCheckBox[] boxes)
    {
        String names = "";
        for (JCheckBox box : boxes)
        {
            if (box.isSelected())
            {
                if (!names.equals(""))
                    names += ", ";
                names += box.getText();
            }
        }
        if (names.equals(""))
            return "none";
        return names;
    }
}

Messages students see when a check fails

C1 · The size list is filled from SIZES

Build the list from the array: JComboBox<String> sizeBox = new JComboBox<String>(SIZES); (or call addItem() for each size). An empty combo box has nothing to choose.

C2 · The size list starts on Regular and is listened to

In the constructor, call sizeBox.setSelectedIndex(1); (Regular) and sizeBox.addItemListener(this);, so choosing a size updates the total.

C3 · The three proteins share one ButtonGroup

Create ButtonGroup proteins = new ButtonGroup(); and add each protein to it: proteins.add(chicken);, proteins.add(beans);, proteins.add(steak);. Creating the group alone groups nothing.

C4 · Extras stay independent

Keep guac and cheese out of the ButtonGroup: a customer can want both. Add them only to the frame with add(guac); and add(cheese);.

C5 · The size price comes from the parallel array

Look up the size price with SIZE_PRICES[sizeBox.getSelectedIndex()]. The list position of the selected size is also the position of its price.

C6 · The total is recalculated from what is selected

Start from the size price and add STEAK_EXTRA, GUAC_PRICE and CHEESE_PRICE for each box whose isSelected() is true. Subtracting on deselection is what lets the total drift.

Progressive hints

  1. JComboBox<String> has a constructor that takes an array. The first item is at index 0, so Regular is index 1.

  2. Creating a ButtonGroup groups nothing until you call its add() with each protein box (see the Don't Do It list).

  3. Write the total as a fresh sum every time: the size price from the parallel array, plus every option whose box is selected right now.

Reflection: questions and model answers

  1. The book's resort calculator adds and subtracts on each event. Why is recalculating from getSelectedIndex() and isSelected() more reliable for this form? Describe one situation where the running total would go wrong.

    The recalculated total always matches what's on screen, whatever events fired and in whatever order. A running total breaks when events come in pairs (steak replacing chicken, a size change fires a deselect and a select) or when one is missed, for example a box set before the listener was registered.

  2. The test clicks Beans twice, yet Beans stays selected. Why? If the truck added a "no protein" option, how would you offer it?

    In a ButtonGroup, once one box is selected, one always stays selected; clicking it again can't clear it. Add a fourth box, No protein, to the group (the book's trick is an invisible box, but a visible option is clearer for customers).
