COP1800 · Java Programming I · Lab 7.1

The bridge door that locks out its own officer

Objectives

  • Explain why == on two String variables compares memory addresses, not the characters
  • Predict when == seems to work on Strings (two identical literals) and when it fails (text read from input)
  • Replace a reference comparison with equals() and keep == where it is right: on a primitive char
  • Name the three Java classes for text data: Character, String and StringBuilder

Requirements

  1. R1 canEnterBridge() compares the badge's contents with DUTY_OFFICER using equals(), and keeps == for the deck, which is a primitive char.
  2. R2 isRepeatScan() returns true when badge and lastBadge contain the same characters, using equals().
  3. R3 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. In the starter, badge and DUTY_OFFICER are both String variables. What does each variable actually hold, so what does badge == DUTY_OFFICER compare?

    Each holds a reference, the memory address where its characters are stored. So == compares the two addresses, not the characters.

  2. deck == BRIDGE_DECK also uses ==. Why is that comparison correct?

    char is a primitive type, so the variable holds the character value itself, not an address. == compares the two values.

Solution

CrewGate.java
import java.util.Scanner;

public class CrewGate
{
    public static final String DUTY_OFFICER = "MARA-07";
    public static final char BRIDGE_DECK = 'B';

    // True only for the duty officer's badge scanned at the bridge deck.
    public static boolean canEnterBridge(String badge, char deck)
    {
        return DUTY_OFFICER.equals(badge) && deck == BRIDGE_DECK;
    }

    // True when the same badge is scanned twice in a row.
    public static boolean isRepeatScan(String badge, String lastBadge)
    {
        return badge.equals(lastBadge);
    }

    public static void main(String[] args)
    {
        Scanner keyboard = new Scanner(System.in);
        System.out.print("Badge >> ");
        String badge = keyboard.nextLine();
        if(canEnterBridge(badge, BRIDGE_DECK))
            System.out.println("Bridge door opens for " + badge);
        else
            System.out.println("Bridge door stays locked for " + badge);
    }
}

Walkthrough

This is the book's TryToCompareStrings problem (Figure 7-1). A String variable holds a reference: the address where the characters are stored. nextLine() builds a new String object for every line it reads, so a scanned MARA-07 sits at a different address from the literal "MARA-07" and == is false. The shipyard tests passed for the misleading reason the book describes: identical literals in a program are stored once, so two literals share one address. equals() compares the characters, however the text was created. The deck is a char, a primitive type, so the variable holds the value itself and == compares values: that comparison was always right (and a char has no methods to call). Writing DUTY_OFFICER.equals(badge) (constant first) also gives false instead of a crash if badge is ever null; badge.equals(DUTY_OFFICER) passes the checks too.

Test program

TestCrewGate.java
import java.util.Scanner;

public class TestCrewGate
{
    public static void main(String[] args)
    {
        // A badge written in the code as a literal
        System.out.println("Literal MARA-07 at deck B: "
            + CrewGate.canEnterBridge("MARA-07", 'B'));

        // Badges "scanned" at the gate: every nextLine() builds a new String
        Scanner scanner = new Scanner("MARA-07\nMARA-07\nTOMAS-12\nMARA-07\n");
        String lastBadge = "";
        String badge;

        badge = scanner.nextLine();
        scan(badge, 'B', lastBadge);
        lastBadge = badge;

        badge = scanner.nextLine();
        scan(badge, 'B', lastBadge);
        lastBadge = badge;

        badge = scanner.nextLine();
        scan(badge, 'B', lastBadge);
        lastBadge = badge;

        badge = scanner.nextLine();
        scan(badge, 'C', lastBadge);
    }

    private static void scan(String badge, char deck, String lastBadge)
    {
        System.out.print(badge + " at deck " + deck + ": ");
        if(CrewGate.isRepeatScan(badge, lastBadge))
            System.out.print("repeat scan, ");
        if(CrewGate.canEnterBridge(badge, deck))
            System.out.println("bridge door opens");
        else
            System.out.println("bridge door stays locked");
    }
}

Messages students see when a check fails

C1 · The badge is compared with equals(); the deck keeps ==

Compare the badge with DUTY_OFFICER.equals(badge) (or badge.equals(DUTY_OFFICER)): a String variable holds an address, and a scanned badge is a new object at a new address. Keep deck == BRIDGE_DECK: a char is a primitive, so == already compares the values.

Hint:

Only one of the two == in the return statement has a reference on each side.

C2 · Repeat scans compare contents with equals()

Return badge.equals(lastBadge). Each scan is read by a separate nextLine() call, so the two badges are always two objects; only their characters can match.

Progressive hints

  1. Ask of each variable in the comparisons: is its type a class (String) or a primitive (char)? Only a primitive variable holds its value directly.

  2. The String class gives every String object a method that compares the characters and returns a boolean. You can call it on the constant or on the scanned badge.

  3. In the test program the literal "MARA-07" passes even with ==, because both literals are the same stored object. The scanned lines are new objects, which is why they fail.

Reflection: questions and model answers

  1. With the starter, the literal "MARA-07" opened the door but the scanned MARA-07 did not. Explain the difference in terms of memory addresses.

    Identical literals are stored once, so both literals refer to the same address and == is true. nextLine() builds a new String object at a new address, so == compares two different addresses and is false even though the characters match.

  2. Why is a bug like this dangerous to test only with literals typed into your code?

    Literal tests pass by accident because identical literals share an address. The bug only appears with text that is created at run time, such as user input, so the program looks correct until real users use it.

  3. Which of the three text classes in this chapter (Character, String, StringBuilder) would you choose for a badge code that never changes after it is scanned, and why?

    String: the badge is fixed text that is compared but never modified. Character holds a single character, and StringBuilder is for text that will be changed repeatedly.
