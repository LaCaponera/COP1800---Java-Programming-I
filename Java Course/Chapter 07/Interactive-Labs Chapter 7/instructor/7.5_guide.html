The departure board that rebuilds itself every hour

Objectives

  • Explain why building text with + in a loop creates a new String on every pass
  • Build text in a loop with a StringBuilder created with new and an initial capacity
  • Change a StringBuilder with append(), insert() and setLength(), then turn it into a String with toString()
  • Explain why equals() on two StringBuilder objects compares references, and compare their contents instead

Requirements

  1. R1 sailingTimes() builds the list in a StringBuilder created with new and an initial capacity of count * 8, adds each entry with append() inside the loop, and returns toString(). No String concatenation onto the list.
  2. R2 The list has | between times, not after the last one (for example, cut it off afterwards with setLength()), and count 0 gives an empty String.
  3. R3 markDelayed() copies the sailing into a StringBuilder, uses insert() to add DELAYED at position 6, and returns the result as a String.
  4. R4 sameText() compares the two boards' contents by converting each with toString() and comparing with equals().
  5. R5 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. With the starter, sailingTimes(6, 3, 2) runs the loop 3 times. How many different String objects does list refer to during the call, counting the empty one it starts with?

    Four: the empty String, then a new String after each of the 3 passes. Strings are immutable, so each + creates a new object and the old ones are left for the garbage collector.

  2. new StringBuilder("Gull Star") contains 9 characters. What is its capacity, and why is it bigger than the length?

    25: the length of the String plus 16. The extra 16 positions leave room to modify the builder without allocating new memory.

Solution

DockBoard.java
public class DockBoard
{
    // 6 becomes "06"; 14 stays "14".
    public static String twoDigits(int hour)
    {
        if(hour < 10)
            return "0" + hour;
        return "" + hour;
    }

    // sailingTimes(6, 3, 2) returns "06:00 | 08:00 | 10:00".
    public static String sailingTimes(int firstHour, int count, int gap)
    {
        StringBuilder list = new StringBuilder(count * 8);
        int hour = firstHour;
        for(int i = 0; i < count; ++i)
        {
            list.append(twoDigits(hour));
            list.append(":00 | ");
            hour = hour + gap;
        }
        if(count > 0)
            list.setLength(list.length() - 3);
        return list.toString();
    }

    // markDelayed("08:00 Gull Star") returns "08:00 DELAYED Gull Star".
    public static String markDelayed(String sailing)
    {
        StringBuilder line = new StringBuilder(sailing);
        line.insert(6, "DELAYED ");
        return line.toString();
    }

    // True when the two boards show the same text.
    public static boolean sameText(StringBuilder a, StringBuilder b)
    {
        return a.toString().equals(b.toString());
    }
}

Walkthrough

A String is immutable, so list = list + ... creates a new String on every pass and copies everything built so far into it. A StringBuilder is changed in place: append() adds to the end of its buffer. Unlike a String, it must be created with new and a constructor. new StringBuilder(count * 8) sets the initial capacity (the size of the buffer) to fit the whole list, so the buffer never has to be reallocated as it grows; this is the effect Figure 7-14 measures. Appending | after every time and then cutting the last 3 characters with setLength(list.length() - 3) keeps the loop simple; the count > 0 test matters because setLength(-3) throws an exception. Appending the separator before every time except the first (if(i > 0)) is equally correct. insert(6, "DELAYED ") adds text at position 6, right after 08:00 . StringBuilder does not compare contents in equals(): it compares references, exactly like ==, so two boards with identical text are "different". The book's fix, a.toString().equals(b.toString()), compares the characters. Here StringBuilder is the right tool for the loop, while a String is fine for twoDigits(), which builds its text once.

Messages students see when a check fails

C1 · A StringBuilder with an initial capacity is appended to in the loop

Declare StringBuilder list = new StringBuilder(count * 8);, call list.append(...) inside the loop instead of list = list + ..., and return list.toString();. The capacity makes room for every 8-character entry up front.

Hint:

append() changes the builder itself, so its result doesn't need to be assigned to anything.

C2 · No separator after the last time

Remove the stray | : either cut the last 3 characters after the loop with list.setLength(list.length() - 3) (only when count > 0), or append the separator only between times with an if inside the loop.

C3 · markDelayed() inserts into a StringBuilder

Copy the sailing with new StringBuilder(sailing), call insert(6, "DELAYED ") on it, and return its toString(). Position 6 is right after the time and its space.

C4 · Boards are compared by their contents

Return a.toString().equals(b.toString()). StringBuilder's own equals() compares references, like ==, so it is false for two separate boards even when their text is identical.

Reflection: questions and model answers

  1. The starter's sameText(north, south) printed false although both boards show 06:00 | 08:00. Explain why, and how your version fixes it.

    StringBuilder's equals() compares references, and north and south are two separate objects at different addresses. My version converts both to Strings with toString() and uses String's equals(), which compares the characters.

  2. Why does the solution create the builder with new StringBuilder(count * 8) instead of new StringBuilder()?

    Each entry is 8 characters, so count * 8 fits the whole list. The buffer then never has to be enlarged and copied while the loop appends, which saves time for long lists.

  3. twoDigits() still builds its result with +. Is that a problem? When should you choose a StringBuilder over a String?

    No: it builds one short String once. Use StringBuilder when text is changed repeatedly, such as appending in a loop; for text built once or compared often, use String.
