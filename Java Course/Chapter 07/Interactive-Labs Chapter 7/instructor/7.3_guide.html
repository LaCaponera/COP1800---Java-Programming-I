COP1800 · Java Programming I · Lab 7.3

The marina list that files zephyr after Zodiac

Objectives

  • Choose between equals() and equalsIgnoreCase() for a comparison typed by people
  • Use the sign of compareTo() to decide which of two Strings comes first
  • Explain why compareTo() puts every capital before every lowercase letter
  • Tell an empty String from a null String, and test for null with == before calling any method

Requirements

  1. R1 sameBoat() treats names as the same boat whatever their capitals, using equalsIgnoreCase().
  2. R2 firstInList() uses compareTo() and returns the name that comes first; when the names are identical it returns a.
  3. R3 nicknameLabel() returns (not recorded) for a null nickname, (none) for an empty one and the nickname in double quotes otherwise. Test for null with == before calling any method on the nickname.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. With the starter, what happens when the test program calls nicknameLabel(null)? Why?

    The program crashes with a NullPointerException: nickname refers to no object, so there is nothing to call equals() on.

  2. "Roger".compareTo("Rodrigo") returns 3. Which characters were compared to get that number, and what does the positive sign mean?

    R and o match, then g is compared with d; g is 3 after d in Unicode, so it returns 3. Positive means Roger comes after Rodrigo.

Solution

MarinaRegistry.java
public class MarinaRegistry
{
    // True when the typed name is the registered boat, whatever the capitals.
    public static boolean sameBoat(String registered, String typed)
    {
        return registered.equalsIgnoreCase(typed);
    }

    // The name that comes first in the slip list; a if they are identical.
    public static String firstInList(String a, String b)
    {
        if(a.compareTo(b) <= 0)
            return a;
        else
            return b;
    }

    // How the nickname column shows a nickname.
    public static String nicknameLabel(String nickname)
    {
        if(nickname == null)
            return "(not recorded)";
        if(nickname.equals(""))
            return "(none)";
        return "\"" + nickname + "\"";
    }
}

Walkthrough

equalsIgnoreCase() is the book's choice for text people type, because you can't predict when they use Shift or Caps Lock; a trailing space still makes two names different. compareTo() returns 0 for identical Strings, a negative number when the calling String comes first and a positive number when it comes later. Only the sign matters, so a.compareTo(b) <= 0 returns a for a tie as required. The comparison uses Unicode values: every capital (65 to 90) is less than every lowercase letter (97 to 122), so Zodiac comes before zephyr, and a space (32) comes before any letter, so Sea Otter comes before Seahorse. An empty String refers to an object with no characters, so you can call its methods; a null String refers to nothing, so nickname.equals("") crashes with a NullPointerException. Testing nickname == null first is the one place where == is the right test for a String: it asks whether the variable holds an address at all. "".equals(nickname) would also avoid the crash, but it would show (none) for null instead of (not recorded), losing a distinction the registry needs.

Messages students see when a check fails

C1 · Names are matched with equalsIgnoreCase()

Return registered.equalsIgnoreCase(typed). equals() is true only when every character matches exactly, so SEA OTTER and Sea Otter count as different boats.

C2 · firstInList() decides with the sign of compareTo()

Compare with a.compareTo(b) and test only its sign: <= 0 means a comes first or the names are identical, so return a; otherwise return b. Don't test for a specific value such as == -1: compareTo() returns the difference between the first two characters that differ, which can be any number.

Hint:

The registry orders by Unicode values, as compareTo() does, so don't switch to a case-insensitive comparison here.

C3 · Null is tested with == before any method call

Start with if(nickname == null) return "(not recorded)";. A null String holds no address, so calling nickname.equals("") on it crashes; == is the right test here because it asks whether the variable refers to an object at all.

Hint:

nickname.equals(null) can never help: if nickname is null, the call itself crashes before equals() runs.

Progressive hints

  1. The String class has a version of equals() that ignores case. Its name says so.

  2. compareTo() returns an int. You only care whether it is negative, zero or positive, so compare it with 0.

  3. For R3, order matters: the first test must not call a method on nickname, because if it is null there is no object to call it on.

Reflection: questions and model answers

  1. Your registry files Zodiac before zephyr. Explain why, using Unicode values.

    compareTo() compares the first characters, Z and z. Capital Z is 90 and lowercase z is 122, so Z is smaller and Zodiac comes first. Every capital comes before every lowercase letter.

  2. Lesson 7.1 said never to compare Strings with ==, yet R3 requires nickname == null. Why is == correct here?

    == compares references. Here we want to know whether the variable refers to any object at all, which is a question about the reference, not about the characters. A method such as equals() can't be called on null.

  3. Why does sameBoat("Sea Otter", "sea otter ") still return false with equalsIgnoreCase()?

    equalsIgnoreCase() ignores only differences in case. The typed name has an extra space at the end, so the two Strings have different characters (and lengths).
