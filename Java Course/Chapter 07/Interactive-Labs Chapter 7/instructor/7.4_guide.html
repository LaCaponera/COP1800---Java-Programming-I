The ticket counter that forgets every fix

Objectives

  • Explain why calling toUpperCase() or replace() without using the result changes nothing: Strings are immutable
  • Split a full name at the space with indexOf() and substring(), and handle the -1 that means not found
  • Capitalize a word with charAt(), Character.toUpperCase() and substring()
  • Clean text with startsWith() and substring() before converting it with Double.parseDouble()

Requirements

  1. R1 normalizeCode() returns the code in capitals with each space replaced by a hyphen, using the values returned by toUpperCase() and replace().
  2. R2 cardName() finds the first space with indexOf(' '), splits the name with substring(), and returns the family name in capitals, , , and the first name with its first letter capitalized (Character.toUpperCase() on charAt(0)) and the rest in lowercase.
  3. R3 When the name has no space (indexOf() returns -1), cardName() returns the whole name in capitals.
  4. R4 fareAmount() removes a leading $ (test it with startsWith(), remove it with substring()) and converts the rest with Double.parseDouble().
  5. R5 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. The starter calls code.toUpperCase(); on its own line. What does that call do, and why does code still hold gi 2130 afterwards?

    It creates a new String, GI 2130, and returns its address, but nothing stores that address. Strings are immutable, so code still refers to the original gi 2130.

  2. For String name = "ana lopez";, what are name.indexOf(' '), name.charAt(0) and name.substring(4)?

    indexOf(' ') is 3, charAt(0) is 'a', and substring(4) is "lopez" (from position 4 to the end).

Solution

FerryTicket.java
public class FerryTicket
{
    // "gi 2130" typed at the counter becomes "GI-2130".
    public static String normalizeCode(String code)
    {
        code = code.toUpperCase();
        code = code.replace(' ', '-');
        return code;
    }

    // "ana lopez" becomes "LOPEZ, Ana"; a single name, "cher", becomes "CHER".
    public static String cardName(String fullName)
    {
        int space = fullName.indexOf(' ');
        if(space == -1)
            return fullName.toUpperCase();

        String firstName = fullName.substring(0, space);
        String familyName = fullName.substring(space + 1);
        return familyName.toUpperCase() + ", "
            + Character.toUpperCase(firstName.charAt(0))
            + firstName.substring(1).toLowerCase();
    }

    // "$24.50" or "24.50" becomes 24.5.
    public static double fareAmount(String fare)
    {
        if(fare.startsWith("$"))
            fare = fare.substring(1);
        return Double.parseDouble(fare);
    }
}

Walkthrough

Immutability is the heart of R1: code.toUpperCase() doesn't change code; it creates a new String and returns its address. Ignoring the return value throws the new String away, so the result must be assigned (code = code.toUpperCase();) or used directly (return code.toUpperCase().replace(' ', '-');). cardName() follows the book's BusinessLetter (Figure 7-8) and RepairName steps: indexOf(' ') gives the position of the first space, substring(0, space) is everything before it and substring(space + 1) everything after it, to the end. Splitting at the first space keeps multi-word family names together (de la cruz). indexOf() returns -1 when the character is missing, and substring(0, -1) would throw, so the single-name case is handled first. Character.toUpperCase(firstName.charAt(0)) is a char; the + that joins it with Strings turns it into text. For fares, startsWith("$") is case-sensitive and exact, and substring(1) drops position 0; Double.parseDouble() then succeeds.

Messages students see when a check fails

C1 · The new Strings from toUpperCase() and replace() are used

Strings are immutable: toUpperCase() and replace() return a new String and leave code as it was. Assign each result (code = code.toUpperCase();) or chain the calls in the return statement.

C2 · The name is split at the space with indexOf() and substring()

Store fullName.indexOf(' ') in a variable, then take substring(0, space) for the first name and substring(space + 1) for the family name. The + 1 skips the space itself.

C3 · The first name gets one capital and the rest lowercase

Build the card as familyName.toUpperCase() + ", " + Character.toUpperCase(firstName.charAt(0)) + firstName.substring(1).toLowerCase(): the family name in capitals, then the first letter of the first name as a capital, then the rest of the first name in lowercase.

Hint:

Try your method on mARIA de la cruz: the card must say Maria, not MARIA.

C4 · A name without a space is handled before substring()

indexOf() returns -1 when there is no space, and substring(0, -1) throws an exception. Test for -1 before splitting and return fullName.toUpperCase() in that case.

C5 · A leading $ is removed before parseDouble()

Test fare.startsWith("$"); if it is true, keep fare.substring(1) (everything after position 0). Then return Double.parseDouble(fare).

Hint:

replace('$', ' ') would leave a space that parseDouble() can't read either, and a char can't be replaced by nothing.

Progressive hints

  1. For R1, read the starter's two calls aloud: what does each one return, and where does that returned value go?

  2. Trace "ana lopez": indexOf(' ') is 3. Which substring() calls give "ana" and "lopez"? Remember the second argument is the position after the last character you want.

  3. For a name without a space, indexOf() doesn't fail; it returns a special value. Check for it before you call substring().

Reflection: questions and model answers

  1. Why does cardName() split at the first space? What would a passenger called maria de la cruz get if you split at the last one?

    The first word is the first name and everything after it is the family name. Splitting at the last space would give CRUZ, Maria de la, breaking up a multi-word family name.

  2. What happens if you remove your -1 test and call cardName("cher")? Explain in terms of what indexOf() returns.

    indexOf(' ') returns -1 because there is no space, so substring(0, -1) is called with a negative end position and the program stops with an exception.

  3. fareAmount("24.50 USD") still crashes. Which exception, and why can't parseDouble() handle it?

    NumberFormatException. parseDouble() can only convert a String that represents a valid number, and " USD" makes it invalid.
