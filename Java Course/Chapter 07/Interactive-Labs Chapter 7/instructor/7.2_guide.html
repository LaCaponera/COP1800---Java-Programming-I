COP1800 · Java Programming I · Lab 7.2

The badge printer that rejects Muñoz

Objectives

  • Use Character.isLetter(), isDigit() and isWhitespace() to test a char instead of hand-written ranges
  • Use Character.toUpperCase() to convert a char, knowing it leaves non-letters unchanged
  • Distinguish the is methods (return a boolean) from the to methods (return a converted char)
  • Explain why the methods are called with the class name: they are static

Requirements

  1. R1 isAllowed() returns true for any letter (use Character.isLetter()), a space, a hyphen or an apostrophe, and false for everything else. No hand-written letter ranges.
  2. R2 toBadge() returns the uppercase equivalent with Character.toUpperCase(); characters that are not lowercase letters come back unchanged. No arithmetic such as c - 32.
  3. R3 reason() returns "a digit" when Character.isDigit() is true, "whitespace" when Character.isWhitespace() is true, and "a symbol" otherwise.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. With the starter, what does isAllowed('\u00f1') (the n with a tilde) return, and why?

    false. The letter is not between 'a' and 'z' or 'A' and 'Z' in Unicode, and it is not a space, hyphen or apostrophe, so every part of the test is false.

  2. Character.isUpperCase() and Character.toUpperCase() look alike. What different kinds of values do they return?

    isUpperCase() returns a boolean (true or false); toUpperCase() returns a char, the uppercase equivalent of its argument.

Solution

BadgePrinter.java
public class BadgePrinter
{
    // True for the characters a badge can print:
    // letters, spaces, hyphens and apostrophes.
    public static boolean isAllowed(char c)
    {
        return Character.isLetter(c) || c == ' ' || c == '-' || c == '\'';
    }

    // The character as it is printed on the badge (badges are in capitals).
    public static char toBadge(char c)
    {
        return Character.toUpperCase(c);
    }

    // Why the printer rejected a character.
    public static String reason(char c)
    {
        if(Character.isDigit(c))
            return "a digit";
        else if(Character.isWhitespace(c))
            return "whitespace";
        else
            return "a symbol";
    }
}

Walkthrough

The Character class (Table 7-1) knows the properties of every Unicode character, so Character.isLetter('\u00f1') is true while the range test c >= 'a' && c <= 'z' is false: ñ has the Unicode value 241, past z (122). Character.toUpperCase() returns the uppercase equivalent and makes no change to anything that is not a lowercase letter, so digits, hyphens and capitals need no special case; c - 32 only works for a to z. The methods whose names start with is return a boolean; those that start with to return a char. All are static, which is why they are called with the class name and a dot. The space test stays c == ' ' on purpose: isWhitespace() is also true for a tab or a newline, which a badge must not print. In reason(), the order of the tests doesn't matter here because a character can't be a digit and whitespace at once.

Test program

Students run it in an IDE and paste the output into the page.

TestBadgePrinter.java
public class TestBadgePrinter
{
    public static void main(String[] args)
    {
        printBadge("O'Neil-Park");
        printBadge("R2D2");
        printBadge("Li\tWei");
        printBadge("Ana!");

        // ñ is the n with a tilde in Munoz; Ñ is its capital.
        char enye = 'ñ';
        System.out.println("n with tilde allowed: " + BadgePrinter.isAllowed(enye));
        System.out.println("n with tilde printed as its capital: "
            + (BadgePrinter.toBadge(enye) == 'Ñ'));
        System.out.println("7 printed as: " + BadgePrinter.toBadge('7'));
    }

    // Walks through the name one character at a time
    // (charAt() and length() are in section 7.4).
    private static void printBadge(String name)
    {
        String badge = "";
        for(int i = 0; i < name.length(); ++i)
        {
            char c = name.charAt(i);
            if(!BadgePrinter.isAllowed(c))
            {
                String shown = name.replace('\t', '_');
                System.out.println(shown + ": rejected at position "
                    + i + ", " + BadgePrinter.reason(c));
                return;
            }
            badge = badge + BadgePrinter.toBadge(c);
        }
        System.out.println(name + ": badge " + badge);
    }
}

Messages students see when a check fails

C1 · Letters are recognised with Character.isLetter()

Replace the two letter ranges with Character.isLetter(c). It is true for every letter Unicode knows, including ñ, é and ü, while the ranges only cover a to z and A to Z. Keep the tests for space, hyphen and apostrophe.

Hint:

isLetterOrDigit() would also let digits through, and a badge can't print them.

C2 · toBadge() converts with Character.toUpperCase()

Return Character.toUpperCase(c). It knows the capital of every lowercase letter and leaves all other characters unchanged, so you need neither the range test nor - 32.

C3 · reason() asks isDigit() and isWhitespace()

Test Character.isDigit(c) and Character.isWhitespace(c) and return "a digit", "whitespace" or "a symbol". isWhitespace() is true for a space, tab, newline, carriage return and form feed, so one call covers them all.

Progressive hints

  1. Look at Table 7-1: which methods answer yes/no questions about a character, and which return a converted character?

  2. Character methods are static: you call them with the class name, a dot and the method name, and pass the char as the argument.

  3. reason() needs an if, an else if and an else: one return for each of the three kinds of rejected character.

Reflection: questions and model answers

  1. Why does toBadge() need no if once it uses Character.toUpperCase()? Use the '7' line of the test output in your answer.

    toUpperCase() makes no change to an argument that is not a lowercase letter, so '7', hyphens, apostrophes and capitals come back as they are. The test shows 7 printed as 7.

  2. Why did the solution keep c == ' ' for spaces instead of using Character.isWhitespace(c) in isAllowed()?

    isWhitespace() is also true for a tab, newline, carriage return and form feed. A badge should print a space but reject a tab, as Li<Tab>Wei shows.

  3. How can you tell from the call Character.isDigit(c) that isDigit() is a static method?

    It is called with the class name Character and a dot, not with an object, so it belongs to the class.
