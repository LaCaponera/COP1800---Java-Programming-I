The night bus that left at 00:0-15

Objectives

  • Tell a logic error that produces wrong output from one that stops the program
  • Write an assert statement with a Boolean expression and an error message
  • Use an assertion's message to find and fix a negative-remainder bug

Requirements

  1. R1 toClock() contains an assert statement, with a message after the colon, stating that the minute of the day is at least 0 and less than MINUTES_PER_DAY.
  2. R2 Negative offsets wrap correctly: -15 becomes 23:45.
  3. R3 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. With the starter, work out toClock(-15) by hand: the values of dayMinute, hour and minute, and the final String.

    dayMinute = -15 % 1440 = -15, hour = -15 / 60 = 0, minute = -15 % 60 = -15. twoDigits(0) is "00" and twoDigits(-15) is "0-15" (since -15 < 10), so the sign shows 00:0-15.

  2. The program never stopped. Is this a syntax error, a runtime error, or another kind of logic error? How did anyone notice it?

    A logic error that doesn't end the program: it compiles and runs but produces incorrect output (p. 421). Someone noticed only because the sign looked wrong.

Solution

ShiftClock.java
public class ShiftClock
{
    public static final int MINUTES_PER_DAY = 1440;

    // Turns minutes after midnight into a 24-hour "HH:MM" time.
    // Offsets can be negative (before midnight) or more than one day.
    public static String toClock(int minutes)
    {
        int dayMinute = minutes % MINUTES_PER_DAY;
        if (dayMinute < 0)
            dayMinute += MINUTES_PER_DAY;
        assert dayMinute >= 0 && dayMinute < MINUTES_PER_DAY
            : minutes + " gave minute of day " + dayMinute;
        int hour = dayMinute / 60;
        int minute = dayMinute % 60;
        return twoDigits(hour) + ":" + twoDigits(minute);
    }

    private static String twoDigits(int value)
    {
        if (value < 10)
            return "0" + value;
        return "" + value;
    }
}

Walkthrough

This is the EvenOdd bug from pp. 422–423 in a new place: the remainder operator gives a negative result when its left operand is negative, so -15 % 1440 is -15, and the hour and minute come out as 0 and -15. No exception is thrown, so it is a logic error that only produces wrong output. assert booleanExpression : message states a condition that must be true; when it is false and assertions are enabled, Java throws an AssertionError showing the message (p. 422), here -15 gave minute of day -15. The test program enables assertions for ShiftClock with ClassLoader.getSystemClassLoader().setClassAssertionStatus("ShiftClock", true), which has the same effect as java -ea (p. 423) and must run before the class is first used. Adding MINUTES_PER_DAY to a negative remainder fixes it; Math.floorMod(minutes, MINUTES_PER_DAY) (Java 8) does the same in one call. The book's other fix, Math.abs(), worked for even/odd but is wrong here: it turns -15 into 00:15 instead of 23:45. The assertion stays in the finished code and costs nothing when assertions are off (p. 424).

Test program

Students run it in an IDE and paste the output into the page.

TestShiftClock.java
public class TestShiftClock
{
    public static void main(String[] args)
    {
        // Same as running with java -ea, for ShiftClock only.
        ClassLoader.getSystemClassLoader().setClassAssertionStatus("ShiftClock", true);

        int[] departures = {75, 1439, 1470, -15, -1500};
        for (int x = 0; x < departures.length; ++x)
            System.out.println(departures[x] + " -> " + ShiftClock.toClock(departures[x]));
    }
}

Expected output

75 -> 01:15
1439 -> 23:59
1470 -> 00:30
-15 -> 23:45

Messages students see when a check fails

C1 · toClock() asserts the range of the minute of the day

Add assert dayMinute >= 0 && dayMinute < MINUTES_PER_DAY : <a message>; after dayMinute is computed. Include the values in the message, as Figure 10-43 does, so the error tells you what went wrong.

Hint:

The syntax is assert booleanExpression : optionalErrorMessage (p. 422); this lab asks for the message.

C2 · Negative remainders wrap into the day

When the remainder is negative, add MINUTES_PER_DAY to it (or use Math.floorMod(minutes, MINUTES_PER_DAY)). Math.abs() fixed the book's even/odd test but turns -15 into 00:15, the wrong side of midnight.

Progressive hints

  1. Write the assertion first and run the test program before fixing anything. The AssertionError's message tells you which value broke your assumption.

  2. The book met the same surprise on p. 423: a negative left operand gives a negative remainder. How far is -15 from the start of the day it belongs to?

  3. A minute of the day of -15 means 15 minutes before midnight. Adding one whole day of minutes moves it to the same moment on the previous day.

Reflection: questions and model answers

  1. With only the assertion added, what did the AssertionError tell you that the wrong sign 00:0-15 did not?

    It stopped at the first bad value and named it: -15 gave minute of day -15. That shows the problem is the remainder (it is negative), not the hour/minute split or twoDigits().

  2. Why is an assertion the right tool here, but the wrong tool for checking that a dispatcher typed a number?

    The assertion checks the programmer's own assumption, which should always be true when the code is right, and it is switched off for users. Typed input can be wrong at any time in production, so it needs exception handling or a decision the program always performs (p. 424).
