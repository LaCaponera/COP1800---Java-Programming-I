Lab 10.4: The laser cutter that stayed locked all afternoon

Cleanup that runs no matter what: the finally block

Estimated time: about 20 minutes. Reading: Ch. 10, section 10.4 (pp. 408–410).

You will be able to:

  • Use a finally block for cleanup that must happen whether or not an exception occurs
  • Explain why code after a try...catch pair might never run
  • Replace repeated cleanup code with a single finally block

How to complete it

  1. Open the lab page (10.4.html) from this module. Your work saves automatically in your browser.
  2. Answer the short warm-up about the code you are given, then write your code until every structure check passes.
  3. Run the test program (instructions are on the lab page), paste its output back into the page and compare.
  4. Answer the reflection questions in your own words.
  5. Download (or copy) your lab report.

Submit here: the lab report (.txt) and your code file (LaserCutter.java).

How it will be assessed

  • Requirements met (5 pts): All structure checks pass and the test program's output matches (see the lab report).
  • Reasoning (3 pts): Warm-up and reflection answers are specific to this code, in the student's own words.
  • Style (2 pts): Allman braces kept; one unlock() call, in the finally block; no extra catch blocks.

The checks on the lab page give you feedback; they are not your grade.
