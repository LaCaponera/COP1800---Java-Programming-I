Five errors, two compiles

Objectives

  • Compile a class and read each part of an error message (file, line, problem, caret)
  • Repair common syntax errors: missing semicolon, missing return type, unmatched brace, wrong case
  • Explain why fixing errors can reveal new ones
  • Confirm that a clean compile creates a .class file

Requirements

  1. R1 The public class name matches the file name RoomBooking.java exactly.
  2. R2 main() has the complete header the JVM looks for.
  3. R3 Every statement ends with a semicolon.
  4. R4 Every class name is written with the correct uppercase and lowercase letters.
  5. R5 Every opening curly brace has a matching closing brace.
  6. R6 The program compiles and prints the four-line confirmation. (verified by the program output)

Before you code: warm-up and model answers

  1. Before compiling, read the starter. How many error messages do you predict the compiler will report on the first compile, and why might the count differ from five?

    Any reasonable prediction is fine. The count can differ because the compiler reports what it notices as it parses: some errors stop it from reading further (so later mistakes aren't seen yet), and one error can also trigger several messages. In fact the first compile reports three errors here.

  2. The file is saved as RoomBooking.java. Find one error that has nothing to do with punctuation. What rule does it break?

    The class header says roomBooking with a lowercase r, but a public class must be in a file with exactly the same name, and Java is case sensitive. (Another: system.out should be System.out.)

Solution

RoomBooking.java
public class RoomBooking
{
    public static void main(String[] args)
    {
        System.out.println("Study Room Booking");
        System.out.println("Room: 3B (seats 6)");
        System.out.println("Date: Thursday, 2:00 PM to 4:00 PM");
        System.out.println("Booked by: Team Falcon");
    }
}

Walkthrough

The first compile reports the three errors that stop the compiler from parsing the file: the missing return type void ("invalid method declaration; return type required"), the missing semicolon ("';' expected") and the missing closing brace ("reached end of file while parsing"). Only once the file can be parsed does the compiler check names, so the second compile reports class roomBooking is public, should be declared in a file named roomBooking.java and package system does not exist. Fixing errors lets the compiler get further, which is why new messages can appear.

Messages students see when a check fails

C1 · The class name matches RoomBooking.java

A public class must be saved in a file with exactly the same name. The file is RoomBooking.java, so the class header needs RoomBooking with a capital R and a capital B.

Hint:

Compare the class header with the file name letter by letter. Java is case sensitive.

C2 · main() has its return type

The compiler says a return type is required. The JVM looks for public static void main(String[] args): void belongs between static and main.

C3 · Every output statement ends with a semicolon

One println() statement ends at its closing parenthesis. The compiler reports ';' expected there (sometimes on the line after). Every Java statement ends with a semicolon.

C4 · System is spelled with a capital S

system and System are different names in Java. The compiler reports package system does not exist because it can't find anything called system. The class is System.

C5 · The class body is closed

The file ends after main()'s closing brace, so the class is never closed: reached end of file while parsing. Add the class's closing curly brace at the very end, aligned with the opening one under the class header.

Progressive hints

  1. Compile first and fix only what the compiler reports. Don't hunt by eye yet: reading the messages is the skill this lab trains.

  2. The caret ^ shows where the compiler noticed the problem, which can be just after the real mistake. For ';' expected, look at the end of the line the caret points to, or the line above.

  3. If the second compile reports new errors, that's normal: the compiler couldn't read far enough to see them before. Compare each name in the code with the file name and with Java's own class names, letter by letter.

Reflection: questions and model answers

  1. What did your first compile report, and what new errors appeared on the second compile? Explain why the compiler didn't report them the first time.

    The first compile reported the missing return type, the missing semicolon and the missing closing brace (reached end of file while parsing). After fixing them, the second compile reported that the public class roomBooking should be in a file named roomBooking.java and that package system does not exist. The compiler must parse the code into meaningful parts before it can check names; while the structure was broken it couldn't get that far.

  2. The message for the missing semicolon pointed at the right line, but other messages can point after the real mistake. Why can the reported location differ from where the error was made?

    The compiler reports where it first discovers that something is wrong, not where the programmer made the mistake. For example, a missing brace isn't noticed until the end of the file, and a missing semicolon can be noticed only when the next line starts, so you sometimes have to look before the caret.
