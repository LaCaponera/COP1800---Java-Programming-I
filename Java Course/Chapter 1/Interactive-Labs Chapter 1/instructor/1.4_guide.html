The bus-stop display

Objectives

  • Identify the class, object, method and argument in an output statement
  • Choose print() or println() to control where the next output appears
  • Output a blank line with println() and no argument
  • Write literal strings exactly as they must appear

Requirements

  1. R1 A blank line follows the title, produced by println() with no argument.
  2. R2 Loading arrivals... (with one trailing space) and done are printed by two statements and appear on one line.
  3. R3 The two route lines follow, each on its own line.
  4. R4 Lines are started only with println(): no \n inside strings.
  5. R5 The full display matches the screen above exactly. (verified by the program output)

Before you code: warm-up and model answers

  1. In System.out.println("CITY TRANSIT - STOP 4417"); name the class, the object, the method and the argument.

    System is the class, out is the object (a property of System that refers to the standard output device), println() is the method, and the literal string "CITY TRANSIT - STOP 4417" is the argument passed to it.

  2. The method header in the starter is public static void main(String[] args). What does void tell you, and does it mean main() produces no output?

    void means main() doesn't return a value to any method that calls it. It doesn't mean there's no output: main() can still display text, as this program does.

Solution

StopDisplay.java
public class StopDisplay
{
    public static void main(String[] args)
    {
        System.out.println("CITY TRANSIT - STOP 4417");
        System.out.println();
        System.out.print("Loading arrivals... ");
        System.out.println("done");
        System.out.println("Route 12 to Downtown: 7 min");
        System.out.println("Route 30 to Airport: 15 min");
    }
}

Walkthrough

print() displays its argument and leaves the insertion point at the end of that line, so done continues it; println() moves to the next line afterwards. println() with empty parentheses outputs just a line break, the blank line. Every literal string sits inside double quotation marks and appears exactly as typed, including the trailing space before done.

Messages students see when a check fails

C1 · A blank line comes from println() with no argument

Call println with empty parentheses: it outputs nothing but a line break, which is the blank line. Methods always keep their parentheses, even with no argument.

C2 · The status line uses print() and then println()

Print "Loading arrivals... " with print() so the insertion point stays on that line, then print "done" with println() so the next output starts on a new line. Keep the space before the closing quotation mark.

Hint:

Which of the two methods leaves the insertion point at the end of the current line?

C3 · Both route lines are printed in order

After the status line, use one println() per route with the text exactly as shown on the screen: capital R, a colon after the destination, then the minutes.

C4 · No \n escapes

Use println() to end a line instead of \n inside a string. The reading builds every line from its own statement, which also keeps each statement short and readable.

Progressive hints

  1. Count the lines on the target screen (the blank one too) and match each with one statement. One line needs two statements.

  2. Remember the difference: after println() the next output starts on a new line; after print() it continues on the same line.

  3. Spaces inside quotation marks are part of the output. Check the space between ... and done against the screen.

Reflection: questions and model answers

  1. Why did the status line need print() for its first part rather than println()? Describe what the screen would show with println().

    print() leaves the insertion point at the end of the line, so done appears right after Loading arrivals... . With println() the insertion point would move to the next line, and done would appear alone on its own line, breaking the display's layout.

  2. Your class is named StopDisplay. What must the file be called, and what would go wrong if you saved it as stopdisplay.java?

    It must be saved as StopDisplay.java, matching the public class name exactly, including case. Java is case sensitive, so with stopdisplay.java the compiler reports that the public class StopDisplay should be declared in a file named StopDisplay.java.
