How a Java program travels

Objectives

  • Trace a program from source file to bytecode to execution in the JVM
  • Name the file each step reads and the file it produces
  • Explain what "write once, run anywhere" means and which file makes it possible
  • Write a console application that displays text output

Requirements

  1. R1 Line 2 names the file javac compiles and the bytecode file it creates.
  2. R2 Line 3 gives the exact command that runs the program in the JVM.
  3. R3 Line 4 names the file that can be copied to Windows, macOS or Linux and run unchanged.
  4. R4 The card prints exactly five lines, in order, one println() per line. (verified by the program output)

Before you code: warm-up and model answers

  1. Line 1 is already written. After it, which program turns TicketScanner.java into something the computer can run, and what kind of code does it produce?

    The Java compiler, javac, translates the source code in TicketScanner.java into bytecode, a binary program stored in TicketScanner.class. The bytecode is not run directly by the computer; the JVM interprets it.

  2. JavaJourney itself is a console application. What does that mean, and how is it different from the other type of Java application the reading describes?

    A console application displays character (text) output on the screen, here through System.out.println(). A windowed application creates a GUI with elements such as menus, toolbars and dialog boxes.

Solution

JavaJourney.java
public class JavaJourney
{
    public static void main(String[] args)
    {
        System.out.println("How TicketScanner travels");
        System.out.println("1. Source code is saved in TicketScanner.java");
        System.out.println("2. javac TicketScanner.java creates bytecode in TicketScanner.class");
        System.out.println("3. java TicketScanner starts the JVM, which interprets the bytecode");
        System.out.println("4. The same TicketScanner.class runs on Windows, macOS and Linux");
    }
}

Walkthrough

The compiler reads source code (.java) and writes bytecode (.class). The java command takes the class name without any extension: typing java TicketScanner.class makes the JVM look for TicketScanner.class.class. Portability comes from the bytecode file: every platform's JVM translates the same .class file to its own machine language, so there's one version of the program, not one per operating system.

Reflection: questions and model answers

  1. Why does a software company using Java usually ship one version of its program instead of separate Windows, macOS and Linux versions?

    Java programs are compiled to bytecode that runs on the Java Virtual Machine, not directly on the operating system. Each platform has its own JVM that translates the same bytecode into its machine language, so one .class file works everywhere: write once, run anywhere.

  2. The JVM is called a hypothetical computer. In your own words, what does that mean, and how does it make Java programs more secure?

    The JVM isn't hardware; it's software that behaves like a computer for bytecode. Because programs run inside it instead of talking to the hardware directly, it can check the bytecode before running it and insulate the real machine from the program, which protects against intruders reaching the hardware through the operating system.
