The fire drill that compiles

Objectives

  • Tell a syntax error from a logic error in a real program
  • Explain why a compiler accepts a program whose instructions are wrong
  • Fix logic by putting the right commands in the right order
  • Choose a test that would reveal a logic error

Requirements

  1. R1 The title line prints first, then the steps print in order: Step 1, Step 2, Step 3, Step 4.
  2. R2 Step 2 sends people down the stairs, never the elevator: Step 2: Take the stairs to the ground floor.
  3. R3 A final step prints last: Step 5: Do not re-enter until staff say it is safe.
  4. R4 The program's complete output matches the drill card exactly. (verified by the program output)

Before you code: warm-up and model answers

  1. Look at the starter without changing it. Will it compile? If it does, does that prove the program is correct? Explain in a sentence or two.

    Yes, it compiles: every statement follows Java's syntax rules and ends with a semicolon. That only proves there are no syntax errors. The program can still be wrong: it prints Step 3 before Step 1 and tells people to use the elevator, which are logic errors the compiler cannot detect.

  2. Predict the starter's output line by line. Which line would a student in Room 214 see second?

    The title, then Step 3, Step 1, Step 2 (elevator) and Step 4, in the order the statements are written. The second line is "Step 3: Walk to the assembly point in Lot C.", which is wrong: people would be told to walk to the lot before stopping work.

Solution

FireDrill.java
public class FireDrill
{
    public static void main(String[] args)
    {
        System.out.println("FIRE DRILL - ROOM 214");
        System.out.println("Step 1: Stop work and leave your belongings.");
        System.out.println("Step 2: Take the stairs to the ground floor.");
        System.out.println("Step 3: Walk to the assembly point in Lot C.");
        System.out.println("Step 4: Wait for your name to be called.");
        System.out.println("Step 5: Do not re-enter until staff say it is safe.");
    }
}

Walkthrough

Statements in main() run one after another, top to bottom, so the order of the println() calls is the order of the drill. The compiler accepted the original because every statement was legal Java; it cannot know that elevators are unsafe in a fire or that Step 3 should not come first. Those are logic errors, and only reading the output against the specification reveals them.

Messages students see when a check fails

C1 · The steps print in order after the title

Statements run from top to bottom, so the println() for Step 1 must come before Step 2, and so on, all after the title. Move whole statements; don't renumber the text.

Hint:

Read the output as a student standing in Room 214 would. Which instruction must they follow first?

C2 · No one is sent to the elevator

Change the Step 2 text so it reads exactly Step 2: Take the stairs to the ground floor. The compiler can't catch this one: any text inside quotation marks is legal Java, so a dangerous instruction compiles perfectly.

C3 · Step 5 is added at the end

Add one more System.out.println(...) statement after Step 4 with the exact text Step 5: Do not re-enter until staff say it is safe. Every statement ends with a semicolon.

Progressive hints

  1. Run the starter in your head first: main() executes its statements from the first line to the last. Write down the output in that order and compare it with what a safe drill needs.

  2. You don't need new Java for R1: cut a whole statement and paste it in a different place. The number inside the quotation marks is just text; it doesn't control when a line runs.

  3. For Step 5, copy the shape of an existing println() statement (class, dot, object, dot, method, parentheses, quotation marks, semicolon) and change only the text between the quotation marks.

Reflection: questions and model answers

  1. The compiler accepted the word "elevator" without a warning. Why can't a compiler catch this kind of mistake, and who is responsible for catching it?

    A compiler only checks that statements follow the language's rules. Text inside quotation marks is a literal string and can contain any characters, so "elevator" is as legal as "stairs". Whether the instruction is safe is a question about meaning, a logic error, so the programmer has to catch it by examining the output against the specification.

  2. The reading warns that correct output for one test doesn't prove a program is logically correct (a program that adds 2 and 2 also prints 4). Describe a check you could make on this drill program that would reveal an ordering mistake that a quick glance might miss.

    Compare every output line with the official drill card, in order, rather than looking only at the first or last line. A glance at the title or a single step would look fine; reading the full sequence (or having a second person do a structured walkthrough) shows whether Step 1 truly comes before Step 2, and so on.

Extension

Add a line before Step 1 that tells people which exit to use. Where must that statement go so the drill still makes sense, and why does the compiler not care where you put it?
