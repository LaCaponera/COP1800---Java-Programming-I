Read the docs: a better weather alert

Objectives

  • Find a class's page in the Java API documentation
  • Read a method summary to choose the version with the arguments you need
  • Use a constant from the documentation in your code
  • Explain how the API docs help you learn beyond the textbook

Requirements

  1. R1 Before any dialog, the console log reads Alert issued: severe thunderstorm until 6:00 PM.
  2. R2 The warning dialog shows Severe thunderstorm until 6:00 PM. Stay indoors. with the title Campus Weather Alert and the warning icon.
  3. R3 A second dialog shows Updates every 15 minutes on the CampusSafe app. with the same title and the information icon.
  4. R4 Both dialogs are centred on the screen.
  5. R5 The test program's console output matches. (verified by the program output)

Before you code: warm-up and model answers

  1. The starter's dialog call passes two arguments. Based on section 1.8, what does each one do, and why can't you change the title with only these two?

    null centres the dialog and the string is the message shown. The two-argument version has no parameter for a title or an icon type, so it always uses the defaults; a different version of the method, with more parameters, is needed.

  2. Section 1.9 says the Java API is also called the Java class library. What kind of information does it give you about a class like JOptionPane?

    It explains how to use each prewritten Java class: its fields (such as constants), and a list of all its methods with the arguments each version takes and what it does.

Solution

WeatherAlert.java
import javax.swing.JOptionPane;

public class WeatherAlert
{
    public static void main(String[] args)
    {
        System.out.println("Alert issued: severe thunderstorm until 6:00 PM");
        JOptionPane.showMessageDialog(null,
            "Severe thunderstorm until 6:00 PM. Stay indoors.",
            "Campus Weather Alert", JOptionPane.WARNING_MESSAGE);
        JOptionPane.showMessageDialog(null,
            "Updates every 15 minutes on the CampusSafe app.",
            "Campus Weather Alert", JOptionPane.INFORMATION_MESSAGE);
    }
}

Walkthrough

The JOptionPane page lists three versions of showMessageDialog. The four-argument one, showMessageDialog(Component parentComponent, Object message, String title, int messageType), adds the title and the message type. The message types are constants in the Field Summary (ERROR_MESSAGE, INFORMATION_MESSAGE, WARNING_MESSAGE, QUESTION_MESSAGE, PLAIN_MESSAGE), written with the class name and a dot because they belong to JOptionPane. Same method name, different argument lists: Java picks the version that matches the arguments you pass.

Messages students see when a check fails

C1 · The alert is logged before any dialog

Put a System.out.println() with exactly Alert issued: severe thunderstorm until 6:00 PM above the first dialog. Statements run in order, and the program waits at each dialog.

C2 · The warning dialog has the title and warning icon

Use the four-argument version from the docs: where the dialog goes, the message, the title, then the message type. The warning type is a constant of JOptionPane, so write the class name, a dot, and the constant's name.

Hint:

In the docs, the Method Summary shows each version's parameter list in order. The Field Summary lists the message-type constants.

C3 · The second dialog uses the information icon

After the warning, add a second four-argument call with the updates message, the same title, and the message-type constant for information.

C4 · Both dialogs are centred

Pass null as the first argument of each showMessageDialog call, so the dialog appears in the centre of the screen.

Progressive hints

  1. Start at the class page for JOptionPane. Use your browser's Find (Ctrl+F) for showMessageDialog to jump between its versions.

  2. Read the parameter list of each version from left to right: the names (parentComponent, message, title, messageType) tell you what each argument is for and in what order.

  3. The message type is an int, but you don't need to know the number: the docs give it a name in the Field Summary. Constants that belong to a class are written as ClassName.CONSTANT_NAME.

Reflection: questions and model answers

  1. How many versions of showMessageDialog did you find, and how does Java know which one you mean when you call it?

    Three: with two arguments (parent and message), with four (adding title and message type), and with five (adding a custom icon). Java chooses the version whose parameter list matches the number and types of the arguments in the call.

  2. Describe how you would use the API docs to learn something the textbook hasn't covered yet. Use a concrete example other than this lab.

    Find the class's page (for example PrintStream, the type of System.out), scan the Method Summary for a method whose description matches the goal, then read its details: parameters, return type and what it does. For example, the PrintStream page shows println() versions that accept different types of argument, such as a char or an int.

Extension

Find the five-argument version of showMessageDialog. What extra argument does it take? Try JOptionPane.ERROR_MESSAGE and JOptionPane.PLAIN_MESSAGE and describe how each dialog looks.
