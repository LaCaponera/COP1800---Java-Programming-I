The climbing gym's member cards

Objectives

  • Write mutator (set) and accessor (get) methods with the right return types and parameters
  • Decide when a method should be an instance method (no static) and when a class method (static)
  • Use a class's fields directly inside its own methods
  • Compute a value from fields in a getter instead of storing it

Requirements

  1. R1 setMemberName(String) stores a name and returns nothing; getMemberName() returns it as a String. Both are public instance methods (no static).
  2. R2 setMonthlyRate(double) and getMonthlyRate() do the same for the monthly rate, which is a double.
  3. R3 getAnnualCost() returns twelve times the member's monthly rate as a double. It is calculated each time it's called: the class has no annual-cost field.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. printGymRules() is static but getMemberId() is not. Using the reading's question "how many times does it occur?", explain why each choice is right.

    The rules occur once for the whole gym, so a class method is right and needs no object. A member ID occurs once per member, so the getter must work with one object's field: it is an instance method, called with a member object.

  2. From another class, which of these compile, and why? (a) MemberCard.printGymRules(); (b) MemberCard.getMemberId(); (c) card.getMemberId(); where card is a MemberCard object.

    (a) and (c). (a) is a public static method, usable with the class name. (b) fails because getMemberId() is nonstatic and needs an object to know whose ID to return. (c) uses an object, so it works.

Solution

MemberCard.java
public class MemberCard
{
    private int memberId;
    private String memberName;
    private double monthlyRate;

    // A class method: the rules are the same for every member.
    public static void printGymRules()
    {
        System.out.println("Tidewater Climbing Gym: chalk bags only.");
    }

    public void setMemberId(int id)
    {
        memberId = id;
    }

    public int getMemberId()
    {
        return memberId;
    }

    public void setMemberName(String name)
    {
        memberName = name;
    }

    public String getMemberName()
    {
        return memberName;
    }

    public void setMonthlyRate(double rate)
    {
        monthlyRate = rate;
    }

    public double getMonthlyRate()
    {
        return monthlyRate;
    }

    public double getAnnualCost()
    {
        return monthlyRate * 12;
    }
}

Walkthrough

A setter takes one parameter of the field's type and returns void; a getter takes nothing and returns the field's type. None of them is static: each works with one member's own fields, so it must be called with an object, as in ana.getMemberName(). If you write static on one, the compiler reports non-static variable memberName cannot be referenced from a static context. Inside the class, every method uses the fields directly; they don't need to be passed in. getAnnualCost() calculates its answer from monthlyRate, so it can never fall out of step with the rate. printGymRules() stays static because it uses no member's data.

Messages students see when a check fails

C1 · Instance setter and getter for memberName

Write setMemberName() with one String parameter and a void return type, storing it in memberName, and getMemberName() with no parameters, returning memberName as a String. Leave out static: these methods work with one member's own field.

Hint:

The memberId pair shows the shape; only the type and names change.

C2 · Instance setter and getter for monthlyRate

Write setMonthlyRate() taking a double and getMonthlyRate() returning a double, both without static. The rate is a double because it holds dollars and cents.

C3 · getAnnualCost() is a double instance method, with no stored field

Add public double getAnnualCost() with no static and no parameters. Don't add an annual-cost field: a stored copy would go out of date the moment the monthly rate changes.

C4 · The annual cost is calculated from the monthly rate

Return the monthly rate multiplied by the number of months in a year. The method reads the field directly; it needs no parameter.

Progressive hints

  1. Copy the shape of the memberId pair: a setter returns nothing and takes one parameter; a getter takes nothing and returns the field's type.

  2. Methods that belong to each member never use static. If the compiler mentions a static context, look for that word in your headers.

  3. The yearly cost isn't stored anywhere: compute it from the rate in the return statement, and keep the result a double.

Reflection: questions and model answers

  1. Why doesn't setMemberName() need to return anything, and why doesn't getMemberName() need a parameter?

    The setter's job is to store a value in the object, so it has nothing to send back. The getter reads the object's own field, which every method of the class can use directly, so it needs no information from the caller.

  2. A colleague suggests adding an annualCost field with its own setter. What could go wrong that can't happen with your getAnnualCost()?

    The stored annual cost could disagree with the monthly rate: if the rate changes and nobody updates the field, the card shows a wrong yearly cost. Calculating it from the rate each time keeps the two consistent.
