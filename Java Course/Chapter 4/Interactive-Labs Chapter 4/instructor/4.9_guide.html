The pool-cover quote

Objectives

  • Explain why Math needs no import and no object, and use Math.PI and Math.round()
  • Import a class or a whole package, and know what an import does and doesn't do
  • Create dates with LocalDate.of() and calculate with plusWeeks() and getDayOfWeek()

Requirements

  1. R1 The program imports LocalDate (the class, import java.time.LocalDate;, or the package, import java.time.*;) and then uses the short name LocalDate everywhere.
  2. R2 The area uses Math.PI, not a typed approximation. The area shown is rounded to two decimals and the price to whole dollars with Math.round(); no Math object is created.
  3. R3 The install date comes from orderDate.plusWeeks(WEEKS_TO_INSTALL), and its line shows the day of the week with getDayOfWeek().
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. The program uses Math and LocalDate, but only one of them needs an import. Which one, and why?

    LocalDate, which is in the java.time package. Math is in java.lang, the one package Java imports into every program automatically.

  2. The starter calculates the install day as 21 + 7 * WEEKS_TO_INSTALL. Which day number is that, and what do you predict LocalDate.of(2026, 12, 42) does?

    Day 42. December has 31 days, so there is no such date: the program stops with an error (an exception saying the day of the month is invalid) instead of printing January 11.

Solution

PoolQuote.java
import java.time.LocalDate;

public class PoolQuote
{
    public static void main(String[] args)
    {
        final double RADIUS = 3.5;          // metres
        final double COVER_PRICE = 18.75;   // dollars per square metre
        final int WEEKS_TO_INSTALL = 3;

        double area = Math.PI * RADIUS * RADIUS;
        double roundedArea = Math.round(area * 100) / 100.0;
        long price = Math.round(area * COVER_PRICE);

        LocalDate orderDate = LocalDate.of(2026, 12, 21);
        LocalDate installDate = orderDate.plusWeeks(WEEKS_TO_INSTALL);

        System.out.println("Pool radius: " + RADIUS + " m");
        System.out.println("Cover area: " + roundedArea + " sq m");
        System.out.println("Cover price: $" + price);
        System.out.println("Ordered: " + orderDate);
        System.out.println("Install: " + installDate + " ("
            + installDate.getDayOfWeek() + ")");
    }
}

Walkthrough

Math lives in java.lang, the only package imported automatically, and every member is static, so Math.PI and Math.round() are used with the class name; new Math() isn't even possible, because its constructor is private. Math.round() returns the closest whole number (a long for a double argument), so the price is a long; rounding to cents multiplies by 100, rounds, and divides by 100.0 so the division isn't integer division. LocalDate is in java.time, so it needs its full path, an import of the class, or an import of the package; import java.*; is not allowed, and an import copies no code. LocalDate.of(2026, 12, 42) throws an exception because December has no 42nd day; plusWeeks() lets the date itself roll into January 2027, and getDayOfWeek() returns the DayOfWeek value MONDAY.

Messages students see when a check fails

C1 · LocalDate is imported and used by its short name

Add import java.time.LocalDate; (or import java.time.*;) at the top of the file, above the class, and shorten every java.time.LocalDate to LocalDate. import java.*; isn't allowed: a wildcard works only for one specific package.

Hint:

Look at how your earlier programs reached Scanner.

C2 · Math.PI for the area and Math.round() for both roundings

Use Math.PI instead of 3.14, and Math.round() twice: for the area to two decimals (scale by 100, round, divide by 100.0) and for the price to whole dollars. Every Math member is static, so use the class name and never create a Math object.

Hint:

Math.round() returns a long; store the price in a variable of that type.

C3 · The install date is calculated by the date, with its day of the week

Get the install date from orderDate.plusWeeks(WEEKS_TO_INSTALL) instead of adding to the day number, and add the install date's getDayOfWeek() to its line. The date handles month and year changes; December 42 doesn't exist.

Progressive hints

  1. java.time.LocalDate appears four times. One line at the very top of the file lets every one of them shrink to LocalDate.

  2. Every member of Math is static: the class name, a dot, the member. Math.round() gives the closest whole number, so rounding to cents means scaling up first and back down afterwards.

  3. Dates aren't plain numbers: ask the order date itself for the date some weeks later, then ask that date which day of the week it is.

Reflection: questions and model answers

  1. Why does Math.PI work without new Math(), and why couldn't you create a Math object even if you tried?

    All of Math's constants and methods are static, so they belong to the class and are used with its name. And Math's constructor is private, so other classes can't instantiate it.

  2. import java.time.*; and import java.time.LocalDate; both work here. Give one reason to prefer each.

    The wildcard saves typing when several classes from the package are used. Naming the class documents exactly what the program uses and avoids conflicts when two packages have classes with the same name. Neither one copies code into the program.
