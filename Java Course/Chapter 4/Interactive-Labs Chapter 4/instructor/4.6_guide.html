The bike rental's missing constructor

Objectives

  • State the values Java gives numeric, boolean and reference fields when no constructor sets them
  • Write a constructor: the class's name and no return type, not even void
  • Write a constructor with parameters and overload it with a parameterless one
  • Explain why new X() stops compiling once a class has only constructors with parameters

Requirements

  1. R1 The parameterless version is a real default constructor: the class's name and no return type, not even void. It still starts every walk-in as a Cruiser for 1 hour.
  2. R2 An overloaded constructor BikeRental(String type, int rentalHours) sets both fields from its parameters, and the parameterless constructor stays, so new BikeRental() still compiles.
  3. R3 RentalCounter creates the booked rental with the two-argument constructor, a "Tandem" for 3 hours, and prints its line after Booked: .
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. The starter's BikeRental() has void in its header. To the compiler, is it a constructor or an ordinary method? What will walkIn.getSummary() return?

    An ordinary method, because constructors have no return type. Nothing calls it, so Java's automatic default constructor runs instead and the summary is null for 0 h, helmet: false.

  2. Which starting values does Java give a numeric field, a boolean field and a String field when no constructor sets them?

    Numeric fields get 0, boolean fields get false, and reference fields such as a String get null.

Solution

BikeRental.java
public class BikeRental
{
    private String bikeType;
    private int hours;
    private boolean helmetIncluded;

    public BikeRental()
    {
        bikeType = "Cruiser";
        hours = 1;
    }

    public BikeRental(String type, int rentalHours)
    {
        bikeType = type;
        hours = rentalHours;
    }

    public String getSummary()
    {
        return bikeType + " for " + hours + " h, helmet: " + helmetIncluded;
    }
}
RentalCounter.java
public class RentalCounter
{
    public static void main(String[] args)
    {
        BikeRental walkIn = new BikeRental();
        System.out.println("Walk-in: " + walkIn.getSummary());

        BikeRental booked = new BikeRental("Tandem", 3);
        System.out.println("Booked: " + booked.getSummary());
    }
}

Walkthrough

With void in its header, BikeRental() was an ordinary method that happened to share the class's name. Nothing called it, so new BikeRental() ran the default constructor Java supplies when a class has none, which leaves bikeType null, hours 0 and helmetIncluded false. Removing void makes it a constructor. The two-parameter version overloads it: same name, different parameter list, so the compiler picks one by the arguments in each new. Keeping the parameterless constructor matters: once a class has any constructor you wrote, Java no longer supplies one, and new BikeRental() would fail with constructor BikeRental in class BikeRental cannot be applied to given types.

Messages students see when a check fails

C1 · BikeRental() is a constructor, not a void method

Remove void from BikeRental(). A constructor has the class's name and no return type, not even void; with a return type, it's an ordinary method that new never calls.

Hint:

Compare its header with the headers of the class's other methods.

C2 · An overloaded constructor takes the type and the hours, and the parameterless one stays

Add a second constructor, BikeRental(String type, int rentalHours), that stores both values, and keep the parameterless one. Once a class has any constructor you wrote, Java stops supplying a default one, so new BikeRental() needs yours.

C3 · The booking uses the two-argument constructor

Create the booking with new BikeRental("Tandem", 3): the arguments are a String and an int, in the same order as the constructor's parameters. Then print its summary after Booked: .

Progressive hints

  1. A constructor's header has the class's name and nothing where a return type would go.

  2. Overloaded constructors share one name and differ only in their parameter lists. The booking will pass a String and then an int.

  3. If new BikeRental() stops compiling, the parameterless constructor is gone: once you write any constructor, Java no longer supplies one.

Reflection: questions and model answers

  1. Suppose you had written only the two-parameter constructor and deleted the parameterless one. Which line would break, and why didn't it break before you wrote any constructor?

    new BikeRental() in RentalCounter. Before, Java supplied a default constructor because the class had none. Once you write any constructor, Java no longer supplies one, so a call with no arguments has nothing to match.

  2. helmetIncluded is never assigned, yet it prints false. Is relying on that automatic value a good idea? What does the reading suggest?

    It works, but the reading suggests initializing a field explicitly in the constructor for clarity, even when the value equals the default, so a reader sees it is intended rather than forgotten.
