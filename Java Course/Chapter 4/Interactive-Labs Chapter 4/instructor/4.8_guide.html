COP1800 · Java Programming I · Lab 4.8

The beach cleanup's volunteer badges

Objectives

  • Use a static field as a class variable that every object shares
  • Write a static method that works without an object, and explain why it has no this
  • Choose correctly between static, final and static final for a field

Requirements

  1. R1 volunteerCount is a class variable: one copy shared by every Volunteer, still able to change (static, not final).
  2. R2 The badge number is a nonstatic final field, assigned once in the constructor from the count.
  3. R3 The event name is a static final constant whose value is given where it is declared.
  4. R4 getVolunteerCount() is a class method (static), so it can be called as Volunteer.getVolunteerCount() without any object.
  5. R5 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. Apply the reading's question, "once per class or once per object?", to each of the four fields.

    The event name and the sign-up count occur once for the whole class. The badge number and the volunteer's name occur once per volunteer object.

  2. With the starter, why does every volunteer get badge #1?

    volunteerCount is an instance variable, so each new volunteer gets its own count starting at 0. The constructor adds 1 to that fresh copy, so every badge is 1 and no count is ever shared.

Solution

Volunteer.java
public class Volunteer
{
    private static final String EVENT_NAME = "Harbor Beach Cleanup";
    private static int volunteerCount = 0;
    private final int BADGE_NUMBER;
    private String name;

    public Volunteer(String volunteerName)
    {
        name = volunteerName;
        volunteerCount = volunteerCount + 1;
        BADGE_NUMBER = volunteerCount;
    }

    public static int getVolunteerCount()
    {
        return volunteerCount;
    }

    public void display()
    {
        System.out.println(EVENT_NAME + ": badge #" + BADGE_NUMBER + " " + name
            + " (" + volunteerCount + " signed up)");
    }
}

Walkthrough

Ask of each field how many times it occurs and whether it may change. The count occurs once per class and changes: static, not final, so every constructor call adds to the one shared copy, and Ana's line shows 3 after Lena signs up although Ana's object was never touched. The badge occurs once per volunteer and never changes: final but not static, assigned in the constructor, like NUM_EVENTS in the reading's dog triathlon. The event name is shared and fixed: static final, with its value in the declaration. Constants are conventionally named in capitals (EVENT_NAME, BADGE_NUMBER); keeping the old names also passes. getVolunteerCount() uses only a class variable, so it can be static; it could not return name, because a static method has no this and so no particular volunteer.

Messages students see when a check fails

C1 · The count is static and not final

Declare volunteerCount as private static int. A static field exists once for the whole class, so each new volunteer adds to the same count. It can't be final: it changes every time someone signs up.

Hint:

Once per class, or once per volunteer?

C2 · The badge number is final but not static

Declare the badge number private final int with no value and no static, and assign it once in the constructor from the count. final stops it from ever changing; leaving out static gives every volunteer their own badge.

C3 · The event name is a static final constant set in its declaration

Make the event name private static final String, with its value in the declaration. It's the same for every volunteer (static) and never changes (final); a static final field must get its value where it is declared.

C4 · getVolunteerCount() is a class method

Add static to getVolunteerCount(). It returns only a class variable, so it needs no object and can be called as Volunteer.getVolunteerCount().

Progressive hints

  1. Two fields hold one value for the whole event; two hold one value per volunteer. Only the first kind is static.

  2. final means "assigned once". A count that grows can't be final; a badge given in the constructor can be, as long as it isn't static.

  3. A static final field must get its value in its declaration. A method that uses only class variables, and is called with the class name, needs one more word in its header.

Reflection: questions and model answers

  1. Could getVolunteerCount() stay static if it returned name instead? Explain using the this reference.

    No. A static method has no this reference because no object is associated with it, so it can't know which volunteer's name to return; the compiler rejects using an instance variable there.

  2. Why must the badge number be final but not static, while the event name is both?

    Each volunteer needs their own badge that never changes, so it is one value per object (not static) that is fixed once assigned (final). The event name is one value for everyone (static) that never changes (final).

Extension
