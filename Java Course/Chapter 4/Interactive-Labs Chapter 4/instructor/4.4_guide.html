COP1800 · Java Programming I · Lab 4.4

The bakery's pickup shelf

Objectives

  • Declare an object reference and allocate the object with new and its constructor
  • Call an object's methods with its identifier, a dot and the method
  • Explain why a client can't assign a private field, and what the set and get methods offer instead
  • Write a getter that controls how a value leaves the object

Requirements

  1. R1 OrderDesk.main() declares two Order references, pickup and delivery, and allocates each object with new Order() (in one statement or two).
  2. R2 Each order's number, item and quantity are set through its public setters, and each line is printed from its getters; OrderDesk never names a field.
  3. R3 getOrderCode() returns "HB-" followed by the order number: the getter decides how the number leaves the object.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. After Order pickup; runs, but before pickup = new Order();, has memory been set aside for an order's number, item and quantity? What does pickup hold after the second statement?

    No. The declaration only tells the compiler the name will be used. After new Order(), pickup holds a reference: the memory address of the newly allocated Order object.

  2. In new Order(), what is Order()? Nobody wrote a method with that name in Order.java; where does it come from?

    It is the constructor, the special method that creates and initializes the object. When a class has no constructor of its own, Java writes a default one, always named after the class.

Solution

OrderDesk.java
public class OrderDesk
{
    public static void main(String[] args)
    {
        System.out.println("Harbor Bakery pickup shelf");

        Order pickup = new Order();
        Order delivery;
        delivery = new Order();

        pickup.setOrderNumber(301);
        pickup.setItem("sourdough roll");
        pickup.setQuantity(12);
        delivery.setOrderNumber(302);
        delivery.setItem("lemon tart");
        delivery.setQuantity(2);

        System.out.println(pickup.getOrderCode() + ": "
            + pickup.getQuantity() + " x " + pickup.getItem());
        System.out.println(delivery.getOrderCode() + ": "
            + delivery.getQuantity() + " x " + delivery.getItem());
    }
}
Order.java
public class Order
{
    private int orderNumber;
    private String item;
    private int quantity;

    public void setOrderNumber(int number)
    {
        orderNumber = number;
    }

    public String getOrderCode()
    {
        return "HB-" + orderNumber;
    }

    public void setItem(String itemName)
    {
        item = itemName;
    }

    public String getItem()
    {
        return item;
    }

    public void setQuantity(int count)
    {
        quantity = count;
    }

    public int getQuantity()
    {
        return quantity;
    }
}

Walkthrough

Order pickup; only declares a name; new Order() sets aside memory for an order and calls its constructor, and pickup then holds that object's memory address: it is a reference. One statement (Order pickup = new Order();) and two statements do the same thing; the solution shows both. Because the fields are private, pickup.orderNumber = 301; would fail with orderNumber has private access in Order, so the desk uses the setters. getOrderCode() shows why that matters: the bakery's prefix is added in one method, and every client gets codes in the right format without knowing how they are made.

Messages students see when a check fails

C1 · Two Order objects are declared and created with new

Declare pickup and delivery with the type Order, and give each one an object with new Order(). A declaration alone only reserves a name: new sets aside the memory and calls the constructor.

Hint:

Compare it with how you create a Scanner.

C2 · Each order is set and read through its methods

Set each order's number, item and quantity with its setters (pickup.setOrderNumber(301) and so on) and build each line from getOrderCode(), getQuantity() and getItem(). The fields are private: another class can't name them.

Hint:

Object name, dot, method: one call per value.

C3 · getOrderCode() adds the HB- prefix

Return the text "HB-" joined with + to orderNumber. The getter controls how the number leaves the object, so every client gets the bakery's format automatically.

Progressive hints

  1. Creating an object takes a type and a name, like any variable, plus new and the constructor to set aside its memory.

  2. The fields are private, so OrderDesk talks to each order only through its public methods: the object's name, a dot, the method and its argument.

  3. The code is text: start the returned value with the prefix in quotes and join the number to it with +.

Reflection: questions and model answers

  1. The bakery's code format changed once, and you edited one method. What would the change have cost if OrderDesk and three other programs read the orderNumber field directly?

    Every one of those programs would need to add the prefix itself, and any one that was missed would print the wrong code. With the getter, the format lives in one place, and clients get it without changes: that is data hiding through encapsulation.

  2. pickup and delivery call the very same getOrderCode(). How does it return HB-301 for one and HB-302 for the other?

    Each object has its own orderNumber, and the method is called through a particular object, so it reads that object's field: 301 for pickup, 302 for delivery.

Extension
