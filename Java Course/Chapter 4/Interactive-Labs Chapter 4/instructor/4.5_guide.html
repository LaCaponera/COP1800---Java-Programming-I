COP1800 · Java Programming I · Lab 4.5

The shipping counter's labels

Objectives

  • Explain why a class you write is a programmer-defined, composite data type
  • Write a method whose return type is a class, and return an object from it
  • Write a method with an object parameter
  • Assign a returned object to a declared reference, as you would an int

Requirements

  1. R1 public static Parcel makeParcel(String destination, double weight) creates a new Parcel, sets both values and returns it: its return type is the class Parcel.
  2. R2 public static void printLabel(Parcel parcel) receives a Parcel and prints its three label lines.
  3. R3 main() assigns first and second the parcels returned by makeParcel() and prints each with printLabel(); main() itself has no new, no setter calls and no println().
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. Compare int count; with Parcel first;. In what ways does the reading say a class you write can be used like a primitive type such as int?

    Both are declared with a type and an identifier, and both can be passed into a method, returned from a method and assigned to another variable of the same type. A class is just a new, programmer-defined (composite) data type.

  2. The two halves of the starter's main() differ only in a few values. Which ones? Those are exactly what the two methods will need.

    The destination and the weight ("Portland", 4.5 versus "Savannah", 12.25), which become makeParcel()'s parameters, and which parcel is printed, which becomes printLabel()'s parameter.

Solution

ShippingCounter.java
public class ShippingCounter
{
    public static void main(String[] args)
    {
        Parcel first;
        Parcel second;
        first = makeParcel("Portland", 4.5);
        second = makeParcel("Savannah", 12.25);
        printLabel(first);
        printLabel(second);
    }

    public static Parcel makeParcel(String destination, double weight)
    {
        Parcel tempParcel = new Parcel();
        tempParcel.setDestination(destination);
        tempParcel.setWeight(weight);
        return tempParcel;
    }

    public static void printLabel(Parcel parcel)
    {
        System.out.println("SHIP TO: " + parcel.getDestination());
        System.out.println("WEIGHT:  " + parcel.getWeight() + " lb");
        System.out.println("--------");
    }
}

Walkthrough

Parcel is a type you invented, so it goes wherever a type goes: as a return type (static Parcel makeParcel(...)), as a parameter type (printLabel(Parcel parcel)) and as the type of a variable in main(). As in Figure 4-10, the object is constructed inside makeParcel() and returned; main() assigns the returned reference to first, exactly as it would assign an int a method returns. Writing new Parcel() in main() as well would create an object that is immediately replaced. The label format now lives in one method, so a new line on every label is one edit.

Messages students see when a check fails

C1 · makeParcel() has Parcel as its return type

Write the header public static Parcel makeParcel(String destination, double weight). The return type is Parcel: a class you write is a data type, just like double.

C2 · makeParcel() builds a new Parcel and returns it

Inside makeParcel(), create a Parcel with new, set its destination and weight from the parameters, and return the object.

C3 · printLabel() receives a Parcel

Write public static void printLabel(Parcel parcel): the parameter's type is the class, and the method prints the label using that parcel's getters.

C4 · main() receives the parcels and passes them on

In main(), assign each parcel the object makeParcel() returns, then pass it to printLabel(). Leave the new, the setters and the println() statements to the two methods: that's the repetition you are removing.

Hint:

first = makeParcel(...) works the same way as assigning an int a method returns.

Progressive hints

  1. Write the two method headers first. A method that hands back a parcel has Parcel where you have always written int, double or void.

  2. Inside makeParcel(), build the object exactly as the starter does in main(), but with the parameters, then send it back with return.

  3. In main(), a call to makeParcel(...) is a Parcel: store it in first the way you would store a returned int.

Reflection: questions and model answers

  1. In Figure 4-10 and in your program, main() declares a parcel but never constructs one. Why would writing new Parcel() in main() as well be wasted work?

    The assignment from makeParcel() replaces the reference straight away, so the object created in main() would never be used; its values would be overwritten by the returned parcel.

  2. The shipping company adds a barcode line to every label. Compare the work in the starter with the work in your version.

    In the starter, the line must be added after every parcel's statements, forty times tomorrow, and one could be missed. In my version, it is one println() in printLabel(), and every label gets it.

Extension

Write public static Parcel copyParcel(Parcel original) that returns a new Parcel with the same destination and weight. Change the copy's weight and print both. Did the original change? What does that tell you about new?
