COP1800 · Java Programming I · Lab 4.2

The ferry tickets that all say the same name

Objectives

  • Name the parts of a class header and say which one is optional
  • Explain the difference between an instance variable (one copy per object) and a static field (one copy per class)
  • Make data fields private so other classes reach them only through public methods (information hiding)

Requirements

  1. R1 passengerName is an instance variable: no static, so each ticket has its own copy.
  2. R2 Both data fields, passengerName and tripNumber, are private; the methods stay public.
  3. R3 TicketBooth sets the evening ticket's trip with setTripNumber(19) instead of assigning the field.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. The class header is public class FerryTicket. Name its three parts and say which one is optional.

    public is the access specifier (optional), class is the keyword, and FerryTicket is the identifier, which conventionally starts with an uppercase letter.

  2. passengerName is declared static. Predict the name the morning ticket will print, and explain why.

    Leo Park. A static field has one copy shared by every ticket, so setting the evening ticket's name overwrote the only copy, including the morning ticket's.

Solution

FerryTicket.java
public class FerryTicket
{
    private String passengerName;
    private int tripNumber;

    public void setPassengerName(String name)
    {
        passengerName = name;
    }

    public String getPassengerName()
    {
        return passengerName;
    }

    public void setTripNumber(int trip)
    {
        tripNumber = trip;
    }

    public int getTripNumber()
    {
        return tripNumber;
    }
}
TicketBooth.java
public class TicketBooth
{
    public static void main(String[] args)
    {
        FerryTicket morning = new FerryTicket();
        FerryTicket evening = new FerryTicket();

        morning.setPassengerName("Ana Ruiz");
        morning.setTripNumber(7);
        evening.setPassengerName("Leo Park");
        evening.setTripNumber(19);

        System.out.println("Trip " + morning.getTripNumber() + ": "
            + morning.getPassengerName());
        System.out.println("Trip " + evening.getTripNumber() + ": "
            + evening.getPassengerName());
    }
}

Walkthrough

With static, one passengerName exists for the whole class, so setting Leo Park on the evening ticket replaced Ana Ruiz everywhere. Without static, the field is an instance variable: every FerryTicket object gets its own copy. Making both fields private is information hiding: only FerryTicket's methods may use them, so evening.tripNumber = 19; no longer compiles (tripNumber has private access in FerryTicket) and the booth must call setTripNumber(19). The methods stay public: they are the class's receptionist, the only way in.

Messages students see when a check fails

C1 · passengerName is an instance variable

Remove static from passengerName. A static field exists once for the whole class, so every ticket shares one name and the last one set wins. Without static, each ticket object gets its own copy.

Hint:

Ask: does a passenger name occur once per class or once per ticket?

C2 · Both fields are private

Declare both fields private. Private data can be used only by the class's own methods, so other classes must go through setTripNumber() and the other public methods, which is where rules about valid values can later be enforced.

C3 · TicketBooth uses the setter, not the field

Replace evening.tripNumber = 19; with a call to the ticket's public setTripNumber() method. Once the field is private, assigning it from another class doesn't compile.

Hint:

The morning ticket already shows how its trip is set.

Progressive hints

  1. Ask of each field: does it occur once per ticket, or once for the whole class? Only the second kind is static.

  2. A field that another class can assign directly isn't hidden. Which access specifier lets only FerryTicket's own methods use it?

  3. Once the fields are hidden, TicketBooth must go through the class's methods: there is already a public one for the trip number.

Reflection: questions and model answers

  1. After your change, how many copies of passengerName exist when the booth sells 100 tickets? How many would exist with static?

    100 copies, one per ticket object, because it is an instance variable. With static there would be exactly one, shared by all 100 tickets.

  2. setTripNumber() accepts any number today. Why is it still better than a public field, even before it checks anything?

    All changes now pass through one method, so a rule such as "only trips that exist" can be added there later and every client obeys it automatically. With a public field any class could store anything, and every client would need changing.
