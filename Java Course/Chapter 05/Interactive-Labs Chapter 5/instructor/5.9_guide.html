COP1800 · Java Programming I · Lab 5.9

The jet-ski deposit that charges the wrong renters

Objectives

  • Apply the precedence of !, relational, equality, &&, || and ?: operators to evaluate an expression by hand
  • Explain why a || b && c means a || (b && c)
  • Add parentheses to change the order of evaluation where the rule needs it
  • Add parentheses that change nothing but make the intended order obvious

Requirements

  1. R1 getExtraDeposit() groups the age-or-incidents test in parentheses, so that either of those and the fast model are required.
  2. R2 isDiscounted() keeps its meaning (a member, or a local on a weekday) but shows the && part in parentheses.
  3. R3 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. Rewrite the starter's condition with the parentheses Java uses because of precedence.

    incidents > MAX_INCIDENTS || (age < MIN_AGE && model == FAST_MODEL): the comparisons are evaluated first, then &&, then ||.

  2. p, q and r are all true. What is the value of !q || r? Of !(q || !r)?

    !q || r is false || true, which is true. In !(q || !r), the parentheses go first: true || false is true, and ! makes it false.

Solution

JetSkiDesk.java
public class JetSkiDesk
{
    public static final int MIN_AGE = 25;
    public static final int MAX_INCIDENTS = 2;
    public static final char FAST_MODEL = 'X';
    public static final int EXTRA_DEPOSIT = 200;

    public static int getExtraDeposit(int age, int incidents, char model)
    {
        int deposit = 0;
        if((incidents > MAX_INCIDENTS || age < MIN_AGE) && model == FAST_MODEL)
            deposit = EXTRA_DEPOSIT;
        return deposit;
    }

    public static boolean isDiscounted(boolean isMember, boolean isLocal,
            boolean isWeekday)
    {
        return isMember || (isLocal && isWeekday);
    }

    public static void main(String[] args)
    {
        System.out.println("Theo: extra deposit $" + getExtraDeposit(40, 3, 'S'));
        System.out.println("Ana: extra deposit $" + getExtraDeposit(22, 0, 'X'));
        System.out.println("Max: extra deposit $" + getExtraDeposit(30, 0, 'X'));
        System.out.println("Member, weekend: " + isDiscounted(true, false, false));
        System.out.println("Local, weekday: " + isDiscounted(false, true, true));
        System.out.println("Local, weekend: " + isDiscounted(false, true, false));
    }
}

Walkthrough

&& has higher precedence than || (Table 5-1), just as multiplication comes before addition. The starter's condition therefore meant incidents > MAX_INCIDENTS || (age < MIN_AGE && model == FAST_MODEL): three incidents made the whole expression true on their own, whatever the model, so Theo paid the deposit for a standard ski. Parentheses around the || part force it to be evaluated first, matching the rule: (incidents > MAX_INCIDENTS || age < MIN_AGE) && model == FAST_MODEL (the book's Figure 5-34). The relational and equality comparisons need no parentheses of their own, because they bind more tightly than && and ||. In isDiscounted() precedence already gave the intended meaning; the parentheses change nothing for the computer but tell the next reader that the order was deliberate.

Messages students see when a check fails

C1 · The OR part is grouped before the AND

Put parentheses around incidents > MAX_INCIDENTS || age < MIN_AGE, then join that group to model == FAST_MODEL with &&. Without them && goes first, so more than two incidents alone triggers the deposit even on the standard model.

Hint:

Rewrite the starter's condition with the parentheses Java silently adds. Is that the owner's rule?

C2 · The AND part is shown in parentheses

Write isMember || (isLocal && isWeekday). Java would evaluate the && first anyway; the parentheses tell the reader that this order is the rule, not luck.

Progressive hints

  1. Precedence works like arithmetic: a + b * c multiplies first. In a || b && c, which operator plays the part of the multiplication?

  2. Evaluate the starter's condition for Theo (40, 3 incidents, model S) step by step, doing && first. Which part makes it true?

  3. Parentheses are evaluated first. Put them around the part of the rule that is joined by or.

Reflection: questions and model answers

  1. Your isDiscounted() parentheses don't change any result. Why are they still worth writing?

    They make the intended order visible. A reader doesn't have to remember that && binds tighter than ||, and a later change can't silently move the grouping without someone noticing the parentheses.

  2. Mo is 25 with exactly 2 incidents and rents model X. Explain, using the constants, why Mo pays no extra deposit.

    age < MIN_AGE is 25 < 25, false, and incidents > MAX_INCIDENTS is 2 > 2, false, so the grouped || is false, and false && anything is false. Both limits are strict comparisons.
