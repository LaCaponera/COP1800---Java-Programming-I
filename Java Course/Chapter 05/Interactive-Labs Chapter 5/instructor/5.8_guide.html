The lighthouse tower on a windy day

Objectives

  • Read and write the conditional operator: test ? valueIfTrue : valueIfFalse
  • Replace an if…else that only chooses between two values with one conditional expression
  • Use ! to negate a Boolean variable, and know when it reads more clearly than a negated comparison

Requirements

  1. R1 getTicketPrice() is one return statement whose value comes from the conditional operator ? :; no if.
  2. R2 canClimbTower() returns true only when it is not windy and the visitor is at least MIN_CLIMB_AGE, using !isWindy.
  3. R3 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. In printVisit(), what does canClimbTower(age, isWindy) ? ", tower climb OK" : ", no tower climb" produce for Sam (34, calm day)?

    ", tower climb OK". The test is true for Sam, so the conditional expression takes the value after the ?, and that text is joined to the rest of the line.

  2. The starter's canClimbTower() receives isWindy but never uses it. Who can climb on a windy day as the code stands?

    Everyone 7 or older: the method returns only age >= MIN_CLIMB_AGE, so the wind makes no difference. That's how Ivy went up on Tuesday.

Solution

LighthouseTickets.java
public class LighthouseTickets
{
    public static final int CHILD_MAX_AGE = 12;
    public static final double CHILD_PRICE = 6.00;
    public static final double ADULT_PRICE = 14.00;
    public static final int MIN_CLIMB_AGE = 7;

    public static double getTicketPrice(int age)
    {
        return (age <= CHILD_MAX_AGE) ? CHILD_PRICE : ADULT_PRICE;
    }

    public static boolean canClimbTower(int age, boolean isWindy)
    {
        return !isWindy && age >= MIN_CLIMB_AGE;
    }

    public static void printVisit(String name, int age, boolean isWindy)
    {
        String price = String.format("%.2f", getTicketPrice(age));
        String climb = canClimbTower(age, isWindy)
            ? ", tower climb OK" : ", no tower climb";
        System.out.println(name + ": $" + price + climb);
    }

    public static void main(String[] args)
    {
        printVisit("Noor", 6, false);
        printVisit("Sam", 34, false);
        printVisit("Ivy", 12, true);
    }
}

Walkthrough

The conditional operator is the only ternary operator in Java: it takes three operands. (age <= CHILD_MAX_AGE) ? CHILD_PRICE : ADULT_PRICE evaluates the test, then takes the value after ? when it is true and the value after : when it is false, so the whole method is one return statement. It suits an if…else whose only job is to choose between two values; for actions or longer logic, an if…else reads better. printVisit() already used one: canClimbTower(…) ? ", tower climb OK" : ", no tower climb". The NOT operator ! reverses a Boolean value. !isWindy reads naturally as "not windy", which is the case the book recommends ! for (a Boolean variable), and it is clearer than isWindy == false. ! has the highest precedence, so !isWindy && age >= MIN_CLIMB_AGE negates only isWindy.

Messages students see when a check fails

C1 · One return with the conditional operator

Replace the if…else with return (age <= CHILD_MAX_AGE) ? CHILD_PRICE : ADULT_PRICE;. The conditional operator chooses between two values in one expression, which is all this method does.

Hint:

printVisit() already contains one conditional expression you can use as a model.

C2 · Climbing needs NOT windy and the minimum age

Return !isWindy && age >= MIN_CLIMB_AGE. The ! operator turns "windy" into "not windy"; both conditions must hold, so they are joined with &&. Testing isWindy == false works but reads less clearly than !isWindy.

Progressive hints

  1. Read ? : as "if … then this value, otherwise that value". Which two values does getTicketPrice() choose between?

  2. The climbing rule has two conditions that must both be true. One of them is about the wind being absent.

  3. ! placed before a Boolean value reverses it: !isWindy is true exactly when isWindy is false.

Reflection: questions and model answers

  1. Give one reason to prefer the conditional operator in getTicketPrice() and one situation where you would keep an if…else instead.

    It's concise: one statement that clearly picks one of two values. I would keep an if…else when each branch performs actions, such as printing or changing several variables, or when the test is long enough that a single line becomes hard to read.

  2. Rewrite the climbing rule without ! (for example with isWindy == false) and say which version is easier to read aloud, and why.

    isWindy == false && age >= MIN_CLIMB_AGE. !isWindy is easier: it reads as "not windy", while == false makes the reader evaluate a comparison of a Boolean against a Boolean.
