COP1800 · Java Programming I · Lab 5.4

The kite shop's missing medium bonus

Objectives

  • Nest a decision inside the if clause of another decision when two conditions must be checked in turn
  • Pair each else with the most recent unmatched if, as the compiler does
  • Use braces or a complete inner if…else to make the pairing you intend

Requirements

  1. R1 Inside the decision for 3 or more items, a nested if…else gives LARGE_BONUS when the total is at least MIN_VALUE and MEDIUM_BONUS otherwise.
  2. R2 Fewer than MIN_ITEMS items earns SMALL_BONUS: that else belongs to the outer if, the one that tests the items.
  3. R3 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. Which if does the starter's else belong to: the items test or the value test? How do you know?

    The value test, if(totalValue >= MIN_VALUE). An else pairs with the most recent if that has no else; the indentation that lines it up with the outer if is ignored by the compiler.

  2. Predict Cai's bonus with the starter (2 items, $1,800) and explain it.

    $0. The outer if is false and has no else, so nothing is assigned and bonus keeps its starting value of 0.

Solution

KiteShopBonus.java
public class KiteShopBonus
{
    public static final int MIN_ITEMS = 3;
    public static final double MIN_VALUE = 1000.00;
    public static final int LARGE_BONUS = 50;
    public static final int MEDIUM_BONUS = 25;
    public static final int SMALL_BONUS = 10;

    public static int getBonus(int itemsSold, double totalValue)
    {
        int bonus = 0;
        if(itemsSold >= MIN_ITEMS)
            if(totalValue >= MIN_VALUE)
                bonus = LARGE_BONUS;
            else
                bonus = MEDIUM_BONUS;
        else
            bonus = SMALL_BONUS;
        return bonus;
    }

    public static void printLine(String name, int itemsSold, double totalValue)
    {
        System.out.println(name + ": " + itemsSold + " items, $" + totalValue
            + " -> bonus $" + getBonus(itemsSold, totalValue));
    }

    public static void main(String[] args)
    {
        printLine("Ana", 4, 1250.00);
        printLine("Ben", 5, 640.00);
        printLine("Cai", 2, 1800.00);
    }
}

Walkthrough

The compiler pairs an else with the most recent if that doesn't have one yet, whatever the indentation shows. In the starter, the only else belonged to the inner if(totalValue >= MIN_VALUE): 3+ items under $1,000 got the small bonus, and fewer than 3 items fell through with no else at all, leaving bonus at 0. Giving the inner if its own else (the medium bonus) completes the nested if…else, so the next else pairs with the outer if, exactly as in the book's Figure 5-13. Wrapping the inner decision in braces works too: if(itemsSold >= MIN_ITEMS) { if(…) … else … } else bonus = SMALL_BONUS;. Either way, the whole nested if…else sits inside the if clause of the outer one, and the total value is examined only for staff who sold enough items.

C2 · Each if has its own else

Progressive hints

  1. Read the starter the way the compiler does: an else belongs to the closest if above it that doesn't have an else yet.

  2. Three outcomes need three assignments. Which constant never appears in the starter?

  3. Once the inner if has its own else, the next else you write pairs with the outer if. Braces around the inner decision make the same pairing explicit.

Reflection: questions and model answers

  1. Why is Cai's $1,800 total never examined by your solution? Is that a problem?

    The value test is nested in the items test, so it runs only when 3 or more items were sold. It isn't a problem: with fewer than 3 items the bonus is $10 whatever the value, so the second question would be wasted.

  2. Rewrite the outcome rules as a sentence a new programmer could use to predict where each else goes in any nested decision.

    Each else belongs to the nearest if above it that doesn't already have an else; elses match ifs on a first-in, last-out basis, so an inner decision must be complete (or closed with a brace) before an else for the outer one.
