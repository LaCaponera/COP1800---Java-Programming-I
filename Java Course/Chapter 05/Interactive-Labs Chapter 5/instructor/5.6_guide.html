COP1800 · Java Programming I · Lab 5.6

The parcel counter's eight-kilogram bargain

Objectives

  • Write a range check as one chain of if…else decisions, so a value gets exactly one result
  • Stop asking a question whose answer is already known: finish the chain with a plain else
  • Get the boundary values right with < versus >=
  • Use || for "outside the range": no value can be below the minimum and above the maximum

Requirements

  1. R1 getRate() is one if…else if…else chain: after a range matches, no other rate is assigned.
  2. R2 The chain asks only two questions: the last range is a plain else, because by then its answer is already known.
  3. R3 isOutOfRange() returns true when the weight is below MIN_WEIGHT or above MAX_WEIGHT.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. Trace getRate(8.0) through the starter. Which if statements are true, and what rate is returned?

    The first two are true (8 ≥ 5 and 8 ≥ 1); the third is false. The second if overwrites the heavy rate, so it returns 9.00.

  2. Can any weight make weightKg < MIN_WEIGHT && weightKg > MAX_WEIGHT true? What does that mean for the 45 kg anchor?

    No: a single value can't be below 0.1 and above 30 at once. The method always returns false, so the anchor is treated as valid and quoted a rate.

Solution

ParcelCounter.java
public class ParcelCounter
{
    public static final double LIGHT_LIMIT = 1.0;   // kg
    public static final double MEDIUM_LIMIT = 5.0;  // kg
    public static final double LIGHT_RATE = 4.50;
    public static final double MEDIUM_RATE = 9.00;
    public static final double HEAVY_RATE = 15.00;
    public static final double MIN_WEIGHT = 0.1;
    public static final double MAX_WEIGHT = 30.0;

    public static double getRate(double weightKg)
    {
        double rate;
        if(weightKg >= MEDIUM_LIMIT)
            rate = HEAVY_RATE;
        else if(weightKg >= LIGHT_LIMIT)
            rate = MEDIUM_RATE;
        else
            rate = LIGHT_RATE;
        return rate;
    }

    public static boolean isOutOfRange(double weightKg)
    {
        return weightKg < MIN_WEIGHT || weightKg > MAX_WEIGHT;
    }

    public static void quote(double weightKg)
    {
        if(isOutOfRange(weightKg))
            System.out.println(weightKg + " kg: cannot ship");
        else
            System.out.println(weightKg + " kg: $"
                + String.format("%.2f", getRate(weightKg)));
    }

    public static void main(String[] args)
    {
        quote(0.4);
        quote(3.2);
        quote(8.0);
        quote(45.0);
    }
}

Walkthrough

Three separate if statements are three independent decisions, so a later one can overwrite an earlier one: 8 kg is at least 5 kg (heavy rate) and at least 1 kg, so the second if reset it to the medium rate. Chaining with else ends the decision as soon as a range matches. After asking at least 5 kg? and at least 1 kg? and getting two no answers, the weight must be under 1 kg, so asking again is wasted work and one more place to get a boundary wrong; a plain else handles it (Figure 5-21). Checking the heaviest range first is fine; if most parcels are light, starting from weightKg < LIGHT_LIMIT is equally correct and a little more efficient (Figure 5-22). In isOutOfRange(), a single weight can never be below 0.1 and above 30 at the same time, so the && version was always false; the English "too light and too heavy are errors" means ||.

Messages students see when a check fails

C1 · One chained decision

Connect the decisions with else so they form one chain: if(…) … else if(…) … else …. Separate if statements are all evaluated, so a later one overwrites the rate an earlier one set, which is how 8 kg ended up at the medium rate.

Hint:

Trace 8.0 through the starter one if at a time. How many times is rate assigned?

C2 · The last range is a plain else

Ask at most two questions and finish with a plain else. Once a weight is neither at least 5 kg nor at least 1 kg, it must be under 1 kg; a third comparison repeats a question that's already answered.

C3 · Out of range means too light OR too heavy

Use ||: weightKg < MIN_WEIGHT || weightKg > MAX_WEIGHT. One weight can't be below 0.1 kg and above 30 kg at the same time, so with && the method can never return true.

Progressive hints

  1. Trace an 8 kg crate through the starter's three if statements. Which assignment happens last?

  2. If the first question is at least 5 kg? and the answer is no, and the second is at least 1 kg? and the answer is no, what do you already know about the weight?

  3. Try isOutOfRange(45.0) by hand with &&: what is each side, and what is the result? The English word and can mislead you here.

Reflection: questions and model answers

  1. Your chain asks at least 5 kg? first. If 90% of Seawall's parcels are letters under 1 kg, which question should come first, and how many questions does a typical parcel then need?

    Ask under 1 kg? first (weightKg < LIGHT_LIMIT). Most parcels then need one question instead of two, and the result for every weight is the same.

  2. Why does quote(1.0) show whether you chose >= or > correctly, while quote(3.2) can't?

    1.0 is exactly on the boundary between light and medium, so only it is treated differently by >= and >; 3.2 is inside the medium range and gets the same rate either way.
