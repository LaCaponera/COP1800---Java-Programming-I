The tide-pool walk's go/no-go questions

Objectives

  • Tell a sequence structure (steps that always run) from a decision structure (a yes-or-no question that picks a path)
  • Turn each diamond of a plan into a yes-or-no question whose answer is a boolean
  • Write a relational expression that respects the exact boundary in the plan (below versus up to)

Requirements

  1. R1 isTideLowEnough(double) returns true only when the tide is below SAFE_TIDE.
  2. R2 hasRoomForOneMore(int) returns true when fewer than MAX_GROUP walkers are signed up, so one more can join.
  3. R3 isOldEnough(int) returns true for children MIN_AGE and older.
  4. R4 Each method returns its comparison directly and uses the named constant, not the number.
  5. R5 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. In the guide's plan, which steps form a sequence structure and which are decision structures? Name one of each.

    "Get the tide height, the walkers signed up and the child's age" is a sequence: it always happens. Each question, such as "is the tide below 0.5 m?", is a decision: the answer chooses whether the walk goes ahead or a notice is posted.

  2. The starter's isTideLowEnough() returns false no matter what. What will the check sheet print, and what does that tell you about where the decision has to happen?

    Every answer prints false. The method ignores its parameter, so it isn't making a decision at all; the decision has to come from comparing tideMeters to SAFE_TIDE inside the method.

Solution

TidePoolTour.java
public class TidePoolTour
{
    public static final double SAFE_TIDE = 0.5;  // metres
    public static final int MAX_GROUP = 12;
    public static final int MIN_AGE = 8;

    // The lead guide's plan, in pseudocode:
    //   get the tide height, the walkers signed up, the child's age
    //   is the tide below 0.5 m?           no  -> post "Walk closed"
    //   is there room for one more walker? no  -> post "Walk full"
    //   is the child 8 or older?           no  -> post "Too young"
    //   all yes -> sign the walker up
    // Each question is one diamond in the flowchart: a yes-or-no answer.

    public static boolean isTideLowEnough(double tideMeters)
    {
        return tideMeters < SAFE_TIDE;
    }

    public static boolean hasRoomForOneMore(int signedUp)
    {
        return signedUp < MAX_GROUP;
    }

    public static boolean isOldEnough(int age)
    {
        return age >= MIN_AGE;
    }

    // A sequence structure: every line runs, one after another.
    public static void main(String[] args)
    {
        System.out.println("Saturday walk: go/no-go answers");
        System.out.println("Tide 0.3 m low enough? " + isTideLowEnough(0.3));
        System.out.println("Tide 0.5 m low enough? " + isTideLowEnough(0.5));
        System.out.println("Room with 11 signed up? " + hasRoomForOneMore(11));
        System.out.println("Room with 12 signed up? " + hasRoomForOneMore(12));
        System.out.println("Age 8 old enough? " + isOldEnough(8));
        System.out.println("Age 7 old enough? " + isOldEnough(7));
    }
}

Walkthrough

Every decision a computer makes comes down to a yes-or-no question, and a relational expression such as tideMeters < SAFE_TIDE is that question: its value is true or false, so the method can return it directly. The work is in the boundaries. Below 0.5 m means <, so exactly 0.5 m is not safe. Room for one more with a group of 12 means fewer than 12 are signed up, so 12 signed up answers false. 8 and older means >=, so an 8-year-old may join. Using SAFE_TIDE rather than 0.5 keeps the rule in one place: if the center changes the limit, one line changes. main() is a sequence structure: every statement runs in order; the diamonds of the plan live inside the three methods.

Messages students see when a check fails

C1 · The tide must be strictly below SAFE_TIDE

Return the comparison tideMeters < SAFE_TIDE. The plan says below 0.5 m, so a tide of exactly 0.5 m is not safe: <= would let it through.

Hint:

Read the plan's wording aloud: is 0.5 m itself below 0.5 m?

C2 · Room means fewer than MAX_GROUP signed up

Return signedUp < MAX_GROUP. With 12 already signed up the group is full, so the answer must be false; with 11 there is room for the twelfth walker.

C3 · MIN_AGE and older may join

Return age >= MIN_AGE. 8 and older includes 8 itself, which > would leave out.

C4 · Named constants, not bare numbers

Write each method as a single return of the comparison, using SAFE_TIDE, MAX_GROUP and MIN_AGE. The comparison already is true or false, and the constants keep each rule in one place.

Progressive hints

  1. A comparison such as x < y already has a value, true or false, so it can follow return directly.

  2. Test each boundary from the plan in your head: the tide at exactly 0.5 m, a group with exactly 12, a child of exactly 8. Which answers are yes?

  3. Two of the questions use <; the age question includes its boundary value.

Reflection: questions and model answers

  1. Your isTideLowEnough() contains no if, yet it makes a decision. Explain how.

    The expression tideMeters < SAFE_TIDE is evaluated to a Boolean value, true or false, and the method returns that value. The decision is the comparison itself; an if would only be needed to choose between different actions.

  2. Which call in the check sheet would have printed a wrong answer if you had used <= in hasRoomForOneMore()? Why do boundaries deserve a test of their own?

    hasRoomForOneMore(12) would print true and let a thirteenth walker join. Values in the middle of a range work with either operator; only the boundary value shows whether < or <= matches the rule, so it needs its own test.

Extension

The plan's last step needs all three answers to be yes. Add public static boolean canJoin(double tide, int signedUp, int age) that returns the three answers combined. (Section 5.5 introduces the operator that joins them; for now, what would you write in pseudocode?)
