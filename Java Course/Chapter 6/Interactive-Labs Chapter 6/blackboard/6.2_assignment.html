Lab 6.2: The ferry kiosk that accepts a party of 12

while loops for validating input: priming input, a compound test, and re-reading at the end of the body

Estimated time: about 25 minutes. Reading: Ch. 6, section 6.2 (pp. 202–210).

You will be able to:

  • Write an indefinite (event-controlled) while loop whose number of iterations depends on what the user types
  • Validate input with a priming input before the loop and a new input as the last statement of the loop body
  • Identify the three actions that keep a while loop from running forever: initialize, test and alter the loop control variable
  • Explain why a decision is the wrong structure for validating input

How to complete it

  1. Open the lab page (6.2.html) from this module. Your work saves automatically in your browser.
  2. Answer the short warm-up about the code you are given, then write your code until every structure check passes.
  3. Run the test program (instructions are on the lab page), paste its output back into the page and compare.
  4. Answer the reflection questions in your own words.
  5. Download (or copy) your lab report.

Submit here: the lab report (.txt) and your code file (FerryKiosk.java).

How it will be assessed

  • Requirements met (5 pts): All structure checks pass and the test program's output matches (see the lab report).
  • Reasoning (3 pts): Warm-up and reflection answers are specific to this code, in the student's own words.
  • Style (2 pts): Consistent Allman braces and indentation; every loop body in braces and indented under its loop header; named constants instead of bare numbers in loop conditions.

The checks on the lab page give you feedback; they are not your grade.
