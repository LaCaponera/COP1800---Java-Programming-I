The ferry kiosk that accepts a party of 12

Objectives

  • Write an indefinite (event-controlled) while loop whose number of iterations depends on what the user types
  • Validate input with a priming input before the loop and a new input as the last statement of the loop body
  • Identify the three actions that keep a while loop from running forever: initialize, test and alter the loop control variable
  • Explain why a decision is the wrong structure for validating input

Requirements

  1. R1 The if becomes a while loop that repeats while partySize is less than MIN_PARTY or greater than MAX_PARTY.
  2. R2 Keep the priming input before the loop. Inside the loop, show the message, reprompt, and read the next entry as the last statement of the body, so the loop control variable is altered before it is tested again.
  3. R3 Count the rejected entries in a variable that starts at 0 and print Rejected entries: N after the loop, before returning the valid size.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. Trace the starter with the entries 0, 12 and 3. Which value does readPartySize() return, and which entry is never checked?

    It returns 12. The if rejects 0 and reads again, but nothing checks the second entry, so 12 is returned and 3 is never read.

  2. Is the validation loop you will write definite or indefinite? Why?

    Indefinite (event-controlled). How many times it runs depends on what the traveller types, which is unknown when the program is written.

Solution

FerryKiosk.java
import java.util.Scanner;

public class FerryKiosk
{
    public static final int MIN_PARTY = 1;
    public static final int MAX_PARTY = 8;

    public static int readPartySize(Scanner input)
    {
        int partySize;
        int rejected = 0;

        System.out.print("Party size (" + MIN_PARTY + "-" + MAX_PARTY + ") >> ");
        partySize = input.nextInt();

        while(partySize < MIN_PARTY || partySize > MAX_PARTY)
        {
            rejected = rejected + 1;
            System.out.println("Parties of " + MIN_PARTY + " to " + MAX_PARTY + " only.");
            System.out.print("Party size (" + MIN_PARTY + "-" + MAX_PARTY + ") >> ");
            partySize = input.nextInt();
        }

        System.out.println("Rejected entries: " + rejected);
        return partySize;
    }

    public static void main(String[] args)
    {
        Scanner keyboard = new Scanner(System.in);
        int party = readPartySize(keyboard);
        System.out.println("Booked: party of " + party);
    }
}

Walkthrough

This is the book's EnterSmallValue and CustomerSurvey pattern (Figures 6-10 and 6-12). The input before the loop is the priming input: it gives the loop control variable its first value, and if that value is valid the loop body never runs. The while test checks the variable, and the last statement of the body reads a new value, which is the alter step that lets the test eventually become false. With an if, the second entry was never checked, so 12 slipped through; a loop checks every entry, however many there are. The loop is indefinite (event-controlled): while writing it you can't know whether it will run 0 or 200 times. The test needs ||, not &&: no number is both below 1 and above 8, so an && test would never be true and every entry would be accepted. Counting where the message is shown (inside the body) gives the number of rejected entries.

Messages students see when a check fails

C1 · A while loop repeats while the size is out of range

Replace the if with while(partySize < MIN_PARTY || partySize > MAX_PARTY). A decision checks only the first entry; a loop checks every entry, so a traveller who types 0 and then 12 is asked again.

Hint:

Use ||: no number is below 1 and above 8 at the same time.

C2 · Priming input before the loop, new input last in the body

Read the first entry before the while (the priming input) and make partySize = input.nextInt(); the last statement inside the loop's braces. Then every new entry is tested by the while before it can be used.

C3 · Rejected entries are counted in the loop and reported after it

Declare a counter set to 0 before the loop, add 1 to it inside the loop body (once per rejected entry), and print it as Rejected entries: N after the loop, just before return.

Progressive hints

  1. Trace the starter with the entries 0, 12, 3. Which entry is never compared with the limits?

  2. The only structural change is one keyword; the body already does the right things in the right order (message, prompt, read).

  3. The counter goes up each time the body runs, because the body runs exactly once per rejected entry.

Reflection: questions and model answers

  1. Name the three actions that keep a while loop from running forever, and point to the line in your readPartySize() that does each one.

    Initialize: the priming input before the loop gives partySize its first value. Test: while(partySize < MIN_PARTY || partySize > MAX_PARTY). Alter: partySize = input.nextInt(); as the last statement of the body.

  2. A classmate wrote the test as partySize < MIN_PARTY && partySize > MAX_PARTY. What does the kiosk do with an entry of 12, and why?

    It accepts 12. No number can be below 1 and above 8 at the same time, so the && test is always false, the body never runs and every entry is accepted.

  3. What would happen if you moved partySize = input.nextInt(); out of the loop body to just after the closing brace?

    An invalid first entry would loop forever: partySize never changes inside the loop, so the test stays true and the message prints endlessly.

Extension
