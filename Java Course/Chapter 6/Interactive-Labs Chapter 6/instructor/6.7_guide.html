The cargo ferry that asks the same question 20 times

Objectives

  • Recognize a loop test that repeats work whose result doesn't change, and move that work before the loop
  • Order the operands of && so the condition most likely to be false (and cheapest) is evaluated first
  • Use counts of calls, not guesses, to show that an optimized loop does the same job with less work
  • Weigh performance against readability, as the book's final note on loop performance advises

Requirements

  1. R1 Call getCapacity() once, before the loop, and store the result in a local variable; the loop's test uses that variable. The capacity doesn't change while the ferry is being loaded.
  2. R2 In the loading decision, test the weight first: weightOf(crate) <= MAX_KG && customsCleared(crate). Most crates fail the cheap weight test, so && skips the customs call for them.
  3. R3 Running the test program prints exactly what it expects: the same crates as before, with fewer lookups. (verified by the program output)

Before you code: warm-up and model answers

  1. In the starter, is getCapacity() called once, or once per iteration? Point to the part of the for header that decides it.

    Once per evaluation of the test, the middle section of the header, which runs before every iteration (plus the final test that ends the loop).

  2. In customsCleared(crate) && weightOf(crate) <= MAX_KG, when is weightOf() skipped? Is customsCleared() ever skipped?

    weightOf() is skipped when customsCleared() returns false (a held crate). customsCleared() is never skipped because it is the left operand, so customs is asked about every crate.

Solution

CargoLoader.java
public class CargoLoader
{
    public static final int MAX_KG = 800;

    // Given: these lookups are slow in real life, so the yard counts them.
    private static int capacityLookups = 0;
    private static int customsLookups = 0;

    // Asks the booking database how many crates fit on tonight's ferry.
    public static int getCapacity()
    {
        ++capacityLookups;
        return 3;
    }

    // Asks the customs service whether a crate is cleared (every fifth crate is held).
    public static boolean customsCleared(int crate)
    {
        ++customsLookups;
        return crate % 5 != 0;
    }

    // Reads the weight from the crate's label (fast).
    public static int weightOf(int crate)
    {
        return 700 + (crate * 170) % 400;
    }

    public static void loadFerry(int crates)
    {
        capacityLookups = 0;
        customsLookups = 0;
        int loaded = 0;
        int capacity = getCapacity();

        for(int crate = 1; crate <= crates && loaded < capacity; ++crate)
        {
            if(weightOf(crate) <= MAX_KG && customsCleared(crate))
            {
                System.out.println("  crate " + crate + " loaded (" + weightOf(crate) + " kg)");
                ++loaded;
            }
        }

        System.out.println("Loaded " + loaded + " crates");
        System.out.println("Capacity lookups: " + capacityLookups
            + ", customs lookups: " + customsLookups);
    }

    public static void main(String[] args)
    {
        loadFerry(20);
    }
}

Walkthrough

Unnecessary operations in the test. The middle section of a for header runs before every iteration. With loaded < getCapacity() in it, the database was asked 20 times for a number that never changed (the book's getNumberOfEmployees() example). Calling it once before the loop and testing a local variable gives the same result with 1 lookup. If the capacity could change during loading, the call would have to stay in the loop.

Order of short-circuit evaluation. && evaluates its right operand only when the left one is true. Customs was asked first, so all 19 crates examined triggered a customs call; only 5 of the 20 crates are light enough. With the weight test first, a heavy crate makes the whole expression false without calling customs: 5 lookups instead of 19. For &&, put the condition most likely to be false first; for ||, the one most likely to be true. Cheaper first is a second reason here: reading a label costs less than a web-service call.

The loaded crates are identical (12, 17, 19), which is the rule for any optimization: same behaviour, less work. Both changes also make the code clearer, which matters more: the book's final note says that saving milliseconds at the cost of readability is not a success.

Messages students see when a check fails

C1 · getCapacity() is called once, before the loop

Store the capacity before the loop (int capacity = getCapacity();) and test loaded < capacity. The test section of a for runs before every iteration, so a method call there is repeated every time, even though its answer never changes.

Hint:

Count how many times the middle section of the for header is evaluated for 20 crates.

C2 · The weight test comes before the customs call

Put the weight test on the left of &&: weightOf(crate) <= MAX_KG && customsCleared(crate). && skips its right operand when the left one is false, and most crates are too heavy, so customs is asked only about the light ones.

Progressive hints

  1. Run the starter and read the two lookup counts. Which loop part is responsible for each number?

  2. The capacity is the same number every time it's asked for. Where could you ask once and remember the answer?

  3. With &&, if the left operand is false, the right one is never evaluated. Which condition is false for most crates?

Reflection: questions and model answers

  1. Your version loads the same three crates. Using the lookup counts, explain where each saving came from.

    Capacity lookups fell from 20 to 1 because the call moved out of the loop test, which is evaluated before every iteration. Customs lookups fell from 19 to 5 because the weight test now comes first and && skips the customs call for the 14 heavy crates.

  2. For && the book says test the condition most likely to be false first. Why? What is the matching rule for ||?

    With &&, one false operand decides the result, so a likely-false first operand lets Java skip the second most often. With ||, one true operand decides, so put the condition most likely to be true first.

  3. When would moving getCapacity() out of the loop be wrong?

    If its answer could change during the loop, for example if another clerk could book space on the ferry while it is loading. Then the loop must ask again each time to stay correct; correctness comes before speed.
