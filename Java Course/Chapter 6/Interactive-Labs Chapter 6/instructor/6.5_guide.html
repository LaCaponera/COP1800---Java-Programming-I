The parking kiosk that never shows its menu

Objectives

  • Distinguish pretest loops (while, for) from the posttest do…while loop
  • Write a do…while loop with a braced body and the test at the bottom, ending in a semicolon
  • Recognize when a fake starting value is a sign that the loop's test is in the wrong place
  • Explain why the compiler accepts a variable declared without a value when a do…while body assigns it

Requirements

  1. R1 The menu loop is a do…while: it starts with do, its body is in braces, and the test } while(choice != QUIT); comes after the body. No while loop tests choice before the body.
  2. R2 choice is declared without a starting value (int choice;): the body always assigns it before the test uses it.
  3. R3 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. With the starter, how many times is the menu printed for any driver? Why?

    Zero. choice starts at QUIT, so choice != QUIT is false at the top of the while loop and the body is skipped; only the 0-minute ticket prints.

  2. Where is the test of a do…while loop, and what does that guarantee about its body?

    At the bottom, after the body. The body always executes at least once.

Solution

ParkingKiosk.java
import java.util.Scanner;

public class ParkingKiosk
{
    public static final int ADD_TIME = 1;
    public static final int SHOW_TIME = 2;
    public static final int QUIT = 3;
    public static final int BLOCK = 30;   // minutes bought with each press of 1

    public static void runKiosk(Scanner input)
    {
        int minutes = 0;
        int choice;

        do
        {
            System.out.print("1 add, 2 time, 3 ticket >> ");
            choice = input.nextInt();
            if(choice == ADD_TIME)
            {
                minutes += BLOCK;
                System.out.println("Added " + BLOCK + " min");
            }
            else if(choice == SHOW_TIME)
                System.out.println("Time bought: " + minutes + " min");
            else if(choice != QUIT)
                System.out.println("Choose 1, 2 or 3");
        } while(choice != QUIT);

        System.out.println("Ticket printed: " + minutes + " min");
    }

    public static void main(String[] args)
    {
        runKiosk(new Scanner(System.in));
    }
}

Walkthrough

while and for are pretest loops: the test is evaluated before the body, so the body may run zero times. A menu must be shown before there is any choice to test, which is the definition of a posttest loop: do { ... } while(test); runs the body once and evaluates the test at the bottom (Figure 6-22). Giving choice the value QUIT silenced the compiler but made the pretest false at once, so the body never ran and the kiosk printed a 0-minute ticket. A fake starting value that exists only to get into a loop is a sign the test belongs at the bottom. With do…while, int choice; compiles: the compiler can see that the body, which always runs first, assigns choice before the test reads it. Note the semicolon after while(choice != QUIT), and the closing brace on the same line, which keeps a reader from mistaking that while for the start of a new loop.

Messages students see when a check fails

C1 · A do…while loop tests choice at the bottom

Start the loop with do {, keep the menu code in the braces, and end it with } while(choice != QUIT);. The body then runs once before the test is evaluated, so the menu always appears; remove the while at the top.

Hint:

A posttest loop asks its question after the body: the keyword do opens it.

C2 · choice has no fake starting value

Declare int choice; with no value. The do…while body always assigns choice before the test reads it, so the compiler accepts it, and no made-up value can decide whether the loop starts.

Progressive hints

  1. With the starter, evaluate choice != QUIT once, before anything is printed. Is the menu ever shown?

  2. The menu must run once before there is a choice to test. Which loop puts its test after the body?

  3. Once the test is at the bottom, ask whether choice still needs a value when it's declared.

Reflection: questions and model answers

  1. Why does int choice; (no value) compile with your do…while, when the starter's programmer had to give it a value for the while version?

    In the do…while, the body runs before the test and always assigns choice with input.nextInt(), so the compiler knows choice has a value when the test reads it. In the while version, the test reads choice before anything assigns it.

  2. The book says you are never required to use do…while. How could you get the same behaviour with a while loop, and what does that cost?

    Show the menu and read a choice once before the loop (a priming input), handle it, then loop while choice != QUIT, repeating the same menu code at the end of the body. It works but duplicates code, so a later change to the menu has to be made in two places.

  3. Driver 2 chose 3 on the first try. How many times did your loop body run, and how many times was the test evaluated?

    The body ran once (the menu appeared and 3 was read) and the test was evaluated once, at the bottom; it was false, so the loop ended.

Extension

Add choice 4, cancel, that resets minutes to 0 and prints Cancelled. Then make the kiosk refuse to print a ticket for 0 minutes: if the driver chooses 3 with no time bought, print Add time first and keep the loop going. Which part of the while(...) test has to change?
