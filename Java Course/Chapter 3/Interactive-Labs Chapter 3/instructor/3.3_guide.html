COP1800 · Java Programming I · Lab 3.3

The tutoring center's pay lines

Objectives

  • Declare a method with two parameters, each with its own type and identifier
  • Pass arguments that match the parameters in number, type and order
  • Explain why an int argument is accepted by a double parameter
  • Explain that a parameter holds a copy of the argument, even when the names match

Requirements

  1. R1 Add public static void displayPayAtRate(double hours, double rate): hours first, then rate, each parameter with its own type. It prints a line in the same format as displayPay(), using the rate it receives.
  2. R2 main() calls displayPayAtRate() for Ana with her 6 hours and her $31.00 rate, in the order the parameters expect.
  3. R3 The printout matches the screen above, and displayPayAtRate(10, 20.0) prints 10.0 hours at $20.0 per hour is $200.0. (verified by the program output)

Before you code: warm-up and model answers

  1. main() has a variable named hours, and displayPay() has a parameter named hours. Are they the same variable? What happens to main()'s hours if displayPay() changes its parameter?

    They are different variables, in different memory locations, that happen to share a name. The parameter receives a copy of the argument's value, so changing it inside displayPay() has no effect on hours in main().

  2. displayPay(leoHours) passes an int. Why does it compile, and why does the line show 8.0 rather than 8?

    An int can be promoted to a double, so a double parameter accepts it. Inside the method, hours is a double holding 8.0, and that is what gets printed.

Solution

TutorPay.java
public class TutorPay
{
    public static void main(String[] args)
    {
        double hours = 12.5;     // Maya
        int leoHours = 8;        // Leo logs whole hours

        displayPay(hours);
        displayPay(leoHours);

        // Payroll sheet for Ana: rate $31.00, hours 6
        displayPayAtRate(6, 31.00);
    }

    public static void displayPay(double hours)
    {
        final double STD_RATE = 22.75;
        double pay = hours * STD_RATE;
        System.out.println(hours + " hours at $" + STD_RATE + " per hour is $" + pay);
    }

    public static void displayPayAtRate(double hours, double rate)
    {
        double pay = hours * rate;
        System.out.println(hours + " hours at $" + rate + " per hour is $" + pay);
    }
}

Walkthrough

Each parameter needs its own type, even when both are double: (double hours, rate) does not compile. Arguments are matched to parameters by position, so Ana's call lists the hours first although the sheet lists the rate first. displayPayAtRate(31.0, 6) would compile and print 31.0 hours at $6.0 per hour is $186.0: a logical error that only the output reveals. The literal 6 is an int promoted to double, which is also why Leo's hours print as 8.0. The hours in main() and the parameter hours are different variables: the parameter receives a copy and disappears when the method ends.

Messages students see when a check fails

C1 · displayPayAtRate has two typed parameters: hours, then rate

Declare displayPayAtRate as public static void with two parameters: a double named hours, then a double named rate. Each parameter needs its own type, even when both are double, and the order you choose is the order every call must follow.

Hint:

Compare with displayPay(double hours): you need two of those type-and-name pairs, separated by a comma.

C2 · The pay uses the rate parameter

Compute the pay from the two parameters, hours times rate, not from the standard rate. The second parameter exists so that each call can send its own rate.

C3 · Ana's call passes the hours first, then the rate

Call displayPayAtRate with Ana's hours first and her rate second, matching the parameter list. The sheet lists the rate first; copying that order still compiles, but prints 31.0 hours at $6.0 per hour: a logical error.

Progressive hints

  1. Look at the header of displayPay(double hours): its parentheses hold a type and a name. A method with two parameters lists two of those, separated by a comma.

  2. Arguments are matched to parameters by position, not by name. In which position does displayPayAtRate expect the hours?

  3. Ana's sheet says rate first. Swap the values when you write the call, then check that the printed line starts with 6.0 hours.

Reflection: questions and model answers

  1. What would displayPayAtRate(31.0, 6) do: fail to compile, crash, or something else? Explain why this kind of mistake is dangerous.

    It compiles and runs, because both values fit double parameters, but it prints 31.0 hours at $6.0 per hour: a logical error. Even the total looks right, so nothing warns you; only checking the output against the data reveals it.

  2. A client calling displayPayAtRate() only needs its interface. What exactly is that interface, and what is hidden from the caller?

    The interface is the header: the name, that it returns nothing, and that it takes a double for hours followed by a double for rate. How the pay is computed and printed is hidden in the body; it could change without affecting any call, as long as the header stays the same.

Extension
