COP1800 · Java Programming I · Lab 3.7

The farmers-market scale

Objectives

  • Recognize a call that matches two overloads equally well, and make it an exact match
  • Explain why methods that differ only in return type are illegal
  • Explain why a potentially ambiguous pair of methods compiles until an ambiguous call is made

Requirements

  1. R1 main() prints the pineapple line with a call that is an exact match for the by-count printLine().
  2. R2 Two methods named lineTotal return each line's amount as a double: lineTotal(int quantity, double unitPrice) and lineTotal(double pounds, int centsPerPound). No printLine() returns a value.
  3. R3 main() prints Total: $ followed by the sum of three lineTotal() calls, and the receipt matches the screen above. (verified by the program output)

Before you code: warm-up and model answers

  1. Which printLine() runs for printLine(3, 4.25), and which for printLine(2.5, 360)? Why is neither call ambiguous?

    printLine(3, 4.25) is an exact match for (int, double), and printLine(2.5, 360) is an exact match for (double, int). Each call has exactly one version that fits without promotion, so the compiler knows which to use.

  2. Explain why printLine(2, 5) does not compile, even though both methods exist and either could take two numbers.

    No version is an exact match for two int arguments. Promoting the first int fits (double, int), and promoting the second fits (int, double), so both match equally well; the compiler can't choose and reports the call as ambiguous.

Solution

MarketScale.java
public class MarketScale
{
    public static void main(String[] args)
    {
        printLine(3, 4.25);      // 3 mangoes at $4.25 each
        printLine(2.5, 360);     // 2.5 lb of cherries at 360 cents per lb
        printLine(2, 5.0);       // 2 pineapples at $5 each

        double total = lineTotal(3, 4.25) + lineTotal(2.5, 360) + lineTotal(2, 5.0);
        System.out.println("Total: $" + total);
    }

    // Sold by count: quantity, and price per item in dollars.
    public static void printLine(int quantity, double unitPrice)
    {
        System.out.println(quantity + " x $" + unitPrice + " = $" + lineTotal(quantity, unitPrice));
    }

    // Sold by weight: pounds, and price per pound in cents.
    public static void printLine(double pounds, int centsPerPound)
    {
        System.out.println(pounds + " lb x " + centsPerPound + "c = $" + lineTotal(pounds, centsPerPound));
    }

    public static double lineTotal(int quantity, double unitPrice)
    {
        return quantity * unitPrice;
    }

    public static double lineTotal(double pounds, int centsPerPound)
    {
        return pounds * centsPerPound / 100.0;
    }
}

Walkthrough

printLine(2, 5) has no exact match. Promoting the first int fits (double, int) and promoting the second fits (int, double), so the call is ambiguous and the program does not compile. printLine(2, 5.0) is an exact match for the by-count version. Beware printLine(2.0, 5): it compiles too, but matches the by-weight version and prints 2 pounds at 5 cents. A double printLine(int, double) next to void printLine(int, double) is illegal: the compiler chooses by arguments, never by return type. Hence a new name, lineTotal, with the same two parameter lists. Having printLine() reuse lineTotal() is optional, but keeps each formula in one place.

Messages students see when a check fails

C1 · The pineapple call is an exact match for the by-count version

Make the pineapple call an exact match for the by-count version: the quantity stays an int 2 and the price becomes a double, written with a decimal point. With two int arguments both versions fit after promotion, so the compiler can't choose. (Writing 2.0 for the quantity instead matches the by-weight version: 2 pounds at 5 cents.)

C2 · Two lineTotal() methods return double

Write two double methods named lineTotal, with the same two parameter lists as the printLine() versions, each returning its amount. Don't give a printLine() a return type: two methods with the same name and parameter list are illegal whatever they return, because the compiler chooses by arguments alone.

Hint:

Copy each printLine() header, then change the return type and the name.

C3 · The total adds three lineTotal() calls

Add the three line amounts by calling lineTotal() once for each item, and print the sum after Total: $.

Progressive hints

  1. Put the two parameter lists side by side. For printLine(2, 5), can the first int be promoted to double? Can the second? Which versions could then accept the call?

  2. An exact match removes the doubt. Keep the quantity an int and write the price so that Java reads it as a double literal.

  3. Overloads are told apart by their parameter lists only, so a method that returns the amount needs a name of its own. Its parameter lists can mirror printLine()'s.

Reflection: questions and model answers

  1. The two printLine() methods compiled fine before you added the pineapple line. When exactly does ambiguity become an error?

    Overloads with different parameter lists are not ambiguous on their own. The program fails only when it contains a call that matches more than one version equally well; without such a call, the methods coexist.

  2. Why can't the compiler use the return type to tell void printLine(int, double) apart from double printLine(int, double)?

    The compiler chooses a method from the arguments in the call, and a call need not use a returned value: printLine(3, 4.25); alone on a line would fit both. Methods with the same name and parameter list are therefore illegal, whatever their return types.

Extension
