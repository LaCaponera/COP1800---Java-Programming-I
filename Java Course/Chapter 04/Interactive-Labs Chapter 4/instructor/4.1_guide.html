The event hall's booking board

Objectives

  • Tell a class (the general description) from an object (one concrete instance), and state an is-a relationship in the right order
  • Send a message to an object: the object's name, a dot, the method and its arguments
  • Explain why every object of a class has the same methods but keeps its own values
  • Recognize a class client: a program that uses objects of a class written by someone else

Requirements

  1. R1 The anniversary's date and time are set by sending setDate() and setTime() to the anniversary object with its own arguments, "June 3" and "7 P.M."; the graduation stays May 12 at 6 P.M.
  2. R2 Every date and time on the board comes from asking that party object, with getDate() and getTime(); no date or time is typed into a println().
  3. R3 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. Which sentence is a correct is-a statement: "A Party is my graduation party" or "My graduation party is a Party"? Why is the other one wrong?

    "My graduation party is a Party." The object is one concrete example of the general class. The other sentence defines the whole class by a single example, which is backwards: a Party is more general than any one party.

  2. Read the starter's four booking lines. Which object receives all four messages, and what will graduation.getDate() return when the board prints?

    All four go to graduation, so its date is set to May 12 and then overwritten with June 3: getDate() returns "June 3". anniversary never receives a message.

Solution

EventBoard.java
public class EventBoard
{
    public static void main(String[] args)
    {
        Party graduation = new Party();
        Party anniversary = new Party();

        graduation.setDate("May 12");
        graduation.setTime("6 P.M.");
        anniversary.setDate("June 3");
        anniversary.setTime("7 P.M.");

        System.out.println("Seabright Event Hall bookings");
        System.out.println("Graduation: " + graduation.getDate() + " at "
            + graduation.getTime());
        System.out.println("Anniversary: " + anniversary.getDate() + " at "
            + anniversary.getTime());
    }
}

Walkthrough

The name before the dot decides which object receives the message. In the starter, all four set messages went to graduation, so its date was overwritten with June 3 and anniversary was never told anything. Both objects have the same methods because both are Party objects, but each keeps its own date and time, so the same setDate() stores May 12 in one and June 3 in the other. Asking each object with getDate() and getTime() means the board can never disagree with the bookings. EventBoard is a class client: it uses Party without knowing or changing how Party is written.

Progressive hints

  1. Read each booking line from left to right: the name before the dot is the object receiving the message, and the text in parentheses is the argument.

  2. anniversary has exactly the same methods as graduation, because both are Party objects. It needs its own two messages with its own arguments.

  3. For the board, each line should be built from the answers a party object gives, the way the graduation line already is.

Reflection: questions and model answers

  1. graduation and anniversary use the very same setDate() method. How can that one method store two different dates?

    Each object keeps its own date value. The method works on whichever object the message is sent to, with the argument sent in that call, so May 12 is stored in the graduation object and June 3 in the anniversary object.

  2. EventBoard uses Party but didn't create it. What does the reading call a class like EventBoard, and why is it useful that Party is written separately?

    A class client (or class user). Because Party is its own class, other programs, such as catering or ticketing, can create Party objects too without rewriting it; a client only needs to know the methods' names and arguments.
