The kayak tour that crashes on display

Objectives

  • Describe composition as a has-a relationship: an object of one class is a field of another
  • Construct a contained object, supplying arguments when it has no default constructor
  • Reuse a contained object's own methods instead of copying its work
  • Explain when a private inner (nested) class is a better fit than a separate class

Requirements

  1. R1 Tour's constructor gives each tour its own Guide by calling Guide's constructor with the guide's name and phone (Guide has no default constructor).
  2. R2 display() shows the guide by calling the contained guide's own display(); Tour does not print the guide's details itself.
  3. R3 The constructor also creates the tour's MeetingPoint, the private inner helper class, from the place and time.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. Read Tour's fields and complete the sentence: "A tour ___ a guide." Is that an is-a or a has-a relationship, and what is it called?

    A tour has a guide. It's a has-a relationship, called composition: an object of one class (Guide) is a data field of another (Tour).

  2. The starter compiles. What happens when the test calls sunrise.display(), and which fields cause it?

    It prints Tour: Sunrise Paddle and then crashes with a NullPointerException: meetingPoint (and guide) are reference fields that were never constructed, so they hold their default value, null.

Solution

Tour.java
public class Tour
{
    private String tourName;
    private Guide guide;
    private MeetingPoint meetingPoint;

    public Tour(String name, String guideName, String guidePhone,
        String place, String time)
    {
        tourName = name;
        guide = new Guide(guideName, guidePhone);
        meetingPoint = new MeetingPoint(place, time);
    }

    public void display()
    {
        System.out.println("Tour: " + tourName);
        guide.display();
        System.out.println("Meet at " + meetingPoint.place + ", "
            + meetingPoint.time);
    }

    // A helper class used only by Tour.
    private class MeetingPoint
    {
        private String place;
        private String time;

        public MeetingPoint(String place, String time)
        {
            this.place = place;
            this.time = time;
        }
    }
}

Walkthrough

private Guide guide; declares only a reference, which starts as null; calling a method through a null reference stops the program with a NullPointerException. The containing class must construct its contained objects, and since Guide's only constructor takes a name and a phone, Tour passes on the two values its own constructor received, as School does with NameAndAddress in Figure 4-37. guide.display() reuses Guide's own work, so a change to how guides are shown is made once, in Guide. MeetingPoint is constructed the same way. It is a private inner class because only Tour uses it; Tour may read its private place and time, but no other class can use it. Guide, needed by several classes, stays a separate class so it can be reused through composition.

Messages students see when a check fails

C1 · The constructor builds the tour's Guide with two arguments

In Tour's constructor, assign guide a new Guide built from guideName and guidePhone. A declared field holds only null until something constructs an object for it, and Guide has no default constructor, so its two arguments are required.

C2 · display() asks the guide to display itself

Show the guide by calling display() on the guide object. Tour has a Guide, so it reuses the guide's own method instead of printing a copy of its details.

Hint:

Figure 4-37: School.display() calls nameAdd.display().

C3 · The constructor builds the inner MeetingPoint

Also assign meetingPoint a new MeetingPoint built from place and time. An inner class is constructed like any other class; until it is, the field is null and display() crashes.

Progressive hints

  1. Declaring private Guide guide; creates only a reference, and it stays null until something constructs a Guide for it.

  2. Guide has one constructor, and it needs two arguments. Tour's constructor has already received both values.

  3. Tour shouldn't know how a guide is shown: ask the guide to show itself. The inner class is constructed the same way as any other.

Reflection: questions and model answers

  1. Guide is a separate public class, but MeetingPoint is a private inner class. Using the reading's reasoning, why is that a sensible split?

    Payroll and the lesson schedule also need guides, so Guide must be a regular class others can reuse through composition. MeetingPoint only helps Tour, so packaging it inside Tour keeps the connection obvious and hides it from other classes.

  2. display() reads meetingPoint.place even though place is private. Why is that allowed, and could TestTour do the same?

    An outer class can access its inner class's members, even private ones. TestTour can't: MeetingPoint is a private inner class, hidden from every class except Tour.
