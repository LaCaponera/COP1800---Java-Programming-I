The bouncing ball that never bounces back

Objectives

  • Pass what one line needs to the next call, as display(spaces, lines) does in Figure 12-19
  • Use statements after a recursive call, which run in reverse order as the calls finish
  • Choose base cases that draw a symmetric pattern with its middle row exactly once

Requirements

  1. R1 With 0 lines bounce() draws nothing; with 1 line it draws only the turning point, once, and does not call itself.
  2. R2 With more lines it draws its row, calls itself with one more space and one line fewer, and after that call draws its own row again: the way back.
  3. R3 bounce() repeats only by calling itself: no loop and no printing of its own; every row is drawn by drawRow().
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. The starter draws only the way down. For bounce(0, 3), list the calls with their spaces and lines, and say which call draws nothing.

    bounce(0,3), bounce(1,2), bounce(2,1) and bounce(3,0). The first three draw rows with 0, 1 and 2 spaces; bounce(3,0) is the base case and draws nothing.

  2. When bounce(2, 1) finishes, where does the program continue? What could a statement written after the recursive call do?

    It continues in bounce(1,2), right after its recursive call, and when that finishes, in bounce(0,3). A statement there runs as each call finishes, deepest first, so it could draw the rows with 1 and then 0 spaces: the way back.

Solution

Bounce.java
public class Bounce
{
    // Draws a ball moving right to the wall and bouncing back.
    // lines: rows down to the wall, counting the turning point.
    // spaces: how far from the left the first row starts.
    public static void bounce(int spaces, int lines)
    {
        if (lines <= 0)
            return;
        if (lines == 1)
        {
            drawRow(spaces);
            return;
        }
        drawRow(spaces);
        bounce(spaces + 1, lines - 1);
        drawRow(spaces);
    }

    // Draws one row: `spaces` spaces, then the ball.
    public static void drawRow(int spaces)
    {
        for (int x = 0; x < spaces; ++x)
            System.out.print(" ");
        System.out.println("O");
    }
}

Walkthrough

Like display() in Figure 12-19, each call passes what the next row needs (one more space, one line fewer), so each line uses knowledge from the previous one (p. 499). The new idea is where the second drawRow(spaces) goes: after the recursive call. A call doesn't finish until the call it made has finished (the reminders on the call stack, p. 490), so the statements after the call run deepest-first, in reverse: 1 space, then 0. That draws the way back. The turning point is a second base case: with one line left, a call draws its row once and stops. Without it, that call would draw its row, make a call that draws nothing, and draw the same row again, so the wall row would appear twice. if (lines == 1) ... else if or an else block instead of return are equally correct.

Messages students see when a check fails

C1 · The turning point is its own base case

Give the turning point its own case: when lines is 1, draw the row once and don't call bounce() again (or recurse and draw the way back only while lines > 1). Otherwise the row at the wall is drawn twice.

C2 · The row is drawn again after the call returns

Put a second drawRow(spaces) right after the recursive call. It runs when the deeper calls have finished, in reverse order, which draws the way back.

C3 · Each call moves right and down

Keep the recursive call as bounce(spaces + 1, lines - 1): one more space and one line fewer, like display(spaces, lines - 1) after spaces++ in Figure 12-19.

C4 · No loop or printing in bounce()

Let bounce() repeat by calling itself and draw every row with drawRow(). A loop here would hide the idea the lab is about: the way back comes from the calls finishing.

Progressive hints

  1. Each call already knows its own spaces. When does each call get control back, and what is still left for it to do then?

  2. Code placed after the recursive call runs on the way back, deepest call first, just as the waiting sumNumbers() calls finish in reverse order (pp. 490–491).

  3. The call with one line left is the wall: it draws its row once and doesn't call itself. Every other call draws its row, makes the recursive call, then draws the same row again.

Reflection: questions and model answers

  1. Explain why the rows drawn after the recursive call come out in the reverse order of the rows drawn before it.

    Each call waits on the call stack until the call it made returns. The deepest call returns first, so the statements after the call run deepest-first: 1 space, then 0, the mirror of the way down.

  2. What would your method draw if you removed the special case for one line, and why?

    The wall row would appear twice. With one line left the call would draw its row, call bounce with 0 lines (which draws nothing), and then draw the same row again on the way back.

Extension

Add a char ball parameter to drawRow() and bounce() so the way down uses O and the way back uses o. Then make the ball step 2 columns per row. Which single argument changes, and does the turning point still need its own case?
