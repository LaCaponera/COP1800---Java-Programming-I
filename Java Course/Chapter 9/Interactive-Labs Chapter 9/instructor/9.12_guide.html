COP1800 · Java Programming I · Lab 9.12

The e-bike that couldn't be rented

Objectives

  • Explain why Java doesn't allow a class to extend two classes
  • Write an interface with abstract methods and a constant, and implement it with implements
  • Write a class header that both extends a class and implements an interface

Requirements

  1. R1 Rentable is an interface that keeps the LATE_FEE_PER_DAY constant and the dailyRate() and rentalTag() methods.
  2. R2 Kayak implements Rentable and extends nothing.
  3. R3 ElectricBike extends Bicycle and implements Rentable, and its rentalTag() returns, for example, E-bike, 54 cm frame, 60 km range from its frame size and range.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. Why can't the starter's ElectricBike be written as extends Bicycle, Rentable or given a second extends?

    Java allows only one superclass per class. ElectricBike already extends Bicycle, so it can't also extend the abstract class Rentable.

  2. Read the starter's Rentable. What does it contain that a subclass could inherit and reuse, besides the constant?

    Nothing: both methods are abstract and there are no fields or method bodies. It only lists what a rentable item must be able to do, so it might as well be an interface.

    // day the item comes back late.

Solution

Rentable.java
public interface Rentable
{
    public static final double LATE_FEE_PER_DAY = 5.0;

    public abstract double dailyRate();

    public abstract String rentalTag();
}
Kayak.java
public class Kayak implements Rentable
{
    private int lengthFeet;

    public Kayak(int feet)
    {
        lengthFeet = feet;
    }

    @Override
    public double dailyRate()
    {
        return 35.0;
    }

    @Override
    public String rentalTag()
    {
        return "Kayak, " + lengthFeet + " ft";
    }
}
ElectricBike.java
public class ElectricBike extends Bicycle implements Rentable
{
    private int rangeKm;

    public ElectricBike(int frameSize, int range)
    {
        super(frameSize);
        rangeKm = range;
    }

    @Override
    public double dailyRate()
    {
        return 28.0;
    }

    @Override
    public String rentalTag()
    {
        return "E-bike, " + getFrameCm() + " cm frame, " + rangeKm + " km range";
    }
}

Walkthrough

Java prohibits multiple inheritance: a class can't extend two classes (p. 371). An interface is the alternative: its methods are implicitly public and abstract and its data is implicitly public, static and final (p. 371), so the keywords in Rentable may be written or left out. A class uses it with implements, and must implement every method (p. 371). ElectricBike extends Bicycle implements Rentable follows the convention that implements comes after extends (p. 372), like WorkingDog extends Dog implements Worker. An interface constant is shared by every class that uses it without being redeclared (pp. 374–375), so RentalCounter reads Rentable.LATE_FEE_PER_DAY. Rentable has no data or method bodies to inherit, which fits the advice on p. 374 for choosing an interface over an abstract class. An array of interface references, Rentable[], can hold any implementing objects.

Test program

Students run it in an IDE and paste the output into the page.

TestRentals.java
public class TestRentals
{
    public static void main(String[] args)
    {
        Kayak tandem = new Kayak(14);
        ElectricBike city = new ElectricBike(54, 60);

        Rentable[] fleet = new Rentable[2];
        fleet[0] = tandem;
        fleet[1] = city;
        for (int x = 0; x < fleet.length; ++x)
            System.out.println(fleet[x].rentalTag() + ": 3 days $"
                + RentalCounter.quote(fleet[x], 3, 0));

        System.out.println("E-bike back 2 days late: $" + RentalCounter.quote(city, 3, 2));
        System.out.println("Is a Bicycle: " + (city instanceof Bicycle)
            + ", is Rentable: " + (city instanceof Rentable));
    }
}

Messages students see when a check fails

C1 · Rentable is an interface

Write the header as public interface Rentable. Its methods are then automatically public and abstract, and the late fee automatically public, static and final.

C2 · Kayak implements Rentable

Change extends Rentable to implements Rentable. A class extends classes and implements interfaces.

C3 · ElectricBike is a Bicycle and Rentable

Write the header as public class ElectricBike extends Bicycle implements Rentable: the extends clause comes first, then implements.

C4 · ElectricBike has a rentalTag()

Add public String rentalTag() that builds the tag from getFrameCm() (inherited from Bicycle) and rangeKm. The method must be public, because interface methods are public.

Progressive hints

  1. Change Rentable's header first. In an interface, the abstract keywords become optional, and so does public static final on the constant.

  2. A class implements an interface with implements. For ElectricBike, keep extends Bicycle and add the interface after it.

  3. The frame size is private in Bicycle, so the tag gets it with getFrameCm(); the range is ElectricBike's own field.

Reflection: questions and model answers

  1. Why is an interface the right choice for Rentable here, while Bicycle stays a class?

    Rentable only states which methods a rentable item must have and shares a constant, and unrelated items (kayaks, e-bikes) need it alongside their own superclass. Bicycle has real data and behaviour that subclasses reuse, so it stays a class.

  2. city instanceof Rentable is true even though ElectricBike doesn't extend Rentable. What relationship does implements create?

    Implementing an interface is an “is a” relationship too: an ElectricBike is a Bicycle and is a Rentable, so it can be stored in a Rentable variable or array and passed to quote().
