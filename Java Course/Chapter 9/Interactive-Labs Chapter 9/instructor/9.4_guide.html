COP1800 · Java Programming I · Lab 9.4

The hotel suites that won't compile

Objectives

  • Predict the order in which parent and child constructors run
  • Call a parent constructor that requires arguments with super(...) as the first statement
  • Write a child constructor that passes a constant to its parent

Requirements

  1. R1 Suite's constructor passes the room number and rate to Room with super(...) as its first statement, then sets bedrooms itself.
  2. R2 StaffRoom has a constructor with one parameter, the room number, that calls super(...) with that number and a rate of 0.0.
  3. R3 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. Read Room.java. Can you write new Room() with no arguments? Why does that matter for Suite?

    No: Room's only constructor requires a number and a rate, and writing it removed the automatic default constructor. Suite's constructor implicitly calls Room() unless told otherwise, so it fails to compile.

  2. When new Suite("501", 349.0, 2) runs, which constructor's message prints first, Room's or Suite's?

    Room's. The superclass constructor always runs before the subclass constructor's own statements.

Starter files

public class Room
{
    private String number;
    private double nightlyRate;

    // Every room must be created with a number and a nightly rate.
    public Room(String roomNumber, double rate)
    {

        nightlyRate = rate;

    }

    public String getNumber()
    {
        return number;
    }

    public double getNightlyRate()
    {
        return nightlyRate;
    }
}

Solution

Suite.java
public class Suite extends Room
{
    private int bedrooms;

    public Suite(String roomNumber, double rate, int numBedrooms)
    {
        super(roomNumber, rate);
        bedrooms = numBedrooms;
        System.out.println("  Suite " + getNumber() + " has " + bedrooms + " bedrooms");
    }

    public int getBedrooms()
    {
        return bedrooms;
    }
}
StaffRoom.java
public class StaffRoom extends Room
{
    public StaffRoom(String roomNumber)
    {
        super(roomNumber, 0.0);
    }
}

Walkthrough

Creating a subclass object runs the superclass constructor first, then the subclass constructor (p. 339), which is why “Room 501 registered” prints before “Suite 501 has 2 bedrooms”. A constructor that doesn't call super(...) gets an automatic call to the parent's no-argument constructor; Room has none, so the starter fails to compile, like Figure 9-9 (p. 343). When a superclass has only constructors that require arguments, each subclass constructor must call one with super(arguments) as its first statement (pp. 340–341, Table 9-1). The child constructor need not match the parent's parameters: StaffRoom(String) passes a constant 0.0, like the HourlyEmployee() example on p. 341. Java does not allow Room(...) by name; you must write super.

Messages students see when a check fails

C1 · Suite calls super(number, rate) first

Make super(roomNumber, rate); the very first statement of the Suite constructor, before setting bedrooms. Java doesn't let you call Room(...) by name; use super.

Hint:

Only comments may come before super(...) in a constructor.

C2 · StaffRoom passes a $0.0 rate to Room

Write public StaffRoom(String roomNumber) whose first statement is super(roomNumber, 0.0);. The child constructor's parameters don't have to match the parent's; it only has to pass what Room needs.

Progressive hints

  1. Compile the starter and read the first error: which constructor is Java looking for, and in which class?

  2. In Suite, the parent's two values are already parameters: roomNumber and rate. Hand them to super(...).

  3. StaffRoom takes one parameter but Room needs two. The second one is a constant you know.

Reflection: questions and model answers

  1. Why must the Room part of a Suite be built before the Suite part? Use getNumber() in the Suite constructor as your example.

    The Suite constructor calls getNumber(), which reads Room's number field. That field only has a value once Room's constructor has run, so the parent must be built first.

  2. StaffRoom's constructor has one parameter while Room's has two. Why is that allowed?

    A child constructor only has to call super(...) with the arguments the parent needs. It can supply them from its own parameters or from constants, so StaffRoom passes its number plus 0.0.

Extension

Give Room a second constructor Room(String roomNumber) that calls this(roomNumber, 99.0). Now which subclass constructors still need super(...), according to Table 9-1? Then try putting bedrooms = numBedrooms; above super(...) and read the error.
