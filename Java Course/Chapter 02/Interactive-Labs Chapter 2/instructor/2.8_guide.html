The episode-length converter

Objectives

  • Use integer division to count whole hours and minutes
  • Use the remainder operator % to find what's left over
  • Predict results from precedence and left-to-right associativity
  • Use parentheses to make an addition happen before a division

Requirements

  1. R1 SECONDS_PER_HOUR (3600) and SECONDS_PER_MINUTE (60) are named constants, and no calculation uses the numbers 3600 or 60 directly.
  2. R2 Each episode is broken into whole hours, the remaining whole minutes and the remaining seconds with / and %, reusing hours, minutes and seconds.
  3. R3 The average adds both lengths before dividing by 2.
  4. R4 With the input 7385 and 5415, the output matches the test program's expected output. (verified by the program output)

Before you code: warm-up and model answers

  1. Compute by hand: 7385 / 3600 and 7385 % 3600. What does each result mean for the episode?

    7385 / 3600 is 2 (integer division drops the fraction): the episode has 2 whole hours. 7385 % 3600 is 185: the seconds left over after those 2 hours.

  2. The starter computes firstSeconds + secondSeconds / 2. What does it give for 7385 and 5415, and why?

    1. Division has higher precedence than addition, so secondSeconds / 2 (2707) is computed first and then added to 7385, instead of averaging the two lengths.

Solution

EpisodeLength.java
import java.util.Scanner;

public class EpisodeLength
{
    public static void main(String[] args)
    {
        final int SECONDS_PER_HOUR = 3600;
        final int SECONDS_PER_MINUTE = 60;
        int firstSeconds;
        int secondSeconds;
        int hours;
        int minutes;
        int seconds;
        int averageSeconds;
        Scanner input = new Scanner(System.in);

        System.out.print("Episode 1 length in seconds >> ");
        firstSeconds = input.nextInt();
        System.out.print("Episode 2 length in seconds >> ");
        secondSeconds = input.nextInt();
        System.out.println();

        hours = firstSeconds / SECONDS_PER_HOUR;
        minutes = firstSeconds % SECONDS_PER_HOUR / SECONDS_PER_MINUTE;
        seconds = firstSeconds % SECONDS_PER_MINUTE;
        System.out.println("Episode 1: " + hours + " h " + minutes + " min " +
            seconds + " s");

        hours = secondSeconds / SECONDS_PER_HOUR;
        minutes = secondSeconds % SECONDS_PER_HOUR / SECONDS_PER_MINUTE;
        seconds = secondSeconds % SECONDS_PER_MINUTE;
        System.out.println("Episode 2: " + hours + " h " + minutes + " min " +
            seconds + " s");

        averageSeconds = (firstSeconds + secondSeconds) / 2;
        System.out.println("Average length: " + averageSeconds + " s");
    }
}

Walkthrough

Both operands are int, so / is integer division and drops the fraction: 7385 / 3600 is 2 whole hours. 7385 % 3600 is the 185 seconds left over, and since % and / have the same precedence and run left to right, 7385 % 3600 / 60 is 185 / 60, 3 minutes. 7385 % 60 gives the 5 seconds that don't fill a minute. In the starter's average, / runs before +, so it computed 7385 + 2707 = 10092; parentheses make the addition happen first: 12800 / 2 = 6400.

Messages students see when a check fails

C1 · Both conversion factors are named constants

Declare final int SECONDS_PER_HOUR = 3600; and final int SECONDS_PER_MINUTE = 60; at the start of main(). The names say what the numbers mean.

C2 · No calculation uses 3600 or 60 directly

Replace each 3600 or 60 in a calculation with its constant, including the starter's firstSeconds / 3600.

C3 · Minutes and seconds use % and /, for both episodes

For each episode: the remaining minutes need both operators (the remainder after whole hours, divided by the seconds in a minute), and the remaining seconds are the remainder after dividing by SECONDS_PER_MINUTE.

Hint:

Work 7385 through by hand: how many seconds are left after the 2 whole hours? How many whole minutes is that?

C4 · Episode 2 is converted and printed

Repeat the three calculations with secondSeconds, assigning them to the same hours, minutes and seconds variables, then print the Episode 2: line in the same format.

C5 · The average adds before it divides

Division has higher precedence than addition, so the starter divides only secondSeconds by 2. Put the sum in parentheses so it's computed first, then divide by 2.

Hint:

Compute the starter's version by hand with 7385 and 5415. Which operation ran first?

Progressive hints

  1. Work through 7385 seconds by hand: whole hours first, then what's left over, then whole minutes in what's left, then what's left after that.

  2. / with two integers gives the whole number of times one fits into the other; % gives what's left over. You need both for the minutes.

  3. *, / and % run before + and -. When you need an addition to happen first, give it parentheses.

Reflection: questions and model answers

  1. Explain how firstSeconds % SECONDS_PER_HOUR / SECONDS_PER_MINUTE is evaluated, step by step, for 7385. Which rule decides the order?

    % and / have the same precedence and associate left to right, so 7385 % 3600 runs first, giving 185, and then 185 / 60 gives 3 whole minutes.

  2. If the two episodes were 7385 and 5416 seconds, the true average is 6400.5. What does your program print, and why?

    1. (7385 + 5416) / 2 divides two integers, so Java performs integer division and drops the .5. To keep it, at least one operand would need to be a floating-point value.
