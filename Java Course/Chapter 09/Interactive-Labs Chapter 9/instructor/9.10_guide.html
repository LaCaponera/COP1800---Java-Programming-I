COP1800 · Java Programming I · Lab 9.10

The clinic payroll that only pays doctors

Objectives

  • Create an array of superclass references, even when the superclass is abstract
  • Store objects of different subclasses in the same array
  • Loop through the array and let each element run its own version of a method

Requirements

  1. R1 Payroll keeps one Employee[] array (created with new Employee[capacity]) and hire() accepts any Employee.
  2. R2 printPayStubs() and totalWeeklyPay() call weeklyPay() on each element; nothing in Payroll mentions a salary.
  3. R3 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. Compile the starter with the test program. Which line fails first, and what does the message say about types?

    clinic.hire(new HourlyEmployee(...)) fails: an HourlyEmployee cannot be converted to a SalariedEmployee, because hire() and the array only accept salaried staff.

  2. Employee is abstract, so new Employee("X") is illegal. Is new Employee[5] legal? What does it create?

    Yes. It creates an array of five Employee references, all null at first. No Employee objects are created.

Starter files

Payroll.java
// Written when the clinic paid salaried staff only.
public class Payroll
{
    // TODO (R1): hourly staff and contractors don't fit in this array.
    private SalariedEmployee[] staff;
    private int count;

    public Payroll(int capacity)
    {
        staff = new SalariedEmployee[capacity];
    }

    // TODO (R1): accept any kind of employee.
    public void hire(SalariedEmployee worker)
    {
        staff[count] = worker;
        ++count;
    }

    // One line per employee, in hiring order.
    public void printPayStubs()
    {
        for (int x = 0; x < count; ++x)
        {
            // TODO (R2): only salaried staff have an annual salary.
            System.out.println(staff[x].getName() + ": $" + staff[x].getAnnualSalary() / 52);
        }
    }

    public double totalWeeklyPay()
    {
        double total = 0.0;
        for (int x = 0; x < count; ++x)
        {
            // TODO (R2)
            total += staff[x].getAnnualSalary() / 52;
        }
        return total;
    }
}

SalariedEmployee.java (read-only for students)
public class SalariedEmployee extends Employee
{
    private double annualSalary;

    public SalariedEmployee(String fullName, double salary)
    {
        super(fullName);
        annualSalary = salary;
    }

    public double getAnnualSalary()
    {
        return annualSalary;
    }

    @Override
    public double weeklyPay()
    {
        return annualSalary / 52;
    }

Solution

Payroll.java
public class Payroll
{
    private Employee[] staff;
    private int count;

    public Payroll(int capacity)
    {
        staff = new Employee[capacity];
    }

    public void hire(Employee worker)
    {
        staff[count] = worker;
        ++count;
    }

    // One line per employee, in hiring order.
    public void printPayStubs()
    {
        for (int x = 0; x < count; ++x)
        {
            System.out.println(staff[x].getName() + ": $" + staff[x].weeklyPay());
        }
    }

    public double totalWeeklyPay()
    {
        double total = 0.0;
        for (int x = 0; x < count; ++x)
        {
            total += staff[x].weeklyPay();
        }
        return total;
    }
}

Walkthrough

Creating an array of objects creates space for references, not objects (p. 361), so new Employee[capacity] is legal even though Employee is abstract, like new Animal[3] on p. 361. An array of superclass references can hold subclass references (p. 361), so one array keeps every employee in hiring order. Because every subclass implements weeklyPay(), a loop over the array can call it on each element and the right version runs for each object (pp. 361–362, Figure 9-40). getAnnualSalary() exists only in SalariedEmployee, so it can't be called through an Employee reference: the compiler forces the switch to weeklyPay().

Messages students see when a check fails

C1 · One Employee[] array

Declare the field as private Employee[] staff; and create it with new Employee[capacity]. A superclass array can hold salaried, hourly and contract employees alike.

C2 · hire() accepts any Employee

Change the parameter to Employee worker, so the clinic can hire any kind of employee.

C3 · Pay stubs use each employee's weeklyPay()

Print staff[x].weeklyPay(). Each element runs its own class's version, so salaried, hourly and contract staff are all paid correctly.

C4 · The total uses weeklyPay() too

Add staff[x].weeklyPay() to the total. Only salaried staff have an annual salary; every employee has a weekly pay.

Progressive hints

  1. Three places name SalariedEmployee: the field, the new expression and the hire() parameter. All three should name the superclass.

  2. Once the array is Employee[], getAnnualSalary() stops compiling. Which method does every Employee have?

  3. Each loop body ends up calling staff[x].weeklyPay().

Reflection: questions and model answers

  1. Someone suggests three arrays instead: one for salaried, one for hourly and one for contract staff. Give two reasons one Employee[] array is better here.

    One array keeps everyone in hiring order, which the pay stubs need, and one loop handles every type. With three arrays, every new employee type means another array, another hire method and another loop.

  2. The loop calls staff[x].weeklyPay() on an Employee reference. How does Java know to divide by 52 for Dr. Okafor but multiply hours for Marisol?

    Each element refers to an object of a specific subclass, and Java runs that object's weeklyPay() at run time. Dr. Okafor's object is a SalariedEmployee and Marisol's is an HourlyEmployee.
