COP1800 · Java Programming I · Lab 9.2

The VIP who was sent to the general line

Objectives

  • Use extends so a subclass receives its parent's fields and methods
  • Put a field and its methods in the most specific class that needs them
  • Use instanceof to test whether an object is a member of a class

Requirements

  1. R1 Ticket has no vouchers at all. VipTicket declares private int vouchers and the methods getVouchers(), setVouchers(int) and useVoucher().
  2. R2 Gate.laneFor() sends a ticket to the VIP lane when it is a VipTicket (use instanceof), whatever its voucher count.
  3. R3 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. In the starter, a general ticket for seat F12 calls getVouchers(). What does it return, and does that number mean anything?

    It returns 0. The number means nothing, because general tickets never come with vouchers; the field shouldn't exist for them.

  2. The starter's laneFor() tests t.getVouchers() > 0. Describe a VIP ticket for which this test gives the wrong lane.

    A VIP ticket whose vouchers have all been used (count 0), or one that was sold without vouchers. The test says General lane even though it is a VIP ticket.

Solution

Ticket.java
public class Ticket
{
    private String seat;
    private double price;

    public String getSeat()
    {
        return seat;
    }

    public double getPrice()
    {
        return price;
    }

    public void setSeat(String seatCode)
    {
        seat = seatCode;
    }

    public void setPrice(double amount)
    {
        price = amount;
    }
}
VipTicket.java
public class VipTicket extends Ticket
{
    private int vouchers;

    public int getVouchers()
    {
        return vouchers;
    }

    public void setVouchers(int count)
    {
        vouchers = count;
    }

    public void useVoucher()
    {
        if (vouchers > 0)
            --vouchers;
    }
}
Gate.java
public class Gate
{
    // Sends each ticket holder to the right entrance lane.
    public static String laneFor(Ticket t)
    {
        if (t instanceof VipTicket)
            return "VIP lane";
        else
            return "General lane";
    }
}

Walkthrough

VipTicket extends Ticket, so it already has a seat, a price and their get and set methods; it only adds what is particular to it, as DinnerParty adds dinnerChoice to Party (pp. 335–336). Inheritance is one-way: a parent can't use its child's members, and it shouldn't carry fields that only some children need (p. 333). instanceof is true when the object on the left is a member or descendant of the class on the right (p. 333), so t instanceof VipTicket is true for every VIP ticket, used vouchers or not. Once Ticket has no getVouchers(), the starter's laneFor() no longer compiles, which forces the change. Passing a VipTicket to a Ticket parameter works because every VipTicket is a Ticket; section 9.9 explains this in detail.

Test program

TestGate.java
public class TestGate
{
    public static void main(String[] args)
    {
        Ticket general = new Ticket();
        general.setSeat("F12");
        general.setPrice(45.0);

        VipTicket vip = new VipTicket();
        vip.setSeat("A3");
        vip.setPrice(180.0);
        vip.setVouchers(2);
        vip.useVoucher();
        vip.useVoucher();
        vip.useVoucher();

        System.out.println("Seat " + general.getSeat() + ", $" + general.getPrice()
            + ": " + Gate.laneFor(general));
        System.out.println("Seat " + vip.getSeat() + ", $" + vip.getPrice()
            + ", vouchers left " + vip.getVouchers() + ": " + Gate.laneFor(vip));
        System.out.println("A VipTicket is a Ticket: " + (vip instanceof Ticket));
        System.out.println("A Ticket is a VipTicket: " + (general instanceof VipTicket));
    }
}

Messages students see when a check fails

C1 · Ticket knows nothing about vouchers

Remove the vouchers field and getVouchers(), setVouchers() and useVoucher() from Ticket. A general ticket has no vouchers, and a parent class shouldn't hold what only one child needs.

C2 · VipTicket holds the vouchers

Declare private int vouchers; in VipTicket. Don't redeclare the seat or the price: VipTicket inherits them from Ticket.

C3 · VipTicket has the three voucher methods

Move getVouchers(), setVouchers(int) and useVoucher() into VipTicket, with the same headers they had in Ticket.

C4 · The gate checks the kind of ticket

Test t instanceof VipTicket. Being a VIP depends on the kind of ticket, not on how many vouchers are left.

Hint:

instanceof is written in lowercase, with the object on the left and the class on the right.

Progressive hints

  1. Cut the field and its three methods from Ticket and paste them into VipTicket. Nothing else in Ticket changes.

  2. After the move, t.getVouchers() no longer compiles in Gate: a plain Ticket has no such method. That's the line to replace.

  3. The condition you need is an instanceof expression with t on the left and the VIP class on the right.

Reflection: questions and model answers

  1. Why is instanceof VipTicket a better test than counting vouchers? Use seat A3 in your answer.

    Seat A3 is a VIP ticket whatever happens to its vouchers. instanceof asks what the object is, which never changes; the voucher count changes as the guest uses vouchers, so it can't identify a VIP.

  2. vip instanceof Ticket is true but general instanceof VipTicket is false. Explain why in terms of “is a”.

    Every VipTicket is a Ticket because it extends Ticket, but a plain Ticket is not a VipTicket. Inheritance goes one way, from parent to child.
