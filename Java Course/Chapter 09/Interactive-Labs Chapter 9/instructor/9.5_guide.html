COP1800 · Java Programming I · Lab 9.5

The insured parcel that never finishes printing

Objectives

  • Call an overridden parent method from the child with super.methodName()
  • Explain the difference between label(), this.label() and super.label() inside an override
  • Extend a parent's result instead of copying its formula

Requirements

  1. R1 InsuredShipment.totalCost() returns the parent's totalCost() plus insuranceFee(); it repeats no rates or formulas from Shipment.
  2. R2 InsuredShipment.label() returns the parent's label() followed by , insured for $ and the insured value.
  3. R3 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. Inside InsuredShipment.label(), the starter calls label(). Which class's label() is that, and what happens next?

    It is InsuredShipment's own label(), the method that is running. It calls itself, which calls itself again, forever, until Java throws a StackOverflowError.

  2. For a 2.0 kg parcel insured for $500.0, what does the starter's totalCost() return, and what should it return?

    The starter returns 5.0 + 8.0 + 10.0 = 23.0. It should return Shipment's 5.0 + 9.0 = 14.0 plus the 10.0 fee, which is 24.0.

Starter files

Shipment.java (read-only for students)
public class Shipment
{
    private int trackingNumber;
    private String city;
    private double weightKg;

    public Shipment(int number, String destination, double kg)
    {
        trackingNumber = number;
        city = destination;
        weightKg = kg;
    }

    public double getWeightKg()
    {
        return weightKg;
    }

    // Base fee plus a rate per kilogram (the per-kg rate rose to 4.5 in March).
    public double totalCost()
    {
        return 5.0 + weightKg * 4.5;
    }

    public String label()
    {
        return "Shipment #" + trackingNumber + " to " + city + ", " + weightKg + " kg";
    }
}
InsuredShipment.java
public class InsuredShipment extends Shipment
{
    private double insuredValue;

    public InsuredShipment(int number, String destination, double kg, double value)
    {
        super(number, destination, kg);
        insuredValue = value;
    }

    // Insurance costs 2% of the declared value.
    public double insuranceFee()
    {
        return insuredValue * 0.02;
    }

    @Override
    public double totalCost()
    {
        // TODO (R1): copied from Shipment last winter. Reuse the parent's
        // shipping cost instead, then add the insurance fee.
        return 5.0 + getWeightKg() * 4.0 + insuranceFee();
    }

    @Override
    public String label()
    {
        // TODO (R2): meant to reuse Shipment's label and add the insurance.
        return label() + ", insured for $" + insuredValue;
    }
}

Solution

InsuredShipment.java
public class InsuredShipment extends Shipment
{
    private double insuredValue;

    public InsuredShipment(int number, String destination, double kg, double value)
    {
        super(number, destination, kg);
        insuredValue = value;
    }

    // Insurance costs 2% of the declared value.
    public double insuranceFee()
    {
        return insuredValue * 0.02;
    }

    @Override
    public double totalCost()
    {
        return super.totalCost() + insuranceFee();
    }

    @Override
    public String label()
    {
        return super.label() + ", insured for $" + insuredValue;
    }
}

Walkthrough

When a child overrides a method but still needs the parent's version, it calls super.methodName() (p. 344), as PreferredCustomer.display() calls super.display() in Figure 9-11. Inside the override, plain label() and this.label() both mean the child's own version (p. 345), so the starter's label() calls itself again and again until the call stack runs out: a StackOverflowError. super.totalCost() reuses Shipment's current formula, so the March price change reaches insured parcels too. Unlike a super(...) constructor call, super.method() does not have to be the first statement (p. 344); here it is part of the return expression.

Messages students see when a check fails

C1 · totalCost() builds on the parent's cost

Return super.totalCost() + insuranceFee(). Copying Shipment's formula means every future price change has to be made twice, and this copy already missed one.

C2 · label() calls the parent's label()

Write super.label() to get Shipment's text. Without super, label() means this same method, so it calls itself until the program crashes.

Hint:

Which keyword means “my parent's version”?

Progressive hints

  1. Both overrides need the same move: get the parent's result first, then add the part that is new.

  2. Shipment's fields are private, so you can't rebuild its label yourself. Ask the parent class for it.

  3. The keyword super, then a dot, then the method name calls the parent's version of an overridden method.

Reflection: questions and model answers

  1. Explain why return label() + ... inside label() crashes, but return super.label() + ... works.

    Inside the override, label() refers to the child's own method, so it calls itself endlessly and fills the call stack. super.label() runs Shipment's version, which returns a string and ends.

  2. Shipping prices will change again next year. Why is super.totalCost() safer than writing the formula into InsuredShipment?

    The formula then lives only in Shipment. When it changes, insured parcels automatically use the new price; a copy would have to be found and changed by hand, which is how the $4.0 rate survived.
