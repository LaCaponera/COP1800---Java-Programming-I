The beach heat alert that waits for 35 degrees

Objectives

  • Replace a data-only class with a record and use its generated accessors, equals() and toString()
  • Implement an interface with an anonymous inner class that uses an effectively final variable
  • Implement a functional interface with a lambda expression

Requirements

  1. R1 Reading is a record with the components String station and double celsius.
  2. R2 heatRule(limit) returns an anonymous inner class that implements Rule and triggers when the reading is at or above limit; the HeatRule class is removed.
  3. R3 freezeRule() returns a lambda expression that triggers when the reading is below 0.0.
  4. R4 Running the test program prints exactly what it expects (records need Java 16 or later). (verified by the program output)

Before you code: warm-up and model answers

  1. With the starter, how many of today's readings does heatRule(32.0) count, and why is the 33.5 at Pier 3 missed?

    It counts 1 (only 36.0). HeatRule ignores the limit parameter and always compares with 35.0, so 33.5 never triggers.

  2. Rule has exactly one abstract method. Why does that matter for writing freezeRule()?

    An interface with one abstract method is a functional interface, so a lambda expression can implement it; Java knows the lambda is the body of triggers().

Solution

Reading.java
public record Reading(String station, double celsius)
{
}
Monitor.java
public class Monitor
{
    // How many readings trigger the rule.
    public static int count(Reading[] readings, Rule rule)
    {
        int total = 0;
        for (int x = 0; x < readings.length; ++x)
        {
            if (rule.triggers(readings[x]))
                ++total;
        }
        return total;
    }

    // A heat rule with each station's own limit: the beach uses 32.0,
    // inland stations use 35.0.
    public static Rule heatRule(double limit)
    {
        Rule rule = new Rule()
        {
            @Override
            public boolean triggers(Reading r)
            {
                return r.celsius() >= limit;
            }
        };
        return rule;
    }

    public static Rule freezeRule()
    {
        return r -> r.celsius() < 0.0;
    }
}

Walkthrough

A record (Java 16 and later) declares a class that only holds unchanging data: you list the components and Java generates private final fields, a public constructor, an accessor named after each component (no get prefix), and equals(), hashCode() and toString() (pp. 378–379). That is why today[0] now prints its values and two readings with the same values are equal. An anonymous inner class is created and instantiated in one new expression, implements the interface without the word implements, and must end with a semicolon (pp. 379–380). It may use limit because the parameter is effectively final: assigned once (p. 380). Rule has one abstract method, so it is a functional interface and a lambda can implement it: r -> r.celsius() < 0.0 (p. 380). A one-line body needs no braces (p. 380). Reading 0.0 is not below freezing, so the freeze count is 1.

public class TestMonitor
{
    public static void main(String[] args)
    {
        Reading[] today = new Reading[5];
        today[0] = new Reading("Pier 3", 33.5);
        today[1] = new Reading("Pier 3", 36.0);
        today[2] = new Reading("Dunes", -1.5);
        today[3] = new Reading("Dunes", 0.0);
        today[4] = new Reading("Marina", 31.0);

        System.out.println("First reading: " + today[0]);
        Reading copy = new Reading("Pier 3", 33.5);
        System.out.println("Same values, same reading? " + today[0].equals(copy));
        Rule beach = Monitor.heatRule(32.0);
        Rule inland = Monitor.heatRule(35.0);
        System.out.println("At or above 32.0 C: " + Monitor.count(today, beach));
        System.out.println("At or above 35.0 C: " + Monitor.count(today, inland));
        System.out.println("Below freezing: " + Monitor.count(today, Monitor.freezeRule()));
        System.out.println("Dunes low: " + today[2].celsius() + " C at " + today[2].station());
    }
}

Messages students see when a check fails

C1 · Reading is a record

Replace the class with public record Reading(String station, double celsius) { }. The constructor, the accessors station() and celsius(), equals() and toString() are generated for you.

C2 · heatRule() uses an anonymous inner class

Return new Rule() { ... } with a triggers() method that compares r.celsius() >= limit. The anonymous class can read limit because the parameter is never reassigned.

Hint:

The class body follows new Rule() directly, and the whole expression ends with a semicolon.

C3 · The HeatRule class is gone

Delete the HeatRule class at the bottom of Monitor.java. It was only ever used once, and it ignored the limit.

C4 · freezeRule() returns a lambda

Return a lambda such as r -> r.celsius() < 0.0. The parameter r is the Reading that triggers() receives.

Progressive hints

  1. A record's whole declaration is its header plus empty braces. Keep the component names: Monitor and the test call celsius() and station().

  2. Model the anonymous class on Figure 9-69: Rule rule = new Rule() { public boolean triggers(Reading r) { ... } }; then return it.

  3. A lambda with one parameter can be written r -> expression; the expression is what triggers() returns.

Reflection: questions and model answers

  1. Converting Reading to a record changed two lines of the output without any other code changing. Which two, and what did the record add that caused it?

    The first line now shows the station and temperature, and “Same values” is true. The record generated toString() and equals() based on its components.

  2. Both new rules implement Rule. Why could the heat rule use either an anonymous class or a lambda, while a separate named HeatRule class was the worst choice?

    Rule is a functional interface, so either form works and both can use the limit. A named class needs its own file or declaration for code used once, and this one hard-coded 35.0 instead of receiving the limit.

Extension

Rewrite heatRule() as a lambda too, then add public static Rule stationRule(String name) that triggers for readings from one station (compare with equals()). Finally try adding limit = limit + 1; at the top of heatRule() and read the error: what does “effectively final” mean?
