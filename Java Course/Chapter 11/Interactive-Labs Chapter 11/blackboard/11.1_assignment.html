Lab 11.1: The visit counter that starts over every morning

A value in RAM is volatile; a file on disk persists

Estimated time: about 20 minutes. Reading: Ch. 11, section 11.1 (pp. 441–443).

You will be able to:

  • Tell volatile storage (RAM, variables) apart from nonvolatile storage (files on a disk)
  • Keep a value that must survive a restart in a file instead of a field
  • Name the everyday file tasks a program performs: check, open, read, write, close, delete

How to complete it

  1. Open the lab page (11.1.html) from this module. Your work saves automatically in your browser.
  2. Answer the short warm-up about the code you are given, then write your code until every structure check passes.
  3. Run the test program (instructions are on the lab page), paste its output back into the page and compare.
  4. Answer the reflection questions in your own words.
  5. Download (or copy) your lab report.

Submit here: the lab report (.txt) and your code file (VisitCounter.java).

How it will be assessed

  • Requirements met (5 pts): All structure checks pass and the test program's output matches (see the lab report).
  • Reasoning (3 pts): Warm-up and reflection answers are specific to this code, in the student's own words.
  • Style (2 pts): Allman braces and indentation kept; getTotal() is the one place that reads the file; no leftover field.

The checks on the lab page give you feedback; they are not your grade.
