Lab 11.7: The locker records that run into each other

Fixed-size records placed by their key field

Estimated time: about 30 minutes. Reading: Ch. 11, section 11.7 (pp. 463–468), with the name padding from p. 474.

You will be able to:

  • Compute a record's size from the default record instead of counting it by hand
  • Make every record the same size by padding or cutting a field to a fixed length
  • Place a record in a random access file at its key field times the record size

How to complete it

  1. Open the lab page (11.7.html) from this module. Your work saves automatically in your browser.
  2. Answer the short warm-up about the code you are given, then write your code until every structure check passes.
  3. Run the test program (instructions are on the lab page), paste its output back into the page and compare.
  4. Answer the reflection questions in your own words.
  5. Download (or copy) your lab report.

Submit here: the lab report (.txt) and your code file (LockerFile.java).

How it will be assessed

  • Requirements met (5 pts): All structure checks pass and the test program's output matches (see the lab report).
  • Reasoning (3 pts): Warm-up and reflection answers are specific to this code, in the student's own words.
  • Style (2 pts): Allman braces and indentation kept; RECSIZE computed once from DEFAULT_RECORD; names padded with spaces, not '\u0000'.

The checks on the lab page give you feedback; they are not your grade.
