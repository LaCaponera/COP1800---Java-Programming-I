The locker records that run into each other

Objectives

  • Compute a record's size from the default record instead of counting it by hand
  • Make every record the same size by padding or cutting a field to a fixed length
  • Place a record in a random access file at its key field times the record size

Requirements

  1. R1 RECSIZE is computed as DEFAULT_RECORD.length(), never typed as a number.
  2. R2 assign() makes every name exactly NAME_LENGTH characters: shorter names are padded with spaces, longer ones are cut.
  3. R3 assign() positions the channel at locker * RECSIZE before writing.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. DEFAULT_RECORD shows 16 visible characters. How many characters long is it on Windows, and on a Mac? Why do they differ?

    18 on Windows and 17 on a Mac. It ends with the system's line separator, which is two characters (\r\n) on Windows and one (\n) on macOS.

  2. With the correct RECSIZE on Windows, at which byte should locker 7's record start? At which byte does the starter write it?

    At 7 × 18 = 126. The starter writes it at byte 7, inside locker 0's record.

Solution

LockerFile.java
import java.nio.file.*;
import java.io.*;
import java.nio.ByteBuffer;
import java.nio.channels.FileChannel;
import static java.nio.file.StandardOpenOption.*;

// A random access file of gym lockers. Locker n's record is record n.
// Record layout: locker number (3 digits), name (10 characters), plan (S or F).
public class LockerFile
{
    public static final int NUMRECS = 20;
    public static final int NAME_LENGTH = 10;
    public static final String DEFAULT_RECORD =
        "000,          ,-" + System.getProperty("line.separator");
    public static final int RECSIZE = DEFAULT_RECORD.length();
    private Path file;

    public LockerFile(String fileName)
    {
        file = Paths.get(fileName);
    }

    // Fills the file with NUMRECS default records.
    public void createEmpty() throws IOException
    {
        OutputStream output = new BufferedOutputStream(Files.newOutputStream(file));
        BufferedWriter writer = new BufferedWriter(new OutputStreamWriter(output));
        for (int count = 0; count < NUMRECS; ++count)
            writer.write(DEFAULT_RECORD, 0, DEFAULT_RECORD.length());
        writer.close();
    }

    // Writes one locker's record in the place its number (the key field) decides.
    public void assign(int locker, String name, String plan) throws IOException
    {
        StringBuilder sb = new StringBuilder(name);
        while (sb.length() < NAME_LENGTH)
            sb.append(' ');
        sb.setLength(NAME_LENGTH);
        String s = idText(locker) + "," + sb.toString() + "," + plan +
            System.getProperty("line.separator");
        byte[] data = s.getBytes();
        ByteBuffer buffer = ByteBuffer.wrap(data);
        FileChannel fc = (FileChannel)Files.newByteChannel(file, READ, WRITE);
        fc.position(locker * RECSIZE);
        fc.write(buffer);
        fc.close();
    }

    // 7 becomes "007", 15 becomes "015".
    private String idText(int locker)
    {
        String id = "00" + locker;
        return id.substring(id.length() - 3);
    }
}

Walkthrough

Random access by record works only when every record has the same size, because record n starts at n × record size (p. 463). The book builds a default record and takes RECSIZE from its length, and notes that the line separator from System.getProperty("line.separator") is two bytes on Windows (p. 465), so 17 is right on a Mac and wrong on Windows. The key field, the locker number, decides the position: locker * RECSIZE (pp. 463 and 467). The book assumes every name has seven characters (p. 466) and later pads names with StringBuilder.setLength() (p. 474). Careful: setLength() cuts a long name correctly, but it pads a short one with the character '\u0000', not spaces, so the solution appends spaces first and then calls setLength() to cut. The test reads the file sequentially and finds each assigned locker on the line with its own number.

Test program

Students run it in an IDE and paste the output into the page.

TestLockerFile.java
import java.nio.file.*;
import java.io.*;

public class TestLockerFile
{
    public static void main(String[] args) throws IOException
    {
        LockerFile lockers = new LockerFile("lockers.txt");
        lockers.createEmpty();
        lockers.assign(3, "Okafor", "S");
        lockers.assign(7, "Li", "F");
        lockers.assign(5, "Bartholomew-Smith", "S");

        // Read the file sequentially, the way Notepad shows it,
        // and display only the lines that are not default records.
        BufferedReader reader = new BufferedReader(
            new InputStreamReader(Files.newInputStream(Paths.get("lockers.txt"))));
        int line = 0;
        String s = reader.readLine();
        while (s != null)
        {
            if (!s.startsWith("000"))
                System.out.println("Line " + line + ": " + s);
            ++line;
            s = reader.readLine();
        }
        reader.close();
        System.out.println("Lines in the file: " + line);
    }
}

Messages students see when a check fails

C1 · RECSIZE comes from the default record

Set RECSIZE = DEFAULT_RECORD.length();. Java then counts the line separator for the system it runs on; a typed number is right on only one kind of computer.

C2 · Names get a fixed length

Make the name exactly NAME_LENGTH characters before building the record: add spaces to a short name and cut a long one (a StringBuilder with append(' ') and setLength() does both).

C3 · The key field decides the position

Position the channel at locker * RECSIZE. position() counts bytes, and locker n's record starts n whole records into the file.

Progressive hints

  1. Run the starter and open lockers.txt in a text editor. Which record did locker 3, written at byte 3, land inside?

  2. Records are numbered from 0, so locker n's record is preceded by n complete records. How many bytes is that?

  3. setLength(NAME_LENGTH) cuts a long name, but it fills a short one with '\u0000' characters, not spaces. Append spaces in a loop while the length is too short, then cut.

Reflection: questions and model answers

  1. Why does random access by record number require every record to have exactly the same size?

    The program finds record n by arithmetic, n times the record size. If one record were longer or shorter, every record after it would start at a different byte than the arithmetic says.

  2. The book assumes users never enter a duplicate ID (p. 466). What does your assign() do if locker 3 is assigned twice, and how could it prevent that?

    It silently overwrites the first record with the second. It could first read the record at 3 × RECSIZE and refuse to write unless it still starts with 000.

Extension

Add String recordFor(int locker) that reads one record with a FileChannel (the technique of section 11.8) and returns it without its line separator. Then make assign() reject a locker number outside 0 to 19 instead of writing past the last record.
