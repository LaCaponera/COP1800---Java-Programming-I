The seat map that books only one seat

Objectives

  • Explain the difference between sequential and random access
  • Write bytes at chosen positions with a FileChannel, position() and a wrapped ByteBuffer
  • Reuse a ByteBuffer with rewind(), and read a single byte from any position

Requirements

  1. R1 book() sets the channel's position to each seat number before writing, and rewinds the buffer after each write so it can be written again.
  2. R2 seatAt() opens the file, moves to the seat's position, reads one byte into a wrapped byte[1], closes the channel, and returns that byte as a char.
  3. R3 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. In the starter's book(), what does out.hasRemaining() return after the first seat has been written, and what happens in the while loop for the next seat?

    It returns false, because the single byte has been written. The while loop's body never runs, so nothing is written for the next seats.

  2. The starter never calls position(). Where does the first X go, and why?

    At byte 0, seat 0. A newly opened channel's position is 0, and it only moves forward as bytes are written.

Solution

SeatMap.java
import java.nio.file.*;
import java.io.*;
import java.nio.ByteBuffer;
import java.nio.channels.FileChannel;
import static java.nio.file.StandardOpenOption.*;

// One row of seats, stored as one character per seat: '.' is free, 'X' is booked.
// Seat numbers start at 0, so seat n is the byte at position n.
public class SeatMap
{
    private Path file;

    public SeatMap(String fileName)
    {
        file = Paths.get(fileName);
    }

    // Creates a row of free seats.
    public void create(int seats) throws IOException
    {
        String s = "";
        for (int x = 0; x < seats; ++x)
            s += ".";
        OutputStream output = new BufferedOutputStream(Files.newOutputStream(file));
        output.write(s.getBytes());
        output.close();
    }

    // Returns the number of seats in the row: one byte per seat.
    public long seatCount() throws IOException
    {
        FileChannel fc = (FileChannel)Files.newByteChannel(file, READ);
        long size = fc.size();
        fc.close();
        return size;
    }

    // Marks each seat in the array as booked.
    public void book(int[] seatNumbers) throws IOException
    {
        byte[] data = "X".getBytes();
        ByteBuffer out = ByteBuffer.wrap(data);
        FileChannel fc = (FileChannel)Files.newByteChannel(file, READ, WRITE);
        for (int x = 0; x < seatNumbers.length; ++x)
        {
            fc.position(seatNumbers[x]);
            while (out.hasRemaining())
                fc.write(out);
            out.rewind();
        }
        fc.close();
    }

    // Returns the character stored for one seat: '.' or 'X'.
    public char seatAt(int seatNumber) throws IOException
    {
        byte[] data = new byte[1];
        ByteBuffer in = ByteBuffer.wrap(data);
        FileChannel fc = (FileChannel)Files.newByteChannel(file, READ);
        fc.position(seatNumber);
        fc.read(in);
        fc.close();
        return new String(data).charAt(0);
    }

    // Returns the whole row as one String.
    public String row() throws IOException
    {
        BufferedReader reader = new BufferedReader(
            new InputStreamReader(Files.newInputStream(file)));
        String s = reader.readLine();
        reader.close();
        return s;
    }
}

Walkthrough

This is the RandomAccessTest program (p. 462) turned into a class. A FileChannel is seekable: position(n) moves to byte n, and the next read() or write() starts there (Table 11-7, p. 461). ByteBuffer.wrap() puts a byte array inside a buffer, so changes to one show up in the other (p. 462). Writing uses up the buffer; hasRemaining() then returns false, and rewind() makes the same bytes available again (p. 462). For seatAt(), a 1-byte array is wrapped, the channel is positioned at the seat, and after read() the byte is in the array; new String(data).charAt(0) (or a (char) cast) turns it into the seat's character. Seats are booked in the order 0, 22, 12 on purpose: random access doesn't care about order.

import java.io.IOException;

public class TestSeatMap

}

Messages students see when a check fails

C1 · book() moves to each seat

Call fc.position(seatNumbers[x]) inside the loop, before writing. A channel writes wherever its position is, and the position doesn't jump to the next seat by itself.

C2 · book() reuses the buffer

Call out.rewind() after each write (p. 462). Once the X has been written the buffer is empty, so later writes send nothing.

C3 · seatAt() goes to the seat

Position the channel at seatNumber before reading; seat n is the byte at position n.

C4 · seatAt() reads into a buffer

Wrap a byte[1] with ByteBuffer.wrap() and call fc.read(...) with it. The byte read lands in the array.

C5 · seatAt() closes the channel

Close the channel before returning, as book() does, so the file isn't left open.

Progressive hints

  1. Compare book() with RandomAccessTest on p. 462: which two calls appear between its writes that the starter doesn't have?

  2. Inside the for loop the order is: move to the seat, write until nothing remains, make the buffer reusable.

  3. For seatAt(), open the channel with READ, then the byte array is where you look after read(): data[0] holds the seat.

Reflection: questions and model answers

  1. A BufferedWriter can't book seat 22 before seat 12, but a FileChannel can. What property of a file channel makes the difference?

    A file channel is seekable: position() can move to any byte and the next read or write starts there. A BufferedWriter writes only forward, from where the last write ended.

  2. In seatAt() you never read from the ByteBuffer itself, yet data[0] holds the seat. Why?

    wrap() doesn't copy the array: the buffer is a view of it. When read() puts a byte into the buffer, it goes straight into the wrapped array.

Extension
