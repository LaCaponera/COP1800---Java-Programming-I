The volunteer export that came out empty

Objectives

  • Describe the data hierarchy: characters, fields, records and files
  • Write records as comma-separated values (CSV) so each field can be found again
  • Explain what a buffer does and close an output file so its contents reach the disk

Requirements

  1. R1 addRecord() writes the ID, name and hours separated by commas (a constant such as DELIMITER = "," is welcome).
  2. R2 finish() closes the writer, which flushes the buffer to the file first.
  3. R3 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. In the finished file, which part of 786,Brown,12.5 is a record, which is a field, and which is a character? What is the file?

    The whole line is a record; 786, Brown and 12.5 are fields; B (or any single symbol) is a character. volunteer_hours.csv, the set of records, is the file.

  2. The starter runs without an error, but the file is empty. Where are the three records when main() ends?

    In the BufferedWriter's buffer in RAM. They were written to the buffer but never flushed, so they never reached the disk, and the buffer disappears when the program ends.

Solution

HoursExport.java
import java.nio.file.*;
import java.io.*;

public class HoursExport
{
    private static final String DELIMITER = ",";
    private BufferedWriter writer;
    private int records;

    // Opens the export file for writing (a new, empty file each time).
    public HoursExport(String fileName) throws IOException
    {
        OutputStream output = new BufferedOutputStream(
            Files.newOutputStream(Paths.get(fileName)));
        writer = new BufferedWriter(new OutputStreamWriter(output));
    }

    // Writes one record (one line): the volunteer's ID, name and hours.
    public void addRecord(int id, String name, double hours) throws IOException
    {
        String s = id + DELIMITER + name + DELIMITER + hours;
        writer.write(s, 0, s.length());
        writer.newLine();
        ++records;
    }

    public int getRecordCount()
    {
        return records;
    }

    // Called once, after the last record.
    public void finish() throws IOException
    {
        writer.close();
    }
}

Walkthrough

A field is a group of characters with a meaning, a record is a collection of fields about one entity, and a file is a group of related records (p. 450). On disk Java sees only a series of bytes (p. 451), so the program must mark where fields end; a comma makes the file a CSV file, which spreadsheets and databases read (p. 451). Each record goes on its own line with newLine(). The empty file is a buffer problem: output waits in a memory block until it is flushed (p. 451), and if an output file is not closed its data might never be written (p. 451). close() flushes first and then releases the file, so it is the right call in finish(); flush() alone would write the data but leave the file open.

Test program

Students run it in an IDE and paste the output into the page.

TestHoursExport.java
import java.nio.file.*;
import java.io.*;

public class TestHoursExport
{
    public static void main(String[] args) throws IOException
    {
        HoursExport export = new HoursExport("volunteer_hours.csv");
        export.addRecord(786, "Brown", 12.5);
        export.addRecord(812, "Okafor", 4.0);
        export.addRecord(845, "Nguyen", 7.25);
        export.finish();
        System.out.println("Records sent: " + export.getRecordCount());

        // Read the file back the way a spreadsheet does:
        // one record per line, fields separated by commas.
        BufferedReader reader = new BufferedReader(new InputStreamReader(
            Files.newInputStream(Paths.get("volunteer_hours.csv"))));
        int lines = 0;
        String s = reader.readLine();
        while (s != null)
        {
            ++lines;
            String[] fields = s.split(",");
            System.out.println("Record " + lines + ": " + fields.length + " fields -> " + s);
            s = reader.readLine();
        }
        reader.close();
        System.out.println("Records in the file: " + lines);
    }
}

Messages students see when a check fails

C1 · A comma delimiter exists

Use a comma as the field delimiter, for example private static final String DELIMITER = ",";. A CSV file separates the values of a record with commas.

C2 · Each field is followed by the delimiter

Put the delimiter between the fields: id + DELIMITER + name + DELIMITER + hours. Without it the reader sees one long field.

C3 · finish() closes the writer

Call writer.close(). Closing flushes the buffer to the disk and then releases the file; until then the records sit in RAM.

Reflection: questions and model answers

  1. If a buffer can lose data like this, why does Java buffer output at all?

    Input and output are among the slowest operations a computer does. Collecting many small writes in a buffer and sending them to the device in one larger operation makes the program much faster.

  2. The book says failing to close an input file usually does no harm, but failing to close an output file can. Explain the difference using this lab.

    Reading leaves the data in the file whether or not you close it. Writing through a buffer keeps the data in memory until a flush, so if the output file is never closed the records may never reach the disk, which is what happened here.
