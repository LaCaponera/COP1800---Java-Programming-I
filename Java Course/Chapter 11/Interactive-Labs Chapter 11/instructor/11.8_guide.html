The help-desk lookup that shows the same account twice

Objectives

  • Read one record directly from a random access file with position() and read()
  • Prepare the ByteBuffer for every read, and recognize a default record
  • Process the same random access file sequentially, skipping default records

Requirements

  1. R1 find() prepares the buffer for every lookup: wrap data in a new ByteBuffer inside the method (or clear() the field first).
  2. R2 find() returns no account #<id> when the record read is a default record (its account number is 000).
  3. R3 listActive() reads the file sequentially with a BufferedReader, skips records whose account number is 0, prints each other record as #042 Rivera $120.5 (name trimmed, balance from parseDouble()), and returns the total of their balances.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. After the first fc.read(buffer) fills all of the buffer's bytes, what can the next fc.read(buffer) with the same buffer copy into it? What does data still hold?

    Nothing: the buffer has no remaining space, so read() copies 0 bytes. data still holds the first record that was read, account 315.

  2. Account 500 was never added. What does its record contain, and which field shows that it is empty?

    The default record, 000, ten spaces and 0000.00. The account number field is 000 instead of 500.

Starter files

AccountWriter.java (read-only for students)
import java.nio.file.*;
import java.io.*;
import java.nio.ByteBuffer;
import java.nio.channels.FileChannel;
import static java.nio.file.StandardOpenOption.*;

// Builds the random access account file (the technique from section 11.7).
// Record layout: account number (3 digits), name (10 characters), balance (0000.00).
public class AccountWriter
{
    public static final int NUMRECS = 1000;
    public static final int NAME_LENGTH = 10;
    public static final String DEFAULT_RECORD =
        "000,          ,0000.00" + System.getProperty("line.separator");
    public static final int RECSIZE = DEFAULT_RECORD.length();
    private Path file;

    public AccountWriter(String fileName)
    {
        file = Paths.get(fileName);
    }

    // Fills the file with NUMRECS default records.
    public void createEmpty() throws IOException
    {
        OutputStream output = new BufferedOutputStream(Files.newOutputStream(file));
        BufferedWriter writer = new BufferedWriter(new OutputStreamWriter(output));
        for (int count = 0; count < NUMRECS; ++count)
            writer.write(DEFAULT_RECORD, 0, DEFAULT_RECORD.length());
        writer.close();
    }

    // Writes one account at the position its number decides.
    // balance must already have the 0000.00 format, for example "0120.50".
    public void add(int id, String name, String balance) throws IOException
    {
        StringBuilder sb = new StringBuilder(name);
        while (sb.length() < NAME_LENGTH)
            sb.append(' ');
        sb.setLength(NAME_LENGTH);
        String idText = "00" + id;
        idText = idText.substring(idText.length() - 3);
        String s = idText + "," + sb.toString() + "," + balance +
            System.getProperty("line.separator");
        ByteBuffer buffer = ByteBuffer.wrap(s.getBytes());
        FileChannel fc = (FileChannel)Files.newByteChannel(file, READ, WRITE);
        fc.position(id * RECSIZE);
        fc.write(buffer);
        fc.close();
    }
}

Solution

AccountReader.java
import java.nio.file.*;
import java.io.*;
import java.nio.ByteBuffer;
import java.nio.channels.FileChannel;
import static java.nio.file.StandardOpenOption.*;

public class AccountReader
{
    private static final int RECSIZE = AccountWriter.RECSIZE;
    private Path file;
    private byte[] data = new byte[RECSIZE];

    public AccountReader(String fileName)
    {
        file = Paths.get(fileName);
    }

    // Random access: jumps straight to one account's record and returns it
    // without its line separator, or "no account #" + id for a default record.
    public String find(int id) throws IOException
    {
        ByteBuffer buffer = ByteBuffer.wrap(data);
        FileChannel fc = (FileChannel)Files.newByteChannel(file, READ);
        fc.position(id * RECSIZE);
        fc.read(buffer);
        fc.close();
        String s = new String(data).trim();
        if (s.startsWith("000"))
            return "no account #" + id;
        return s;
    }

    // Sequential access: displays every real account, in file order,
    // as "#042 Rivera $120.5", and returns the total of their balances.
    public double listActive() throws IOException
    {
        double total = 0;
        InputStream input = new BufferedInputStream(Files.newInputStream(file));
        BufferedReader reader = new BufferedReader(new InputStreamReader(input));
        String s = reader.readLine();
        while (s != null)
        {
            String[] fields = s.split(",");
            if (Integer.parseInt(fields[0]) != 0)
            {
                double balance = Double.parseDouble(fields[2]);
                System.out.println("#" + fields[0] + " " + fields[1].trim() + " $" + balance);
                total += balance;
            }
            s = reader.readLine();
        }
        reader.close();
        return total;
    }
}

Walkthrough

Random access means retrieving one record directly, without reading the records before it (p. 470): the position is the key times the record size, exactly as it was when writing. ReadEmployeesRandomly wraps the byte array again inside its loop, buffer = ByteBuffer.wrap(data); (p. 470). That line matters: a buffer that has been filled has no remaining space, and read() into it copies nothing. Default records start with 000, the same test ReadEmployeesSequentially uses (id != 0, pp. 468–469). A random access file can also be processed sequentially (p. 468): reading it line by line lists the accounts in account-number order, because each record's place in the file was set by its key. new String(data).trim() drops the line separator from a record read by the channel; fields[1].trim() drops the name's padding.

Messages students see when a check fails

C1 · A fresh buffer for every lookup

Wrap data in a new buffer at the start of find(), as ReadEmployeesRandomly does inside its loop (p. 470). A buffer that has been filled has no room for the next record.

C2 · find() recognizes a default record

Check the record's account number: if it is 000 (for example s.startsWith("000")), return "no account #" + id.

C3 · listActive() reads line by line

Read the file sequentially with a BufferedReader and readLine() until it returns null, as ReadEmployeesSequentially does (p. 469).

C4 · listActive() splits each record

Split each record on the comma to get the account number, name and balance fields.

C5 · listActive() totals the balances

Convert the balance field with Double.parseDouble() before printing and adding it to the total.

Progressive hints

  1. Compare find() with ReadEmployeesRandomly on p. 470. Which line runs inside its loop, before every read, that the starter runs only once?

  2. After the read, the record is in data. Its first three characters are the account number; a record nobody has written still has 000 there.

  3. listActive() is ReadEmployeesSequentially (p. 469) with a different print: split, skip when Integer.parseInt(fields[0]) is 0, trim the name, parse the balance, add it.

Reflection: questions and model answers

  1. The help desk uses find() and the supervisor uses listActive() on the same file. Which is real-time processing and which is batch processing, and why does each fit its access method?

    find() is real-time: a caller is waiting, so the program must jump straight to one record. listActive() is batch: it processes every record once, one after another, so reading sequentially is natural.

  2. The accounts were added as 42, 7, 315 but are listed as 7, 42, 315. Why, and why does the book say you don't need a random access file just to get sorted output?

    Each record's position was set by its account number, so reading front to back gives account order. If sorted output were the only goal, sorting the records would do it without reserving space for 1,000 records.
