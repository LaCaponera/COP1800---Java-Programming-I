The club roster that splits Mary Ann in two

Objectives

  • Choose a field delimiter that can't appear inside the data
  • Read a sequential file from first record to last with a BufferedReader loop
  • Split each record with split() and convert fields with parseInt() and parseDouble()

Requirements

  1. R1 Records use a comma between fields: DELIMITER is ",".
  2. R2 totalDues() reads every record until readLine() returns null, splits it into fields and adds its dues with Double.parseDouble().
  3. R3 findName() reads records in order until one has the requested ID, closes the file, and returns that name or no member #<id>.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. With the starter's space delimiter, the first record is 104 Mary Ann Lee 40.0. What does split(" ") return, and what is in element 2?

    An array of five Strings: 104, Mary, Ann, Lee and 40.0. Element 2 is Ann, so parseDouble() of it throws a NumberFormatException.

  2. Why must findName(131) read the records for 104, 117 and 123 before it reaches Jo's?

    The file is used sequentially: records can only be read one after another in the order they were stored, and 131 was stored fourth.

Solution

RosterFile.java
import java.nio.file.*;
import java.io.*;

public class RosterFile
{
    private static final String DELIMITER = ",";
    private Path file;

    public RosterFile(String fileName)
    {
        file = Paths.get(fileName);
    }

    // Writes one record per member: ID, name and dues paid.
    public void save(int[] ids, String[] names, double[] dues) throws IOException
    {
        OutputStream output = new BufferedOutputStream(Files.newOutputStream(file));
        BufferedWriter writer = new BufferedWriter(new OutputStreamWriter(output));
        for (int x = 0; x < ids.length; ++x)
        {
            String s = ids[x] + DELIMITER + names[x] + DELIMITER + dues[x];
            writer.write(s, 0, s.length());
            writer.newLine();
        }
        writer.close();
    }

    // Reads every record, first to last, and adds up the dues.
    public double totalDues() throws IOException
    {
        double total = 0;
        InputStream input = new BufferedInputStream(Files.newInputStream(file));
        BufferedReader reader = new BufferedReader(new InputStreamReader(input));
        String s = reader.readLine();
        while (s != null)
        {
            String[] fields = s.split(DELIMITER);
            total += Double.parseDouble(fields[2]);
            s = reader.readLine();
        }
        reader.close();
        return total;
    }

    // Returns the name of the member with this ID, or "no member #" + id.
    public String findName(int id) throws IOException
    {
        String result = "no member #" + id;
        InputStream input = new BufferedInputStream(Files.newInputStream(file));
        BufferedReader reader = new BufferedReader(new InputStreamReader(input));
        String s = reader.readLine();
        boolean found = false;
        while (s != null && !found)
        {
            String[] fields = s.split(DELIMITER);
            if (Integer.parseInt(fields[0]) == id)
            {
                result = fields[1];
                found = true;
            }
            s = reader.readLine();
        }
        reader.close();
        return result;
    }
}

Walkthrough

This follows WriteEmployeeFile and ReadEmployeeFile2 (pp. 457–460). A delimiter works only if it can't appear inside a field; names contain spaces but not commas, so the comma-separated layout keeps each name in one field (CSV, p. 451). split(DELIMITER) returns an array with one element per field, and parseInt() and parseDouble() turn the text back into numbers (p. 460). totalDues() uses the read-test-process-read loop of ReadEmployeeFile2. findName() is a sequential search: it must read the records before the match, and it closes the reader in every case, which is why the solution stores the result and returns once at the end. Using the constant DELIMITER for both writing and reading means the two can never disagree.

TestRosterFile.java
import java.io.IOException;

public class TestRosterFile
{
    public static void main(String[] args) throws IOException
    {
        int[] ids = {104, 117, 123, 131};
        String[] names = {"Mary Ann Lee", "Tomas Okafor", "Ana Ruiz", "Jo Van Der Berg"};
        double[] dues = {40.0, 25.5, 12.75, 30.0};

        RosterFile roster = new RosterFile("roster.txt");
        roster.save(ids, names, dues);
        System.out.println("Saved " + ids.length + " members to roster.txt");

        System.out.println("Total dues: $" + roster.totalDues());
        System.out.println("#104 is " + roster.findName(104));
        System.out.println("#131 is " + roster.findName(131));
        System.out.println("#200 is " + roster.findName(200));
    }
}

Messages students see when a check fails

C1 · Comma delimiter

Set DELIMITER to ",". Names contain spaces, so a space can't mark where a field ends; a comma never appears in these fields.

C2 · totalDues() reads to the end

Read with a loop that continues while the line is not null, as ReadEmployeeFile2 does on p. 460.

C3 · totalDues() splits each record

Split each line with s.split(DELIMITER) so the dues are in their own array element.

C4 · totalDues() converts the dues

Convert the dues field with Double.parseDouble() before adding it; the file holds text, not numbers.

C5 · findName() compares IDs

Compare each record's ID field with id: convert it with Integer.parseInt() (or compare text with equals()).

C6 · findName() closes the file

Close the reader before returning, also when the member is found early. Keep the answer in a variable and return it after close().

Progressive hints

  1. Open roster.txt after save() runs. Could you, or a program, tell where Mary Ann Lee's name ends?

  2. totalDues() has the same shape as ReadEmployeeFile2 on p. 460: read a line, loop while it isn't null, split, convert, add, read the next line.

  3. In findName(), a boolean such as found in the loop condition lets you stop early and still reach the single reader.close() after the loop.

Reflection: questions and model answers

  1. Why is a comma a better delimiter than a space for this file, and what would break if a member's name were entered as Lee, Mary Ann?

    Names contain spaces but not commas, so each name stays one field. A name with a comma would split into two fields, shifting the dues to element 3 and making element 2 a name fragment.

  2. The file stores 40.0 as text. What does Double.parseDouble() do with it, and why can't total += fields[2] work?

    It converts the characters 4, 0, . and 0 into the double value 40.0. fields[2] is a String, and += with a double total would not compile; text must be converted before arithmetic.
