The kiosk log that overwrites itself

Objectives

  • Choose StandardOpenOption values that append to, or truncate, an existing file
  • Write bytes to a file with Files.newOutputStream() and a BufferedOutputStream
  • Read a file line by line with a BufferedReader until readLine() returns null

Requirements

  1. R1 append() opens the file with CREATE and APPEND, so each event is added after the existing ones.
  2. R2 printAll() reads and numbers every line in a loop that stops when readLine() returns null, and returns how many lines it read.
  3. R3 clear() leaves the log empty: open it with TRUNCATE_EXISTING (or with no options) and close it, or delete it.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. Using Table 11-4, which options does Files.newOutputStream(file) behave as if it had when you pass none? Which single option does the starter pass?

    With no options it acts as CREATE and TRUNCATE_EXISTING, so the file is replaced. The starter passes only CREATE, which opens the file without truncating it.

  2. In printAll(), what does readLine() return once there are no more lines, and how many times does the starter call it?

    It returns null at the end of the file. The starter calls it once, so it only ever sees the first line.

Solution

KioskLog.java
import java.nio.file.*;
import java.io.*;
import static java.nio.file.StandardOpenOption.*;

public class KioskLog
{
    private Path file;

    public KioskLog(String fileName)
    {
        file = Paths.get(fileName);
    }

    // Adds one event to the end of the log.
    public void append(String event) throws IOException
    {
        String s = event + System.getProperty("line.separator");
        byte[] data = s.getBytes();
        OutputStream output = new BufferedOutputStream(
            Files.newOutputStream(file, CREATE, APPEND));
        output.write(data);
        output.flush();
        output.close();
    }

    // Displays every event, numbered from 1, and returns how many there were.
    public int printAll() throws IOException
    {
        InputStream input = Files.newInputStream(file);
        BufferedReader reader = new BufferedReader(new InputStreamReader(input));
        int count = 0;
        String s = reader.readLine();
        while (s != null)
        {
            ++count;
            System.out.println(count + ". " + s);
            s = reader.readLine();
        }
        reader.close();
        return count;
    }

    // Starts a fresh log for the next shift: no events.
    public void clear() throws IOException
    {
        OutputStream output = Files.newOutputStream(file, CREATE, TRUNCATE_EXISTING);
        output.close();
    }
}

Walkthrough

Files.newOutputStream() takes a Path and StandardOpenOption values (p. 454). With no options it behaves like CREATE plus TRUNCATE_EXISTING, replacing the contents; CREATE on its own opens the file and writes from byte 0 without truncating, which is why fragments of older, longer events survive. APPEND (used with CREATE or WRITE) adds to the end (Table 11-4, p. 454). Reading uses Files.newInputStream() wrapped in a BufferedReader (p. 456), and readLine() returns null at the end of the file, so the loop reads, tests for null, prints, and reads again (p. 455). Note the book's one-line loop while(s = reader.readLine() != null) needs extra parentheses, while((s = reader.readLine()) != null), or it doesn't compile. clear() opens with CREATE, TRUNCATE_EXISTING and closes immediately, leaving a 0-byte file.

TestKioskLog.java
import java.nio.file.*;
import java.io.IOException;

public class TestKioskLog
{
    public static void main(String[] args) throws IOException
    {
        // Start clean: remove any kiosk.log left by an earlier run.
        Files.deleteIfExists(Paths.get("kiosk.log"));

        KioskLog log = new KioskLog("kiosk.log");
        log.append("07:58 door opened by J. Ruiz");
        log.append("08:02 alarm off");
        log.append("08:15 lights on");
        System.out.println("Morning shift");
        System.out.println("Events: " + log.printAll());

        log.clear();
        log.append("17:30 door locked");
        System.out.println("Evening shift, after clear()");
        System.out.println("Events: " + log.printAll());
    }
}

Messages students see when a check fails

C1 · append() adds to the end

Open the file with CREATE, APPEND (Table 11-4). CREATE alone starts writing at byte 0 and leaves the rest of the old text behind.

C2 · printAll() reads until null

Read in a while loop that continues as long as the line is not null; readLine() returns null only at the end of the file.

C3 · clear() empties the file

Open the file with CREATE, TRUNCATE_EXISTING (or with no options) and close it straight away; truncating cuts it to 0 bytes. Deleting it with Files.deleteIfExists(file) also works.

Progressive hints

  1. Open kiosk.log after running the starter and compare it with the three events. Which event's text is at the start, and where did the leftover letters come from?

  2. Table 11-4 (p. 454) has an option whose description says new data goes to the end of the file. You can pass several options separated by commas.

  3. In printAll(), read the first line before the loop, test it for null in the while condition, and read the next line as the last statement of the loop body.

Reflection: questions and model answers

  1. Explain, byte by byte, why the starter can leave a fragment such as ened by J. Ruiz in the log.

    CREATE without APPEND or TRUNCATE_EXISTING opens the existing file and starts writing at byte 0. A shorter event overwrites only the first bytes of the longer old one, so the rest of the old line, after the new line separator, stays in the file.

  2. When would you choose TRUNCATE_EXISTING on purpose, and when CREATE_NEW?

    TRUNCATE_EXISTING when the file must be replaced, as clear() does or a nightly report that is rebuilt from scratch. CREATE_NEW when an existing file must never be touched, because it throws an exception instead of overwriting.
