COP1800 · Java Programming I · Lab 5.3

The ferry crew's negative overtime

Objectives

  • Use curly braces to make several statements depend on an if or an else
  • Explain why an indented statement after an unbraced if always runs
  • Write an if…else with a block in each clause, so every path assigns every result
  • State the scope of a variable declared inside a block

Requirements

  1. R1 When hoursWorked is more than FULL_WEEK, both the regular-pay and the overtime-pay statements depend on the if: they form one block.
  2. R2 An else block sets regular pay to hours times rate and overtime pay to 0.0. regularPay and overtimePay are declared without a value, so each path assigns them once.
  3. R3 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. In the starter, how many statements depend on if(hoursWorked > FULL_WEEK)? Which line runs no matter how many hours are worked?

    One: regularPay = FULL_WEEK * rate;. The overtime line is an independent statement, so it runs for every deckhand, including Marta with 30 hours.

  2. Predict Marta's overtime pay with the starter code (30 hours at $25.50).

    −382.5: (30 − 40) × 1.5 × 25.50. The overtime line runs even though she didn't work more than 40 hours.

Solution

DeckhandPay.java
public class DeckhandPay
{
    public static final int FULL_WEEK = 40;
    public static final double OT_RATE = 1.5;

    public static void printPay(String name, double hoursWorked, double rate)
    {
        double regularPay;
        double overtimePay;

        if(hoursWorked > FULL_WEEK)
        {
            regularPay = FULL_WEEK * rate;
            overtimePay = (hoursWorked - FULL_WEEK) * OT_RATE * rate;
        }
        else
        {
            regularPay = hoursWorked * rate;
            overtimePay = 0.0;
        }

        System.out.println(name + ": regular $" + regularPay
            + ", overtime $" + overtimePay);
    }

    public static void main(String[] args)
    {
        printPay("Marta", 30, 25.50);
        printPay("Jonah", 44, 20.00);
    }
}

Walkthrough

Without braces, an if controls exactly one statement. In the starter, only regularPay = FULL_WEEK * rate; depended on the if; the overtime line was an independent statement that ran for everyone, so 30 hours gave (30 − 40) × 1.5 × 25.50 = −382.50. The indentation made it look dependent, but the compiler ignores indentation. Braces make both lines one block. The else block is the other half of the dual-alternative selection, as in the book's Payroll program (Figure 5-9). Declaring the two variables without values is deliberate: the compiler checks that every path assigns them before the println uses them (variable might not have been initialized otherwise), so forgetting an assignment in one branch becomes a compile error instead of a wrong paycheck. The final println is outside the decision, so it runs for every deckhand.

Messages students see when a check fails

C1 · Both overtime-case statements are in one block

Put curly braces around the two pay statements after if(hoursWorked > FULL_WEEK). Without them, the if controls only the first statement, and the overtime line runs for every deckhand, which is how 30 hours produced negative overtime.

Hint:

Indentation is for people; braces are for the compiler.

C2 · An else block sets both amounts

Add an else block with braces that sets regularPay to hoursWorked * rate and overtimePay to 0.0. One block for each case makes each path's work visible in one place.

C3 · Pay is declared without a value

Declare double regularPay; and double overtimePay; with no starting value. Then the compiler confirms that every path of your if…else assigns both, so a forgotten assignment can't slip through as a wrong amount.

Progressive hints

  1. Count the statements that depend on the starter's if. The compiler counts one; how many did the programmer mean?

  2. A pair of curly braces turns several statements into one block that an if or an else can control.

  3. When the week is 40 hours or less, regular pay is every hour at the normal rate and there is no overtime: that is the else block.

Reflection: questions and model answers

  1. Suppose you declared double bonus = 25.0; inside the if block. Could the final println use bonus? Why or why not?

    No. A variable declared inside a block is local to that block; after the closing brace it no longer exists, so the println would get cannot find symbol. To use it after the decision, declare it before the if.

  2. Why is declaring regularPay without a starting value safer here than giving it one?

    With no starting value, the compiler refuses to compile unless every path assigns it before it's used. A starting value would hide a missing assignment: the program would compile and quietly print the starting value as someone's pay.
