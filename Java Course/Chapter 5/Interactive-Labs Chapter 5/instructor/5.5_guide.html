COP1800 · Java Programming I · Lab 5.5

The bike dock that runs out too early

Objectives

  • Combine two Boolean tests with && (both must be true) or || (at least one must be true)
  • Write a complete Boolean expression on each side of a binary logical operator
  • Predict which method calls are skipped by short-circuit evaluation
  • Order the operands of && so a method with a side effect runs only when it should

Requirements

  1. R1 tryUnlock() checks the rider's credit before reserving a bike, in one && expression, so a rider without credit never reserves one.
  2. R2 getFare() gives HALF_FARE when the rider is a member or has at least FREQUENT_RIDES rides this month, using one || expression with a complete comparison on each side.
  3. R3 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. In the starter, Kim has no credit. List, in order, what tryUnlock() does for Kim, including what happens to the dock.

    It calls dock.reserveBike() first, which takes a bike (2 left becomes 1) and returns true; then rider.hasCredit() returns false, so the whole && is false and Kim sees cannot unlock. The bike stays reserved even though Kim didn't get it.

  2. Why does if(rider.getRidesThisMonth() >= 10 || >= 20) not compile?

    || is a binary operator: it needs a complete Boolean expression on each side. >= 20 has no left operand; it would have to be rider.getRidesThisMonth() >= 20.

Starter files

UnlockStation.java
public class UnlockStation
{
    public static final double FULL_FARE = 4.00;
    public static final double HALF_FARE = 2.00;
    public static final int FREQUENT_RIDES = 10;

    public static void tryUnlock(Rider rider, BikeDock dock)
    {
        // TODO (R1): a rider with no credit must not take a bike out of the dock.
        if(dock.reserveBike() && rider.hasCredit())
            System.out.println(rider.getName() + ": unlocked, fare $"
                + String.format("%.2f", getFare(rider)));
        else
            System.out.println(rider.getName() + ": cannot unlock");
    }

    public static double getFare(Rider rider)
    {
        double fare = FULL_FARE;
        // TODO (R2): members ride at half fare, and so do frequent riders.
        if(rider.isMember() && rider.getRidesThisMonth() >= FREQUENT_RIDES)
            fare = HALF_FARE;
        return fare;
    }

    public static void main(String[] args)
    {
        BikeDock dock = new BikeDock("Pier Street", 2);
        tryUnlock(new Rider("Kim", false, false, 3), dock);
        tryUnlock(new Rider("Raj", true, true, 2), dock);
        tryUnlock(new Rider("Lu", true, false, 12), dock);
        System.out.println("Bikes left: " + dock.getBikesAvailable());
    }
}
BikeDock.java (read-only for students)
// The city's BikeDock class. Read it; you don't need to change it.
public class BikeDock
{
    private String street;
    private int bikesAvailable;

    public BikeDock(String dockStreet, int bikes)
    {
        street = dockStreet;
        bikesAvailable = bikes;
    }

    // Holds a bike for the rider: one fewer bike stays in the dock.
    // Returns false when the dock is empty.
    public boolean reserveBike()
    {
        if(bikesAvailable > 0)
        {
            bikesAvailable = bikesAvailable - 1;
            return true;
        }
        return false;
    }

    public int getBikesAvailable()
    {
        return bikesAvailable;
    }
}

Solution

UnlockStation.java
public class UnlockStation
{
    public static final double FULL_FARE = 4.00;
    public static final double HALF_FARE = 2.00;
    public static final int FREQUENT_RIDES = 10;

    public static void tryUnlock(Rider rider, BikeDock dock)
    {
        if(rider.hasCredit() && dock.reserveBike())
            System.out.println(rider.getName() + ": unlocked, fare $"
                + String.format("%.2f", getFare(rider)));
        else
            System.out.println(rider.getName() + ": cannot unlock");
    }

    public static double getFare(Rider rider)
    {
        double fare = FULL_FARE;
        if(rider.isMember() || rider.getRidesThisMonth() >= FREQUENT_RIDES)
            fare = HALF_FARE;
        return fare;
    }

    public static void main(String[] args)
    {
        BikeDock dock = new BikeDock("Pier Street", 2);
        tryUnlock(new Rider("Kim", false, false, 3), dock);
        tryUnlock(new Rider("Raj", true, true, 2), dock);
        tryUnlock(new Rider("Lu", true, false, 12), dock);
        System.out.println("Bikes left: " + dock.getBikesAvailable());
    }
}

Walkthrough

&& evaluates its left operand first and stops as soon as the answer is known: if the left side is false, the right side never runs (short-circuit evaluation). In the starter, dock.reserveBike() was on the left, so it ran for every rider, and its side effect, taking a bike out of the dock, happened even for Kim, who had no credit. With rider.hasCredit() on the left, a rider without credit stops the expression before reserveBike() is called. A nested if(rider.hasCredit()) { if(dock.reserveBike()) … } gives the same result. For the fare, the rule is either condition, so the operator is ||; the starter's && demanded both and charged Raj, a member with 2 rides, the full fare. Each side of || must be a complete Boolean expression: rider.getRidesThisMonth() >= FREQUENT_RIDES, not just >= FREQUENT_RIDES.

Messages students see when a check fails

C1 · Credit is checked before a bike is reserved

Put rider.hasCredit() on the left of && and dock.reserveBike() on the right. && stops at the first false, so a rider without credit never reaches reserveBike(), and no bike leaves the dock for them.

Hint:

Which of the two calls changes something in the dock?

C2 · Half fare for a member OR a frequent rider

Join the two conditions with ||: half fare needs only one of them to be true. Keep a complete comparison on each side, rider.isMember() || rider.getRidesThisMonth() >= FREQUENT_RIDES.

Progressive hints

  1. Trace Kim: which call in the starter's condition runs first, and what does it do to the dock even though the answer will be cannot unlock?

  2. With &&, the right-hand call runs only when the left-hand side is true. Which call should only happen for riders who can pay?

  3. Say the fare rule out loud: "a member or a frequent rider". The starter's operator says something else.

Reflection: questions and model answers

  1. Both rider.hasCredit() && dock.reserveBike() and dock.reserveBike() && rider.hasCredit() give the same true/false answer for every rider. Why do they still behave differently?

    Because of short-circuit evaluation and a side effect. && skips its right side when the left side is false, and reserveBike() changes the dock. Only the order that puts hasCredit() first skips the reservation for riders who can't pay.

  2. In getFare(), if the rider is a member, is getRidesThisMonth() ever called? What would change if it had a side effect, such as counting the lookup?

    No: with ||, a true left side decides the answer, so the right side isn't evaluated. If it counted lookups, members' lookups would never be counted; a call whose side effect must always happen should run on its own before the if.

Extension

The city adds a rule: riders under 16 can unlock only if they are members. Add a boolean isUnder16 parameter to a new version of tryUnlock() and write the condition. Where does the new test go so that a bike is still reserved only when the rider will get it?
