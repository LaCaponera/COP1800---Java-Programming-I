COP1800 · Java Programming I · Lab 5.7

The rental dock that hands out two boats

Objectives

  • Use switch to test one variable against a series of exact char values
  • End each case with break, and predict the fall-through when it is missing
  • Stack empty case labels so several values share one action
  • Rewrite a chain of if statements as a switch expression with ->

Requirements

  1. R1 In describe(), every case ends with break, so one code prints one boat.
  2. R2 describe() accepts lowercase codes: 'k', 'p' and 'c' are stacked with their uppercase labels, so each pair shares one action.
  3. R3 getHourlyRate() returns the value of a switch expression (case 'k', 'K' -> 18.00; …, default -> 0.0;) instead of the if chain.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. Predict what the starter's describe('K') prints, and explain why.

    Kayak and then Paddleboard. The K case has no break, so execution falls through into the next case and continues until the break after Paddleboard.

  2. Why does describe('p') print Unknown code p even though the rate lookup knows a lowercase p?

    A switch matches exact values, and 'p' and 'P' are different char values. There is no case 'p', so the default runs.

Solution

RentalDesk.java
public class RentalDesk
{
    public static void describe(char code)
    {
        switch(code)
        {
            case 'k':
            case 'K':
                System.out.println("Kayak");
                break;
            case 'p':
            case 'P':
                System.out.println("Paddleboard");
                break;
            case 'c':
            case 'C':
                System.out.println("Canoe");
                break;
            default:
                System.out.println("Unknown code " + code);
        }
    }

    public static double getHourlyRate(char code)
    {
        return switch(code)
        {
            case 'k', 'K' -> 18.00;
            case 'p', 'P' -> 22.00;
            case 'c', 'C' -> 25.00;
            default -> 0.0;
        };
    }

    public static void quote(char code)
    {
        describe(code);
        double rate = getHourlyRate(code);
        if(rate > 0)
            System.out.println("  $" + String.format("%.2f", rate) + " an hour");
    }

    public static void main(String[] args)
    {
        quote('K');
        quote('p');
        quote('c');
        quote('Z');
    }
}

Walkthrough

A switch jumps to the matching case and runs statements from there *until a break or the end of the switch*: with no break after Kayak, execution fell through into the paddleboard case. Each case therefore ends with break (the last one, default, doesn't need it). An empty case 'k': falls through to case 'K': on purpose, so both letters share one action (Figure 5-28); case 'k', 'K': is the shorter form Java 14 and later accept. The switch expression (Figure 5-29) produces a value: each -> gives the result for its labels, there is no fall-through and no break, and the whole expression is followed by a semicolon because it ends the return statement. A switch expression that returns a value must cover every possible input, which is why default -> 0.0; is required.

Messages students see when a check fails

C1 · Every boat's case ends with break

Add break; after System.out.println("Kayak");. Without it, a K runs the kayak line and then falls through into the paddleboard case; break ends the switch after one boat.

Hint:

Where does execution go after the Kayak line, when nothing stops it?

C2 · Lowercase codes share the uppercase actions

Add case 'k': directly above (or together with) case 'K':, and the same for p and c. An empty case falls through to the next label, so both letters run the same statements without repeating them.

C3 · The rate comes from a switch expression

Replace the if chain with return switch(code) { case 'k', 'K' -> 18.00; … default -> 0.0; };. Each arrow gives the value for its labels, there is no fall-through to guard against, and default covers every other code.

Progressive hints

  1. Trace describe('K') line by line. After the Kayak line, what is the next statement Java runs?

  2. A case label with no statements under it passes control straight to the next label. Use that to give 'k' the same action as 'K'.

  3. In a switch expression, labels that share a result are separated by commas, and -> is followed by the value itself. Remember the semicolon after the closing brace.

Reflection: questions and model answers

  1. Fall-through caused the Kayak bug, and fall-through also makes case 'k': case 'K': work. What decides whether it helps or hurts?

    Whether it is intended. Stacked empty labels fall through on purpose so several values share one action; a case with statements and no break falls into the next case's statements, which is usually a mistake.

  2. Why can't a switch expression that returns a value leave out default, when the switch statement in describe() could?

    The expression must produce a value for every possible char, so the compiler requires all inputs to be covered. A statement may simply do nothing when no case matches.
