The marina meter that always says EXPIRED

Objectives

  • Write an if statement whose dependent statement runs only when its Boolean expression is true
  • Recognise the empty statement created by a semicolon right after the condition
  • Use if…else (a dual-alternative selection) so exactly one of two actions runs
  • Compare objects' values through their getters instead of comparing references with ==

Requirements

  1. R1 In printMeter(), EXPIRED prints only when minutesLeft is 0: the if controls that line.
  2. R2 printMeter() is an if…else: a meter prints exactly one line, EXPIRED or the minutes left.
  3. R3 compareSlips() compares the two boats' lengths with getLengthFeet(), not the two Boat references.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. Trace printMeter(45) in the starter. Which lines print, and which part of the code decides that?

    Both Meter: EXPIRED and Meter: 45 min left print. The if ends at the semicolon after its condition, so its only dependent statement is empty; both println calls are independent statements that always run.

  2. A classmate suggests if(minutesLeft = 0). What does Java do with that line, and why?

    It doesn't compile. A single = assigns 0 to minutesLeft, which gives an int, and an if accepts only a Boolean expression. Equality is tested with ==.

Solution

SlipReport.java
public class SlipReport
{
    public static void printMeter(int minutesLeft)
    {
        if(minutesLeft == 0)
            System.out.println("Meter: EXPIRED");
        else
            System.out.println("Meter: " + minutesLeft + " min left");
    }

    public static void compareSlips(Boat first, Boat second)
    {
        if(first.getLengthFeet() == second.getLengthFeet())
            System.out.println(first.getName() + " and " + second.getName()
                + " need the same slip size");
        else
            System.out.println(first.getName() + " and " + second.getName()
                + " need different slip sizes");
    }

    public static void main(String[] args)
    {
        printMeter(0);
        printMeter(45);

        Boat otter = new Boat("Sea Otter", 28);
        Boat heron = new Boat("Blue Heron", 28);
        Boat gull = new Boat("Gull", 22);
        compareSlips(otter, heron);
        compareSlips(otter, gull);
    }
}

Walkthrough

if(minutesLeft == 0); ends the if at the semicolon: when the condition is true, Java runs an empty statement, and the EXPIRED line below it is an independent statement that always runs, whatever its indentation says. Removing the semicolon makes the println the if's dependent statement. Adding else turns it into a dual-alternative selection, so exactly one of the two lines prints. In compareSlips(), first == second compares references: it is true only when both names refer to the same object in memory. Sea Otter and Blue Heron are different objects with equal lengths, so their values must be compared: getLengthFeet() returns an int, and int values can be compared with any relational operator.

Messages students see when a check fails

C1 · No semicolon right after the meter's condition

Delete the semicolon after if(minutesLeft == 0). That semicolon is an empty statement: it becomes the whole if, and the EXPIRED line below runs every time, no matter how it is indented.

Hint:

Where does an if statement end? Look for the first semicolon after the condition.

C2 · An if…else picks exactly one line

Put else before the minutes-left line. An if…else is a dual-alternative selection: when the meter is at 0 only EXPIRED prints, and otherwise only the minutes print.

C3 · The boats' lengths are compared, not their references

Compare first.getLengthFeet() with second.getLengthFeet(). first == second asks whether both names refer to the same object in memory; two different boats of 28 feet are different objects, so it says false.

Hint:

What value does the slip size actually depend on?

Progressive hints

  1. An if statement ends at its first semicolon. In printMeter(), where is the first semicolon after the condition's closing parenthesis?

  2. Two lines that must never both print are the two halves of an if…else.

  3. Boat is a class, so first and second hold references. The value you care about comes back from one of Boat's getters, as an int.

Reflection: questions and model answers

  1. Why does first == second say false for Sea Otter and Blue Heron, but true if you call compareSlips(otter, otter)?

    == on objects compares references, the memory addresses. otter and heron are two different objects, so their references differ even though the lengths are equal. Passing otter twice gives two references to the same object, so == is true.

  2. The indentation of the starter made the EXPIRED line look controlled by the if. What does the compiler use instead of indentation to decide what belongs to an if?

    Statements and punctuation: the if's dependent statement is the single statement right after the condition (or a block in braces). The compiler ignores indentation, so a semicolon after the condition makes an empty statement the dependent one.
