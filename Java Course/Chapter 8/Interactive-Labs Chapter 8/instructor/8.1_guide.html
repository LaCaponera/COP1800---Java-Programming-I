COP1800 · Java Programming I · Lab 8.1

The food-truck log that crashes on Sunday

Objectives

  • Declare an array variable and reserve its memory with new, sizing it from a variable
  • Map a person's numbering (Day 1, Day 2, ...) to array subscripts that start at 0
  • Predict when a subscript is out of bounds and read an ArrayIndexOutOfBoundsException message

Requirements

  1. R1 The constructor creates sales with exactly as many elements as the days parameter, not a typed number.
  2. R2 record() and getSale() use the subscript dayNumber - 1, so Day 1 is element 0.
  3. R3 getLastDay() returns the last element: subscript numDays - 1.
  4. R4 Running the test program prints exactly what it expects. (verified by the program output)

Before you code: warm-up and model answers

  1. With the starter, sales = new double[7]. What are the subscripts of the first and the last element, and what happens when record(7, 380.25) runs?

    The subscripts run from 0 to 6. record(7, ...) uses subscript 7, which is out of bounds, so Java throws an ArrayIndexOutOfBoundsException and the program stops.

  2. In the starter, which element receives Day 1's sale, and which element is never used?

    Day 1 goes into sales[1], the second element. sales[0], the first element, is never used.

Solution

SalesWeek.java
public class SalesWeek
{
    private double[] sales;
    private int numDays;

    // Creates the sales log for a week with the given number of working days.
    public SalesWeek(int days)
    {
        numDays = days;
        sales = new double[days];
    }

    // The owner's sheet numbers the working days 1, 2, 3, ...
    public void record(int dayNumber, double amount)
    {
        sales[dayNumber - 1] = amount;
    }

    public double getSale(int dayNumber)
    {
        return sales[dayNumber - 1];
    }

    // The sale of the last working day of the week.
    public double getLastDay()
    {
        return sales[numDays - 1];
    }
}

Walkthrough

Declaring the variable (double[] sales;) and reserving memory (new double[days]) are two distinct steps (p. 268). Java accepts any integer expression as the size, so the parameter days sizes the array to the week (pp. 269–270). Subscripts start at 0, so a person's Day n is element n − 1, and the highest legal subscript is one less than the size (p. 269): sales[numDays] is out of bounds. new double[numDays] and sales[sales.length - 1] also pass the checks. Day 3 prints 0.0 because nothing was stored there yet; section 8.2 explains these default values.

Messages students see when a check fails

C1 · The array is sized from the number of days

Create the array with new double[days], so a 5-day catering week gets 5 elements and a 7-day week gets 7. Java lets a variable set an array's size; a typed 7 is wrong for every week that isn't 7 days long.

Hint:

Which parameter already holds the number of working days?

C2 · record() stores Day n in element n − 1

Store the sale in sales[dayNumber - 1]: subscripts start at 0, so Day 1 belongs in element 0 and Day 7 in element 6.

C3 · getSale() reads the same element

Read sales[dayNumber - 1], the element record() writes to; otherwise Day 1 shows Day 2's sale.

C4 · getLastDay() reads the last element

Return sales[numDays - 1]: in an array of numDays elements the last subscript is numDays - 1; sales[numDays] is one past the end.

Progressive hints

  1. Java allows any integer expression as an array size: a literal, a named constant, a variable, a calculation or a method's return value. Which variable in the constructor already holds the number of days?

  2. Think of a subscript as "how many elements away from the start". Day 1 is zero elements away from the start; Day 7 is six away.

  3. For an array of n elements the highest legal subscript is one less than n. getLastDay() already uses numDays; it is off by one.

Reflection: questions and model answers

  1. The crash message said Index 7 out of bounds for length 7. Explain why 7 is not a legal subscript for an array of length 7.

    A 7-element array has subscripts 0 through 6 because counting starts at 0. Subscript 7 would be an eighth element, which was never reserved.

  2. Before your fix, Day 1's sale was stored but never displayed, and nothing crashed. Why is a silent off-by-one error more dangerous than the crash on Day 7?

    The silent error gives wrong numbers that look plausible, so nobody notices and decisions are made on bad data. The crash at least stops the program and points to the line.

  3. Why is sizing the array from the days parameter better than reserving 7 elements for every week?

    The array then matches the week exactly: getLastDay() finds the real last day, a 5-day week has no unused elements, and the class works for any schedule without editing the code.
