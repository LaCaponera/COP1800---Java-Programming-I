COP1800 · Java Programming I · Lab 3.1

The food-truck sign

Objectives

  • Move a group of statements into a well-named static void method
  • Place a method inside the class but outside every other method
  • Call a method from main() as many times as you need
  • Explain why the order of the calls, not the order of the methods in the file, decides what runs

Requirements

  1. R1 A method public static void displayHours() holds the three hours lines. It sits inside the TruckSign class but outside main().
  2. R2 main() calls displayHours() once for each sign, and no hours text is left in main().
  3. R3 main() calls displaySpecial() so the special appears right under the window header. Leave displaySpecial() where it is, above main().
  4. R4 The printout matches the screen above exactly. (verified by the program output)

Before you code: warm-up and model answers

  1. displaySpecial() is the first method in the starter's class. When you run the starter, does its line print first, last or not at all? Explain.

    Not at all. Only main() runs automatically when the program starts; any other method runs only when something calls it. Its position in the file changes nothing.

  2. The hours appear twice in main(). Name the real problem this duplication caused at the truck, and say how a method prevents it.

    When Saturday's hours changed, only one copy was edited, so the two signs disagreed. With the lines in one method there is a single copy to change, and every call shows the new hours.

Solution

TruckSign.java
public class TruckSign
{
    public static void displaySpecial()
    {
        System.out.println("Today's special: birria tacos");
    }

    public static void main(String[] args)
    {
        System.out.println("=== La Esquina: serving window ===");
        displaySpecial();
        displayHours();

        System.out.println("=== La Esquina: side door ===");
        displayHours();
    }

    public static void displayHours()
    {
        System.out.println("Mon-Fri   11 am to 9 pm");
        System.out.println("Sat       noon to 10 pm");
        System.out.println("Sun       closed");
    }
}

Walkthrough

A method is written inside the class but never inside another method; displayHours() could equally go before main() or between displaySpecial() and main(), and the program would behave the same. displaySpecial() comes first in the file but did nothing in the starter: only main() runs automatically, and every other method runs only when it is called. Now a change to Saturday's hours is made in one place and both signs follow, and main() reads like an outline of the printout.

Messages students see when a check fails

C1 · displayHours() is a public static void method with empty parentheses

Write a header public static void displayHours() followed by a body in braces, inside the class's braces but outside main(). A method can sit before or after main(), never inside it.

Hint:

Copy the shape of displaySpecial()'s header and change the name.

C2 · displayHours() prints the three hours lines

Move the three hours println() statements, unchanged, into the body of displayHours().

C3 · main() calls displayHours() for both signs

Call displayHours() once after the window header and once after the side-door header. The work is written once; a method can be called as many times as you need.

C4 · No hours text left in main()

main() still prints hours itself. Remove those println() statements, so the hours exist in one place only: inside displayHours().

C5 · main() calls displaySpecial()

displaySpecial() sits in the class but never runs: only main() runs automatically. Call it right after the window header.

Progressive hints

  1. Run the starter first. Which lines appear twice, and which method in the class never shows its output?

  2. A method needs a header and a body in braces, and it goes inside the class but outside main(). displaySpecial() shows the exact shape.

  3. Once the hours live in their own method, each sign needs a single statement for them: the method's name, empty parentheses and a semicolon.

Reflection: questions and model answers

  1. You could have placed displayHours() before main() instead of after it. Would the printout change? What decides the order in which methods run?

    No. The order of the calls inside main() decides what runs and when; the physical order of the methods in the class has no effect. main() always runs first.

  2. Read your new main() aloud. How does the name displayHours help someone who has never seen the program? Connect your answer to abstraction.

    main() now reads like an outline: header, special, hours, next header, hours. The name says what happens without listing the details; using a general name for a group of detailed statements is abstraction.
