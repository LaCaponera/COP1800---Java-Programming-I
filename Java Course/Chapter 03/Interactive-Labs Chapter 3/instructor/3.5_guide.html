The arcade scoreboard

Objectives

  • Identify the block in which a variable is in scope
  • Explain why changing a parameter inside a method doesn't change the caller's variable
  • Send a new value back with return, and store it in the caller
  • Remove a block that exists for no reason

Requirements

  1. R1 addBonus() returns the new score as an int, and main() stores what it returns.
  2. R2 combo is declared in main()'s outer block (remove the unnecessary inner block), so the final line can use it.
  3. R3 The final line prints the score times the combo, and the whole printout matches the screen above. (verified by the program output)

Before you code: warm-up and model answers

  1. Predict the starter's After bonus: line. addBonus() clearly prints 1700; explain why main() prints something else.

    main() prints 1200. It passes a copy of its score; inside addBonus() the parameter score is a different variable in a different memory location, so adding 500 changes only that copy, which goes out of scope when the method ends. main()'s score is untouched.

  2. If you change only the final line to print score * combo, what does the compiler report, and why?

    cannot find symbol for combo. It was declared inside the inner block, so it went out of scope at that block's closing brace; the final line is outside its scope.

Solution

ScoreBoard.java
public class ScoreBoard
{
    public static void main(String[] args)
    {
        int score = 1200;
        System.out.println("Start: " + score);

        score = addBonus(score);
        System.out.println("After bonus: " + score);

        int combo = 3;
        System.out.println("Combo x" + combo);

        System.out.println("Final: " + (score * combo));
    }

    public static int addBonus(int score)
    {
        final int BONUS = 500;
        score = score + BONUS;
        System.out.println("In addBonus, score is " + score);
        return score;
    }
}

Walkthrough

addBonus()'s parameter score is a different variable from main()'s score: it receives a copy of 1200, becomes 1700, and goes out of scope at the method's closing brace. Returning it and assigning the result in main() is how the new value gets back. combo was declared inside a block that existed for no reason, so it went out of scope at that block's closing brace; declared in main()'s outer block it stays in scope until the end of main(). The parentheses around score * combo are optional (* happens before +) but make the intent clear.

Messages students see when a check fails

C1 · addBonus() is of type int

Change addBonus()'s return type from void to int, so it can send the new score back to its caller.

C2 · addBonus() returns the updated score

End addBonus() with a return statement that sends back the updated score. The parameter is a copy that disappears when the method ends; return is the way its value gets out.

C3 · main() stores what addBonus() returns

Assign the result of addBonus(score) to a variable in main(), normally score itself. A call alone on its line throws the returned value away.

C4 · No block made for no reason

Remove the extra pair of braces around combo. That block has no purpose, and combo goes out of scope at its closing brace, so the final line can't see it.

C5 · The final line multiplies by combo

Print the final score as score times combo. It compiles only once combo is in scope on that line.

Progressive hints

  1. Run the starter and compare In addBonus, score is ... with After bonus: .... At that moment two variables named score exist. Where does each one live?

  2. A method can't reach into main()'s variables, but it can send a value back. That takes a return type other than void, a return statement, and a caller that keeps the result.

  3. A variable declared inside braces goes out of scope at the closing brace. Does combo need a block of its own at all?

Reflection: questions and model answers

  1. Could you declare a second int score inside a new block nested in main()? Why can addBonus() use the name score for its parameter without any conflict?

    No: a nested block lies entirely inside main()'s block, where the first score is still in scope, so it would be an illegal redeclaration. addBonus() is a different method with its own scope, so its score is a separate variable; the two scopes never overlap.

  2. The reading advises against creating blocks for no reason. Using this lab, describe a bug an unnecessary block caused or could cause.

    The extra braces made combo go out of scope before the final line needed it, so the final score couldn't use it. Unnecessary blocks hide where a variable lives and invite variables that vanish too early, or duplicates with the same name.
