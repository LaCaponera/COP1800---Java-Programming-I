COP1800 · Java Programming I · Lab 3.4

The bike courier's weekly payout

Objectives

  • Give a method a non-void return type and end it with a return statement
  • Use a returned value: store it, print it or calculate with it
  • Build a method that calls other methods and treats them as black boxes
  • Explain why a statement after return is unreachable

Requirements

  1. R1 calculateGross(double hours, double rate) returns the gross pay as a double and prints nothing.
  2. R2 calculatePlatformFee(double gross) returns 25% of the gross, using a named constant FEE_RATE.
  3. R3 calculateNet(double hours, double rate) gets its numbers by calling calculateGross() and calculatePlatformFee(), and returns gross minus fee.
  4. R4 main() prints the three lines by using the values the methods return. The output, including the test program's checks for another courier, matches. (verified by the program output)

Before you code: warm-up and model answers

  1. The starter calls calculateGross(hours, rate); on a line by itself. What does that call do, and what is lost?

    It computes the gross and prints Gross: $555.0 from inside the method, but it returns nothing, so main() gets no number to work with. No other code can use the gross, for example to compute the fee.

  2. The stubs end with return 0.0;. Why does the compiler insist on a return in a method of type double, but not in a void method like displayHours()?

    Every non-void method must return a value of its declared type (or one that can be promoted to it). A void method returns nothing, so it needs no return statement.

Solution

CourierPayout.java
public class CourierPayout
{
    public static void main(String[] args)
    {
        double hours = 30;
        double rate = 18.50;

        double gross = calculateGross(hours, rate);
        System.out.println("Gross: $" + gross);
        System.out.println("Platform fee: $" + calculatePlatformFee(gross));
        System.out.println("Net payout: $" + calculateNet(hours, rate));
    }

    public static double calculateGross(double hours, double rate)
    {
        double gross = hours * rate;
        return gross;
    }

    public static double calculatePlatformFee(double gross)
    {
        final double FEE_RATE = 0.25;
        return gross * FEE_RATE;
    }

    public static double calculateNet(double hours, double rate)
    {
        double gross = calculateGross(hours, rate);
        double fee = calculatePlatformFee(gross);
        return gross - fee;
    }
}

Walkthrough

A method's type is the type of the value it returns: calculateGross() becomes type double, and its return sends the number back to whoever called it. Returning instead of printing lets each caller decide what to do: main() stores the gross, puts the fee call straight inside println() (note the two closing parentheses), and calculateNet() subtracts. calculateNet() treats the other methods as black boxes: it knows only what they take and return. FEE_RATE may also be declared at class level; a local final constant is what this chapter has used so far.

Messages students see when a check fails

C1 · calculateGross() is of type double

Change the return type of calculateGross() from void to double, the type of the value it will send back.

C2 · calculateGross() returns the gross and prints nothing

End calculateGross() with a return statement that sends the gross back, and remove its println(). A method that returns the number lets every caller decide what to do with it: print it, store it or calculate with it.

C3 · The fee rate is a named constant of 0.25

Declare the 25% as a named constant, final double FEE_RATE, holding 0.25. The name tells a reader what 0.25 means, and a change of fee is made in one place.

C4 · calculatePlatformFee() returns gross times FEE_RATE

Replace the stub's return 0.0; with the gross multiplied by FEE_RATE, returned to the caller.

C5 · calculateNet() reuses the other two methods

Let calculateNet() call calculateGross() and calculatePlatformFee() instead of repeating their arithmetic. It needs to know only what they take and what they return, not how they work.

C6 · main() uses every returned value

In main(), use what each method returns: store the result in a variable or put the call inside println(). A call alone on its line throws the returned value away.

Progressive hints

  1. A method's type is the word just before its name. Which word must change so that calculateGross() can send back a double?

  2. In calculateNet(), ask the other two methods for the numbers: keep what each call returns in a local variable, then return the difference.

  3. In main(), a call that returns a value can go anywhere a double variable could, even inside println() after the label and a +. Count the closing parentheses.

Reflection: questions and model answers

  1. Suppose you add System.out.println("Done"); after the return in calculateGross(). What happens, and why?

    The class no longer compiles: the statement is unreachable (dead code). return ends the method and sends control back to the caller, so nothing after it could ever run.

  2. calculateNet() doesn't know how the fee is computed. Why is that a strength? Use this case: the app changes its fee to 20% plus a $1.50 weekly service charge.

    calculateNet() treats calculatePlatformFee() as a black box: it only relies on it taking a gross and returning a double. The new rule changes only the body of calculatePlatformFee(); calculateNet(), main() and every other caller keep working because the interface is unchanged.
