COP1800 · Java Programming I · Lab 3.2

The vet clinic's lobby screen

Objectives

  • Name the parts of a method header: access specifier, static, return type, identifier and parentheses
  • Explain what public access allows that private does not
  • Fill in a stub: a method with a finished header and an empty body
  • Call a method in another class with its fully qualified name, ClassName.methodName()

Requirements

  1. R1 displayHours() in VetClinic has public access, so other classes can call it.
  2. R2 The stub displayEmergencyLine() is completed: its body prints After hours: call (555) 010-0199, and its header stays public static void displayEmergencyLine().
  3. R3 LobbyScreen.main() shows the hours and then the emergency line by calling the two VetClinic methods with their fully qualified names, without copying their println() statements.
  4. R4 Running VetClinic and then LobbyScreen prints exactly what the test program expects. (verified by the program output)

Before you code: warm-up and model answers

  1. Label the parts of the header private static void displayHours(): which word is the access specifier, which the modifier, which the return type, which the identifier, and what do the empty parentheses tell you?

    private is the access specifier; static is the modifier (no object is needed to call the method); void is the return type (it sends nothing back); displayHours is the identifier; the empty parentheses mean the method receives no data.

  2. Inside VetClinic, main() calls displayHours() with no class name. Why will LobbyScreen need to write more than that?

    Within its own class, the simple name is enough. From another class, the compiler only recognizes the method by its fully qualified name, VetClinic.displayHours(): the class name works like a family name.

Solution

VetClinic.java
public class VetClinic
{
    public static void main(String[] args)
    {
        System.out.println("Harbor Paws Veterinary Clinic");
        displayHours();
    }

    public static void displayHours()
    {
        System.out.println("Mon-Sat   8 am to 7 pm");
        System.out.println("Sun       10 am to 4 pm");
    }

    public static void displayEmergencyLine()
    {
        System.out.println("After hours: call (555) 010-0199");
    }
}
LobbyScreen.java
public class LobbyScreen
{
    public static void main(String[] args)
    {
        System.out.println("Now showing on the lobby screen:");
        VetClinic.displayHours();
        VetClinic.displayEmergencyLine();
    }
}

Walkthrough

A private method can be called only from inside its own class, which is why LobbyScreen could not use displayHours(); public opens it to every class. Inside VetClinic, the simple name displayHours() is enough. From LobbyScreen, the compiler finds the method only through its fully qualified name, VetClinic.displayHours(); without the class name it searches LobbyScreen and reports cannot find symbol. The stub needed only a body: its header, the method's declaration, was already complete. Keep both files in the same folder so the compiler finds VetClinic.

Messages students see when a check fails

C1 · displayHours() is public

Change private to public in the header of displayHours(). A private method can be called only from inside its own class; public lets LobbyScreen call it too.

Hint:

The access specifier is the first word of the header.

C2 · The stub prints the emergency line

Fill the stub's body with one println() that prints After hours: call (555) 010-0199 exactly. Keep the header as it is, and never end a header with a semicolon.

C3 · LobbyScreen calls both VetClinic methods by their full names, in order

In LobbyScreen.main(), call the hours method and then the emergency-line method, each written as the class name VetClinic, a dot and the method name. Don't copy the clinic's text: a change to the hours should be made once, in VetClinic.

Hint:

You have already called a method this way: JOptionPane.showMessageDialog().

Progressive hints

  1. Try the call from LobbyScreen first and read the compiler's message. It names the problem with displayHours() exactly.

  2. Of public, private, static, void and the name, only one word in the header decides which classes may call the method.

  3. From inside VetClinic the short name works. From another class, the method's full name includes its class, like a surname.

Reflection: questions and model answers

  1. Explain the difference between a method's header (declaration) and its body (implementation), using displayEmergencyLine() as the example.

    The header, public static void displayEmergencyLine(), tells other code how to use the method: who may call it, that it returns nothing, its name, and that it takes no data. The body between the braces is the implementation, the println() that does the work. As a stub, the method had a header and an empty body.

  2. Another class in the hospital's system also has a method named displayHours(). Could VetClinic.displayHours() in LobbyScreen ever run the wrong one? Explain.

    No. The fully qualified name includes the class, so VetClinic.displayHours() always means the method in VetClinic. Two classes can each have a method with the same name; they are entirely separate methods.
